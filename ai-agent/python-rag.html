Implementación de RAG y recuperación de conocimiento en Python

Esta sección introduce la tecnología de Generación Aumentada por Recuperación (Retrieval-Augmented Generation, RAG).

RAG es una de las tecnologías centrales para construir agentes intensivos en conocimiento.

Al combinar la recuperación vectorial con modelos de generación de lenguaje, RAG otorga a los agentes la capacidad de acceder y utilizar conocimiento externo, en lugar de depender únicamente del contenido "memorizado" en los parámetros del modelo.

Principios básicos de RAG

La idea central de RAG es combinar dos etapas, "recuperación de información" y "generación de lenguaje", para formar un flujo completo de preguntas y respuestas.

Cuando el usuario plantea una pregunta, el sistema primero recupera de la base de conocimiento los contenidos relacionados con la pregunta.

Luego, el sistema proporciona el contenido recuperado como contexto al modelo de generación, ayudándolo a producir respuestas más precisas y fundamentadas.

Por qué se necesita RAG

Los modelos de lenguaje tienen una fecha límite de conocimiento y no pueden percibir eventos posteriores a su entrenamiento.

Los parámetros del modelo son limitados; es imposible almacenar todo el conocimiento del mundo en ellos.

Si se depende completamente de que el modelo "recuerde" conocimiento desde sus parámetros, cuando encuentra contenido que no recuerda con precisión o que nunca aprendió, tiende a inventar respuestas con total seriedad; esto es lo que se conoce como "alucinación" (hallucination).

El enfoque de RAG consiste en hacer que el modelo consulte fuentes reales antes de responder, convirtiendo "responder de memoria" en "responder con el material abierto". Las fuentes de conocimiento también pueden actualizarse en cualquier momento sin necesidad de reentrenar el modelo.

核心架构

Un sistema RAG completo generalmente incluye tres componentes centrales:

检索器（Retriever）: Se encarga de encontrar en la base de conocimiento los fragmentos de información más relevantes para la pregunta.

向量数据库（Vector Store）: almacena las representaciones vectoriales correspondientes al contenido de los documentos y admite búsqueda de similitud a gran escala y de baja latencia.

生成器（Generator）: genera la respuesta final en lenguaje natural basándose en el contenido recuperado y la pregunta original del usuario.

La relación entre los tres puede entenderse así: el recuperador se encarga de "buscar información", la base de datos vectorial de "almacenar información y encontrar rápidamente información similar", y el generador de "organizar la respuesta a partir de la información".

工作流程

第一步，索引阶段. Se divide el documento original en varios fragmentos de texto (chunks), se vectorizan uno a uno y se almacenan en la base de datos vectorial; este paso suele realizarse de forma offline y anticipada.

第二步，检索阶段. Cuando el usuario realiza una consulta, la consulta se vectoriza de la misma manera y se realiza una búsqueda por similitud en la base de datos vectorial para encontrar los bloques de texto más relevantes.

第三步，增强阶段. Los bloques de texto relevantes recuperados se combinan con la pregunta original del usuario para construir un prompt más completo.

第四步，生成阶段. El modelo de generación produce la respuesta final basándose en este contexto enriquecido.

De estos cuatro pasos, solo el primero es un preprocesamiento offline; los otros tres ocurren en tiempo real cuando el usuario pregunta. Por lo tanto, la velocidad y la calidad de la recuperación determinan directamente la velocidad de respuesta y la calidad de las respuestas de todo el sistema.

代码实现

Implementación básica de RAG

class SimpleRAG:
    """
简化版 RAG 系统实现
包含三个核心组件：嵌入器、向量存储、生成器
    """

    def __init__(self, embedder, vector_store, generator):
        # 嵌入器：负责把文本转换为向量
        self.embedder = embedder
        # 向量数据库：负责存储向量并支持相似度检索
        self.vector_store = vector_store
        # 生成器：基于上下文生成回答
        self.generator = generator

    def add_documents(self, documents):
        """
将文档添加到知识库
:param documents: 原始文档列表（每个元素是一段完整文本）
        """
        # 第一步：把长文档切分为较小的文本块，便于精确检索
        chunks = self.chunk_documents(documents)

        # 第二步：将所有文本块转换为向量
        embeddings = self.embedder.embed(chunks)

        # 第三步：把向量与对应的原文一起存入向量数据库
        self.vector_store.add(embeddings, chunks)

    def chunk_documents(self, documents, chunk_size=500, overlap=50):
        """
文档切分：把长文档拆成固定长度、有一定重叠的文本块

:param documents: 原始文档列表
:param chunk_size: 每个文本块的字符数
:param overlap: 相邻文本块之间的重叠字符数（避免语义在切分处被截断）
:return: 切分后的文本块列表
        """
        chunks = []
        for doc in documents:
            # 按 (chunk_size - overlap) 的步长滑动切分，保留一定重叠区域
            for i in range(0, len(doc), chunk_size - overlap):
                chunk = doc[i:i + chunk_size]
                chunks.append(chunk)
        return chunks

    def query(self, question, top_k=5):
        """
处理用户查询，返回生成的回答

:param question: 用户提出的问题
:param top_k: 检索时返回的相关文本块数量
:return: 生成模型给出的最终回答
        """
        # 1. 把问题转换为向量，才能与知识库中的向量做比较
        question_embedding = self.embedder.embed([question])[0]

        # 2. 在向量数据库中检索最相似的 top_k 个文本块
        results = self.vector_store.search(question_embedding, top_k)

        # 3. 把检索到的文本块拼接成上下文
        context = "\n".join([doc for doc, _ in results])

        # 4. 把上下文和原始问题一起组织成提示词
        prompt = f"基于以下内容回答问题：\n{context}\n\n问题：{question}"

        # 5. 交给生成模型产出最终回答
        return self.generator.generate(prompt)

Esta implementación básica ya puede ejecutar un flujo RAG completo, pero en proyectos reales suele ser insuficiente: el método de división es demasiado simple y brusco, y la clasificación de la recuperación depende solo de un cálculo de similitud vectorial, con precisión limitada. A continuación se presentan varias estrategias de optimización comunes.

Advanced RAG

Los problemas comunes del RAG básico incluyen: la baja calidad del contenido recuperado, una clasificación insuficientemente precisa y la mezcla de información irrelevante en el contexto.

Advanced RAG optimiza aún más el flujo básico mediante la introducción de técnicas como el reordenamiento y la recuperación híbrida, mejorando así la precisión de las respuestas finales.

Reordenamiento (Reranking)

La recuperación vectorial de RAG básico es rápida, pero la precisión de la clasificación es limitada y tiende a colocar en los primeros puestos contenido que no es lo suficientemente relevante a nivel semántico.

El enfoque de reranking consiste en: primero usar la búsqueda vectorial para filtrar rápidamente un conjunto de textos candidatos (por ejemplo, top-20), y luego usar un Cross-Encoder, que requiere más computación pero es más preciso, para puntuar cada candidato, reordenarlos y seleccionar los pocos realmente más relevantes (por ejemplo, top-5).

Este enfoque de dos etapas, "primero filtrar de forma aproximada y luego refinar la clasificación", equilibra la velocidad de recuperación y la precisión de la recuperación.

RAG con reranking

class AdvancedRAG:
    """
高级 RAG 系统
在基础流程之上增加重排序环节
    """

    def __init__(self, embedder, vector_store, reranker, generator):
        # 嵌入器
        self.embedder = embedder
        # 向量数据库
        self.vector_store = vector_store
        # 重排序模型（交叉编码器），用于精细化排序
        self.reranker = reranker
        # 生成器
        self.generator = generator

    def query(self, question, initial_k=20, final_k=5):
        """
处理查询，包含"粗筛 + 精排"两阶段检索

:param question: 用户问题
:param initial_k: 第一阶段向量检索返回的候选数量
:param final_k: 重排序后最终保留的数量
        """
        # ==================== 阶段1：初步检索（粗筛） ====================
        # 把问题转换为向量
        question_embedding = self.embedder.embed([question])[0]

        # 用向量相似度快速召回一批候选文本（速度快，精度一般）
        initial_results = self.vector_store.search(
            question_embedding,
            initial_k
        )

        # ==================== 阶段2：重排序（精排） ====================
        # 构造 (问题, 候选文档) 配对，交给交叉编码器逐一打分
        doc_pairs = [(question, doc) for doc, _ in initial_results]

        # 交叉编码器会同时编码问题和文档，能更精确地判断两者的相关性
        reranked = self.reranker.rerank(doc_pairs)

        # 取重排序后真正最相关的 final_k 条
        final_context = "\n".join([doc for doc, _ in reranked[:final_k]])

        # ==================== 阶段3：生成 ====================
        prompt = f"上下文：{final_context}\n\n问题：{question}"
        return self.generator.generate(prompt)

混合检索

La recuperación híbrida (Hybrid Retrieval) combina las ventajas de la recuperación densa y la recuperación dispersa.

La recuperación densa (Dense Retrieval) se basa en la similitud vectorial y es buena para capturar la relevancia semántica; incluso si la pregunta del usuario y el documento no usan exactamente las mismas palabras, puede haber coincidencia.

La recuperación dispersa (como BM25) se basa en estadísticas de frecuencia de términos de palabras clave, destaca en la coincidencia literal precisa y, en escenarios como nombres propios, números y fragmentos de código, suele ser más fiable que la recuperación vectorial.

Cada uno tiene sus puntos ciegos: la búsqueda vectorial puede "entender el significado pero no encontrar las palabras clave exactas", mientras que la búsqueda por palabras clave puede "coincidir las palabras pero no entender la semántica". La búsqueda híbrida fusiona los resultados de ambas rutas de recuperación para complementarse mutuamente.

RAG con búsqueda híbrida

class HybridRAG:
    """
混合检索 RAG
结合稠密检索（向量）和稀疏检索（关键词）
    """

    def __init__(self, dense_retriever, sparse_retriever, fusion_fn):
        # 稠密检索器：基于向量相似度，擅长语义匹配
        self.dense_retriever = dense_retriever
        # 稀疏检索器：基于关键词统计（如 BM25），擅长精确匹配
        self.sparse_retriever = sparse_retriever
        # 融合函数：用于合并两路检索结果，例如 RRF（见下方实现）
        self.fusion_fn = fusion_fn

    def query(self, question, top_k):
        """
执行混合检索，返回融合排序后的结果

:param question: 用户问题
:param top_k: 最终返回的结果数量
        """
        # ==================== 稠密检索 ====================
        # 多召回一些候选（top_k * 2），留出融合时筛选的空间
        dense_results = self.dense_retriever.search(question, top_k * 2)

        # ==================== 稀疏检索 ====================
        # 基于关键词的检索，同样多召回一些候选
        sparse_results = self.sparse_retriever.search(question, top_k * 2)

        # ==================== 结果融合 ====================
        # 使用 Reciprocal Rank Fusion（RRF）等策略融合两路排序结果
        fused = self.fusion_fn(dense_results, sparse_results)

        # 取融合后排名最高的 top_k 条
        return fused[:top_k]


def reciprocal_rank_fusion(results_a, results_b, k=60):
    """
Reciprocal Rank Fusion（RRF）算法
用于把两路（或多路）检索的排序结果融合成一个统一排序

核心思路：只看每个文档在各路结果里的"排名"，而不是具体分数，
避免了向量相似度分数和 BM25 分数量纲不同、无法直接比较的问题。

:param results_a: 检索结果 A，格式为 [(doc, score), ...]
:param results_b: 检索结果 B，格式为 [(doc, score), ...]
:param k: 平滑常数，用于降低排名靠后的文档的权重差异，通常取 60
:return: 按融合分数从高到低排序的 [(doc, score), ...] 列表
    """
    scores = {}

    # 处理结果 A：排名越靠前，贡献的分数越高
    for rank, (doc, _) in enumerate(results_a):
        scores[doc] = scores.get(doc, 0) + 1 / (k + rank + 1)

    # 处理结果 B，同样按排名累加分数
    for rank, (doc, _) in enumerate(results_b):
        scores[doc] = scores.get(doc, 0) + 1 / (k + rank + 1)

    # 按累加后的融合分数从高到低排序
    sorted_docs = sorted(scores.items(), key=lambda x: -x[1])

    return sorted_docs

Otras estrategias de optimización

查询扩展: Expande la consulta original añadiendo sinónimos o palabras relacionadas, ampliando el alcance de recuperación y mejorando la tasa de recall.

查询改写: utiliza modelos para comprender la intención real del usuario y reescribe preguntas coloquiales o ambiguas en formulaciones más adecuadas para la recuperación.

上下文压缩: Antes de entregar los resultados de recuperación al modelo generativo, se eliminan las partes redundantes e irrelevantes y se conserva solo la información clave, lo que reduce costos y el riesgo de que el modelo generativo se vea interferido por contenido no relacionado.

向量数据库

La base de datos vectorial es la infraestructura del sistema RAG; se encarga de almacenar enormes cantidades de vectores de alta dimensión y admite búsqueda de similitud a gran escala y de baja latencia.

核心概念

嵌入（Embedding）: el proceso de convertir texto (o imágenes, audio, etc.) en un conjunto de vectores numéricos densos; el contenido semánticamente similar queda más cerca en el espacio vectorial.

向量维度: la longitud del vector de incrustación. Cuanto mayor es la dimensión, en teoría más rica es la información semántica que puede expresarse, pero también aumentan los costos de almacenamiento y cómputo.

相似度度量: métodos de cálculo específicos para medir el "grado de similitud" o la "distancia" entre dos vectores; diferentes métricas son adecuadas para diferentes escenarios.

Medidas de similitud comunes

度量方法 公式 特点 适用场景
余弦相似度 cos(A,B) = A·B/(|A||B|) Solo mide la similitud direccional, independientemente de la magnitud del vector; rango de valores [-1,1]. 文档/文本相似度
欧氏距离 d(A,B) = sqrt(sum((Ai-Bi)^2)) Mide la distancia espacial absoluta entre vectores; rango de valores [0,+∞). Coincidencia de características de imagen
点积 A·B = sum(Ai*Bi) Se ve afectada tanto por la dirección como por la magnitud; alta eficiencia computacional. 推荐系统

Comparación de las principales bases de datos vectoriales

数据库 类型 特点 适用场景
Pinecone 云服务 Servicio totalmente gestionado, fácil de usar, escalado automático, sin necesidad de operación y mantenimiento propios. Entornos de producción que necesitan un lanzamiento rápido
Weaviate 开源 Soporte nativo para recuperación híbrida (vectores + palabras clave), alto grado de modularización. Escenarios que requieren una lógica de recuperación personalizable y flexible
Milvus 开源 Alta disponibilidad, fácil escalado horizontal, capaz de soportar escalas de miles de millones de vectores o más. Recuperación vectorial a muy gran escala
Chroma 开源 Ligero, API simple, se puede poner en marcha con unas pocas líneas de código. Desarrollo de prototipos, enseñanza y pruebas locales
Qdrant 开源 Implementado en Rust, excelente rendimiento, admite abundantes condiciones de filtrado. Escenarios que requieren alto rendimiento y filtrado complejo

代码示例

Usando la base de datos vectorial Chroma.

import chroma_client
from chroma_client import ChromaClient

# 创建客户端（可连接本地实例，也可连接远程服务）
client = ChromaClient()

# 创建或获取一个集合（Collection），相当于关系型数据库里的"表"
collection = client.get_or_create_collection("knowledge_base")

# 添加文档：ID、向量、原文、元数据需要一一对应
collection.add(
    ids=["doc1", "doc2", "doc3"],  # 每条文档的唯一标识
    embeddings=[
        [0.1, 0.2, 0.3],  # 文档1对应的向量（实际维度通常远高于3维）
        [0.4, 0.5, 0.6],  # 文档2对应的向量
        [0.7, 0.8, 0.9],  # 文档3对应的向量
    ],
    documents=[
        "人工智能是计算机科学的一个分支",
        "机器学习是人工智能的子领域",
        "深度学习是机器学习的子领域"
    ],
    metadatas=[
        {"source": "教科书"},  # 文档1的来源信息，可用于后续过滤
        {"source": "论文"},
        {"source": "论文"}
    ]
)

# 检索：传入查询向量，返回最相似的 n_results 条结果
results = collection.query(
    query_embeddings=[[0.15, 0.25, 0.35]],  # 查询对应的向量
    n_results=2  # 返回 top-2 最相似的结果
)

# 输出检索结果
print(results["documents"])   # 命中的原文内容
print(results["distances"])   # 对应的距离/相似度分数，数值越小通常表示越相似

Al elegir una base de datos vectorial, es necesario considerar de manera integral el volumen de datos, los requisitos de latencia de consulta, el método de implementación (nube gestionada o autogestionada) y la capacidad de operación y mantenimiento del equipo. Para desarrollo de prototipos a pequeña escala, se prefiere Chroma; para entornos de producción listos para usar, se puede elegir Pinecone; para escenarios a muy gran escala que requieren control autónomo, Milvus o Qdrant son más adecuados.

GraphRAG

GraphRAG es una solución avanzada que combina el Grafo de Conocimiento (Knowledge Graph) con RAG.

Mejora las capacidades de recuperación y razonamiento del sistema mediante la construcción de una estructura de grafo compuesta por entidades y relaciones.

Por qué se necesita GraphRAG

El RAG tradicional se basa en la búsqueda de similitud de fragmentos de texto y tiene dificultades para manejar problemas que requieren "razonamiento de múltiples saltos" (es decir, respuestas que requieren encadenar múltiples piezas de información).

El RAG tradicional tampoco captura fácilmente de manera explícita las relaciones semánticas entre entidades, como información estructurada del tipo "quién es el superior de quién" o "qué empresa adquirió a qué empresa".

GraphRAG organiza explícitamente estas entidades y relaciones en una estructura de grafo, permitiendo que el sistema razone a lo largo de rutas de relación, en lugar de solo "buscar textos similares".

核心优势

Capaz de capturar relaciones semánticas entre entidades y formar una red de conocimiento estructurada, no solo fragmentos de texto dispersos.

Admite razonamiento basado en rutas y puede responder mejor a preguntas relacionales.

Puede manejar problemas complejos que requieren razonamiento de múltiples saltos (multi-hop), como "¿quién es el mentor del mentor de alguien?", que necesitan atravesar varios nodos de relación consecutivamente para llegar a la respuesta.

代码实现

GraphRAG 实现

class GraphRAG:
    """
GraphRAG 系统
结合知识图谱检索与向量检索，兼顾关系推理与语义相似度
    """

    def __init__(self, kg_builder, embedder, vector_store, generator):
        # 知识图谱构建器：负责实体/关系抽取与图谱查询
        self.kg_builder = kg_builder
        # 嵌入器：用于将文档和问题转换为向量
        self.embedder = embedder
        # 向量数据库：作为知识图谱检索的补充通道
        self.vector_store = vector_store
        # 生成器：基于融合后的上下文生成最终回答
        self.generator = generator

    def index_documents(self, documents):
        """
将文档同时索引到知识图谱和向量数据库
:param documents: 文档列表
        """
        for doc in documents:
            # 从文档中提取实体
            # 例如从"OpenAI 成立于 2015 年"中提取出
            # 实体：OpenAI（组织）、2015年（时间）
            entities = self.kg_builder.extract_entities(doc)

            # 从文档中提取实体间的关系
            # 例如提取出关系三元组：(OpenAI, 成立于, 2015年)
            relations = self.kg_builder.extract_relations(doc)

            # 把实体和关系写入知识图谱
            self.kg_builder.add_entities(entities)
            self.kg_builder.add_relations(relations)

            # 同时把原文向量化后存入向量数据库，用于补充语义检索
            embedding = self.embedder.embed([doc])
            self.vector_store.add(embedding, [doc])

    def query(self, question):
        """
处理查询：结合知识图谱推理和向量检索
        """
        # ==================== 知识图谱检索 ====================
        # 先找出问题中涉及的相关实体
        # 例如"谁创立了 OpenAI？" -> 识别出实体 "OpenAI"
        relevant_entities = self.kg_builder.query_entities(question)

        # 基于这些实体，取出图谱中与之直接相关的子图
        # 子图包含相关实体及其邻接节点、连接边
        subgraph = self.kg_builder.get_subgraph(relevant_entities)

        # ==================== 向量检索 ====================
        # 作为补充通道，检索语义相似的文本内容
        vector_results = self.vector_store.search(question, top_k=5)

        # ==================== 结果融合 ====================
        # 把图谱推理结果与向量检索结果融合为统一上下文
        combined_context = self.fuse_results(subgraph, vector_results)

        # ==================== 生成 ====================
        return self.generator.generate(combined_context, question)

    def fuse_results(self, subgraph, vector_results):
        """
融合知识图谱子图与向量检索结果，组织成生成模型可读的上下文文本
        """
        # 把子图转换为自然语言描述（如"OpenAI -成立于-> 2015年"）
        kg_text = subgraph.to_text()

        # 拼接向量检索到的原文片段
        vector_text = "\n".join([doc for doc, _ in vector_results])

        return f"{kg_text}\n{vector_text}"

应用场景

GraphRAG es especialmente adecuado para los siguientes escenarios:

Preguntas y respuestas que requieren comprender relaciones entre entidades, por ejemplo, "¿quién es el CEO de esta empresa?".

Problemas que requieren razonamiento de múltiples saltos para obtener la respuesta, por ejemplo, "¿quién es el mentor del mentor de Zhang San?".

Escenarios donde es necesario descubrir relaciones implícitas en la base de conocimiento que no están escritas explícitamente.

需要注意的是，构建和维护知识图谱本身有一定的工程成本（实体/关系抽取的准确率、图谱更新维护等），因此更适合对关系推理有明确需求的场景，而不建议作为所有 RAG 项目的默认起点。

Comparación de soluciones y recomendaciones de selección

方案 核心思路 优势 局限 适用场景
基础 RAG Búsqueda vectorial + generación directa Implementación simple, bajo costo y curva de aprendizaje rápida Precisión de recuperación limitada; es fácil recuperar contenido no suficientemente relevante Preguntas y respuestas simples, validación rápida de prototipos
Advanced RAG（重排序） Filtrado grueso vectorial + reranking con Cross-Encoder Mejora significativamente la precisión del ordenamiento de la recuperación Añade una inferencia adicional del modelo, aumentando la latencia y el costo. Escenarios con altos requisitos de precisión en las respuestas
混合检索 Fusión de búsqueda vectorial y búsqueda por palabras clave Equilibra la coincidencia semántica y la coincidencia exacta de palabras clave Requiere mantener dos índices de recuperación simultáneamente Bases de conocimiento con abundantes nombres propios, código y números.
GraphRAG Fusión de grafo de conocimiento y búsqueda vectorial Admite razonamiento relacional y preguntas y respuestas multi-salto El costo de construcción y mantenimiento del grafo es alto Escenarios con requisitos claros de razonamiento relacional y de múltiples saltos.

章节小结

Este capítulo presenta las tecnologías centrales de RAG y la recuperación de conocimiento.

RAG 基础原理: al combinar la recuperación y la generación, permite que los agentes respondan preguntas utilizando conocimiento externo, en lugar de depender por completo de la memoria de los parámetros del modelo.

Advanced RAG: mediante técnicas como el reordenamiento y la recuperación híbrida, mejora aún más la calidad de la recuperación y la precisión de las respuestas sobre el flujo básico.

向量数据库: es la infraestructura del sistema RAG, responsable de almacenar y recuperar eficientemente las representaciones vectoriales de los documentos; la selección debe evaluarse de manera integral según el volumen de datos y el método de implementación.

GraphRAG: al integrar grafos de conocimiento, refuerza el razonamiento relacional y la capacidad de preguntas y respuestas de múltiples saltos, pero también conlleva costos adicionales de construcción y mantenimiento.

Para elegir la solución RAG adecuada, lo clave es comprender primero las necesidades reales del escenario de negocio: para preguntas y respuestas simples, el RAG básico suele ser suficiente; si se requieren alta precisión en la recuperación, se puede introducir el reordenamiento; si la base de conocimiento tiene muchos nombres propios/palabras clave, es adecuado incorporar recuperación híbrida; si involucra mucho razonamiento relacional y preguntas y respuestas de múltiples saltos, entonces considerar GraphRAG. Cuanto más compleja es la tecnología, mayores son los costos de ingeniería y mantenimiento; elegir según la necesidad es más importante que perseguir ciegamente "soluciones más avanzadas".
