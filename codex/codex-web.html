Codex Versión en la nube

Codex Web es la versión en la nube que te permite acceder a Codex desde cualquier dispositivo y ejecutar tareas en un entorno aislado.

Acceder a Codex Web

Para acceder a Codex en la nube:

https://chatgpt.com/codex

Requisitos de uso

  • Plan ChatGPT Plus / Pro / Business / Enterprise
  • O usar una API Key de OpenAI

Al usar una API Key, algunas funciones de la nube pueden no estar disponibles.

Entornos en la nube (Environments)

Environment es el concepto central de Codex Web; cada entorno es un espacio de trabajo aislado.

Crear entorno

  1. Conectar una cuenta de GitHub
  2. Seleccionar un repositorio
  3. Configurar script de configuración y variables de entorno
  4. Seleccionar política de acceso a la red

Flujo de ejecución de tareas

Las tareas en la nube se ejecutan según el siguiente flujo:

  1. Crear un contenedor y clonar el repositorio en la rama seleccionada
  2. Ejecutar el script de configuración para instalar dependencias
  3. Aplicar la configuración de acceso a la red
  4. El Agente ejecuta la tarea (editar código, ejecutar comandos, verificar resultados)
  5. Mostrar resultados y cambios de archivos

Imagen predeterminada

La nube utiliza una imagen llamadauniversalcomo imagen de contenedor predeterminada:

  • Lenguajes comunes preinstalados: Python, Node.js, Go, Rust
  • Incluye herramientas comunes: npm, pip, cargo, git
  • Se puede fijar la versión del runtime

Fijación de versión

Fijar versión

# Configuración de Environment

# Fijar versión de Python
python_version = "3.11"

# Fijar versión de Node.js
node_version = "20"

El script de configuración se ejecuta automáticamente al crear el contenedor:

Detección automática

Codex detecta automáticamente el tipo de proyecto y ejecuta la instalación correspondiente:

  • Node.js: ejecuta automáticamente npm install / yarn / pnpm
  • Python: ejecuta automáticamente pip install / poetry install

Script manual

Script de configuración personalizado

# Setup Script
# Configurar en la configuración del entorno

npm install
npm run build
pip install -r requirements.txt

Script de mantenimiento

El script de mantenimiento se ejecuta al iniciar el contenedor en caché:

  • Se usa para actualizar dependencias o reconstruir
  • Más rápido que una configuración completa

El script de configuración y el Agente se ejecutan en diferentes sesiones de Bash; los comandos export no persisten.

Variables de entorno y Secretos

Variables de entorno

Las variables de entorno están disponibles durante toda la tarea:

Configurar variables de entorno

# Environment Variables
NODE_ENV=production
DEBUG=false
API_ENDPOINT=https://api.example.com

Secrets

Los Secretos se usan para almacenar información sensible:

  • Almacenamiento con cifrado adicional
  • Solo se descifran durante la ejecución de la tarea
  • Solo disponibles en el script de configuración
  • Se eliminan automáticamente en la fase del Agente
TipoAlcance de visibilidadUso
Environment VariablesScript de configuración + AgenteConfiguración general
SecretsSolo script de configuraciónAPI Key, contraseñas

Control de acceso a la red

El acceso a la red en los entornos en la nube está restringido por defecto:

Configuración predeterminada

FaseAcceso a la red
Script de configuraciónPermitido (necesario para instalar dependencias)
AgentProhibido (predeterminado)

Opciones de acceso a la red del Agente

ConfiguraciónDescripción
OffProhibir completamente el acceso a la red
OnPermitir acceso a la red (se pueden restringir dominios)

Lista blanca de dominios

Configuración de dominios

# Configuración de red

# Lista blanca preestablecida
domain_allowlist = "common-dependencies"
# Incluye: github.com, npmjs.com, pypi.org, etc.

# Dominios personalizados
domain_allowlist = [
    "github.com",
    "api.mycompany.com"
]

# Restringir métodos HTTP
allowed_methods = ["GET", "HEAD", "OPTIONS"]

Riesgos de seguridad

Habilitar el acceso a la red del Agente aumenta los riesgos:

  • Inyección de prompts (obtener instrucciones de páginas web maliciosas)
  • Fuga de datos (enviar código o claves al exterior)
  • Descargar dependencias maliciosas

Habilita el acceso a la red del Agente solo cuando sea necesario y usa la lista blanca de dominios para restringirlo.

Caché de contenedores

La nube guarda en caché el estado del contenedor para acelerar tareas posteriores:

  • La caché dura hasta 12 horas
  • Se invalida automáticamente cuando cambian el script de configuración o las variables de entorno
  • Las nuevas tareas se inician más rápido

Gestión de tareas en la nube

Crear tarea

  1. Seleccionar entorno
  2. Ingresar descripción de la tarea
  3. Seleccionar modelo y configuración
  4. Iniciar tarea

Monitoreo de tareas

  • Ver el progreso en tiempo real
  • Ver cambios de archivos
  • Revisar la salida de comandos

Procesamiento de resultados

  • Ver el Diff de cambios
  • Crear Pull Request
  • Descargar archivos modificados

Tareas paralelas

La nube admite ejecutar múltiples tareas en paralelo:

  • Procesar diferentes funcionalidades al mismo tiempo
  • Múltiples entornos trabajando de forma independiente
  • Mejora la eficiencia general

Evita que múltiples tareas modifiquen el mismo archivo al mismo tiempo, de lo contrario se producirán conflictos.

Preguntas frecuentes

P: ¿Cuál es la diferencia entre Cloud y local?

Cloud se ejecuta en servidores remotos, ideal para tareas paralelas y acceso remoto; local opera directamente sobre tus archivos.

P: ¿Cómo se factura?

Las tareas en la nube consumen crédito; el costo se calcula según el modelo y el uso.

P: ¿Se puede acceder a archivos locales?

La nube no puede acceder a archivos locales, pero se pueden sincronizar mediante Git.

P: ¿Cuándo se necesita acceso a la red?

Solo se necesita cuando el Agente requiere datos en tiempo real o APIs externas; el script de configuración suele ser suficiente.
