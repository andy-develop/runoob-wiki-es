C++ Clases y objetos

C++ añade programación orientada a objetos sobre la base del lenguaje C; C++ admite programación orientada a objetos. La clase es una característica central de C++ y a menudo se denomina tipo definido por el usuario.

La clase se utiliza para especificar la forma de los objetos; es un tipo de datos definido por el usuario, una combinación que encapsula datos y funciones. Los datos en una clase se llaman variables miembro, y las funciones se llaman funciones miembro. La clase puede considerarse como una plantilla que se puede usar para crear múltiples objetos con las mismas propiedades y comportamientos.

Definición de clases en C++

Para definir una clase se necesita la palabra claveclassluego se especifica el nombre de la clase, y el cuerpo de la clase está encerrado entre un par de llaves; el cuerpo contiene las variables miembro y las funciones miembro de la clase.

Definir una clase es, en esencia, definir un plano de un tipo de datos; define qué incluyen los objetos de la clase y qué operaciones se pueden realizar sobre ese objeto.

En el siguiente ejemplo usamos la palabra claveclasspara definir el tipo de datos Box, que contiene tres variables miembro: length, breadth y height:

class Box { public: double length; // la longitud de la caja double breadth; // el ancho de la caja double height; // la altura de la caja };

La palabra clavepublicdetermina los atributos de acceso de los miembros de la clase. Dentro del ámbito del objeto de la clase, los miembros públicos son accesibles desde fuera de la clase. También puede especificar los miembros de la clase comoprivate 或 protected, esto lo explicaremos más adelante.

Definir objetos de C++

La clase proporciona el plano de los objetos, por lo que básicamente los objetos se crean según la clase. Declarar un objeto de una clase es como declarar una variable de un tipo básico. La siguiente declaración define dos objetos de la clase Box:

Box Box1; // declara Box1, de tipo Box Box Box2; // declara Box2, de tipo Box

Los objetos Box1 y Box2 tienen cada uno sus propios miembros de datos.

Acceso a miembros de datos

Los miembros de datos públicos de un objeto de clase pueden utilizar el operador de acceso directo a miembros.para acceder.

Para comprender mejor estos conceptos, probemos el siguiente ejemplo:

Ejemplo

#include <iostream> using namespace std; class Box { public: double length; // longitud double breadth; // ancho double height; // altura // declaración de la función miembro double get(void); void set( double len, double bre, double hei ); }; // definición de la función miembro double Box::get(void) { return length * breadth * height; } void Box::set( double len, double bre, double hei) { length = len; breadth = bre; height = hei; } int main( ) { Box Box1; // declara Box1, de tipo Box Box Box2; // declara Box2, de tipo Box Box Box3; // declara Box3, de tipo Box double volume = 0.0; // para almacenar el volumen // detalles de box 1 Box1.height = 5.0; Box1.length = 6.0; Box1.breadth = 7.0; // detalles de box 2 Box2.height = 10.0; Box2.length = 12.0; Box2.breadth = 13.0; // el volumen de box 1 volume = Box1.height * Box1.length * Box1.breadth; cout << "Volumen de Box1:" << volume <<endl; // el volumen de box 2 volume = Box2.height * Box2.length * Box2.breadth; cout << "Volumen de Box2:" << volume <<endl; // detalles de box 3 Box3.set(16.0, 8.0, 12.0); volume = Box3.get(); cout << "Volumen de Box3:" << volume <<endl; return 0; }

    El struct en C++ es una extensión del struct en C; ya no es solo una estructura de datos que contiene diferentes tipos de datos, ha adquirido demasiadas funcionalidades.

    ¿Puede struct contener funciones miembro? ¡Sí!

    ¿Puede struct heredar? ¡¡Sí!!

    ¿Puede struct implementar polimorfismo? ¡¡¡Sí!!!

    Ya que puede hacer todo esto, ¿qué diferencia queda con class?

    La diferencia más esencial es el control de acceso predeterminado, que se refleja en dos aspectos:

    1) El permiso de acceso de herencia predeterminado. struct es public, class es private.

    Puedes escribir el siguiente código:

    struct A
{
    char a;
};
struct B : A
{
    char b;
};

    En este caso, B hereda de A de forma public.

    Si todos los struct anteriores se cambian a class, entonces B hereda de A de forma private. Este es el permiso de acceso de herencia predeterminado.

    Por lo tanto, cuando normalmente escribimos herencia de clases, solemos escribir así:

    struct B : public A

    Es para indicar que es herencia public, en lugar de usar la herencia private predeterminada.

    Por supuesto, si la herencia predeterminada es public o private depende de la subclase, no de la clase base.

    Quiero decir que struct puede heredar de class, y class también puede heredar de struct; entonces el permiso de acceso de herencia predeterminado depende de si la subclase usa struct o class. Como sigue:

    struct A{}; 
class B : A{}; //private继承
struct C : B{}; //public继承

    2) Como struct es la implementación de una estructura de datos, su control de acceso a datos predeterminado es public, mientras que class, como implementación de un objeto, su control de acceso a variables miembro predeterminado es private.

    Observa mi elección de palabras anterior; sigo enfatizando que struct es un cuerpo de implementación de una estructura de datos, aunque se puede usar igual que class. Sigo llamando "datos" a las variables dentro de struct y "miembros" a las variables dentro de class, aunque no hay diferencia entre ellas.

    En realidad, usar struct o class depende completamente de la preferencia personal; puedes reemplazar todas las class en tu programa por struct y seguirá funcionando con normalidad. Pero mi mejor consejo es: si crees que lo que vas a hacer se parece más a una estructura de datos, entonces usa struct; si lo que vas a hacer se parece más a un objeto, entonces usa class.

    Por supuesto, aquí también quiero enfatizar un punto: para el control de acceso, se debe especificar explícitamente en el programa en lugar de depender de los valores predeterminados. Es un buen hábito y también hace que tu código sea más legible.

    Llegado a este punto, muchas personas con conocimientos quizás crean que este tema puede darse por concluido, porque saben que la "única" diferencia entre struct y class es el control de acceso. Mucha documentación efectivamente solo menciona esta diferencia.

    Pero arriba no usé "única", sino "más esencial", porque realmente tienen otra diferencia, aunque esa diferencia quizás rara vez la tratemos normalmente. Esa es: la palabra clave "class" también se usa para definir parámetros de plantilla, como "typename". Pero la palabra clave "struct" no se usa para definir parámetros de plantilla. Este punto fue explicado en Inside the C++ Object Model escrito por Stanley B.Lippman.

    La discusión del tema hasta aquí, básicamente debería poder concluir. Pero alguien dijo una vez que había encontrado otras "diferencias", así que veamos si realmente es otra diferencia. Como se dijo anteriormente, struct en C++ es una extensión de struct en C. Ya que es una extensión, debe ser compatible con todas las características que struct debía tener en C. Por ejemplo, puedes escribir así:

    struct A //定义一个struct
{
    char c1;
    int n2;
    double db3;
};
A a={'p',7,3.1415926}; //定义时直接赋值

    Es decir, struct puede usar {} para asignar valores iniciales al definirse. Entonces surge la pregunta: ¿puede class hacerlo? Cambia struct por class en lo anterior e inténtalo. ¡Error! Oh~ entonces esa persona saltó diciendo que había encontrado otra diferencia. Miremos con atención, ¿es realmente otra diferencia?

    Intenta agregar un constructor (o función virtual) al struct anterior, ¿qué descubrirás?

    Correcto, struct tampoco puede usar {} para asignar valores iniciales.

    En efecto, asignar valores iniciales con {} es solo usar una lista de inicialización para inicializar los datos en orden. Por ejemplo, si arriba se escribe A a={'p',7}; entonces c1, n2 se inicializan, pero db3 no. Una operación de copia tan simple solo puede ocurrir en estructuras de datos simples, y no debería aplicarse a objetos. Agregar un constructor o una función virtual hace que struct refleje más las características de un objeto, haciendo que esta operación {} ya no sea válida.

    De hecho, es porque agregar tales funciones hace que la estructura interna de la clase cambie. ¿Y si se agrega una función miembro ordinaria? Descubrirás que {} sigue siendo utilizable. En realidad, puedes entender las funciones ordinarias como un algoritmo para la estructura de datos, lo cual no rompe sus características de estructura de datos.

    Entonces, viendo esto, descubrimos que incluso si struct quiere usar {} para asignar valores iniciales, debe cumplir muchas restricciones. Estas condiciones en realidad hacen que struct refleje más una estructura de datos en lugar de las características de una clase.

    Entonces, ¿por qué arriba, con solo cambiar struct a class, {} ya no se puede usar?

    En realidad, el problema es precisamente lo que dijimos antes: ¡control de acceso! Mira, ¿qué olvidamos? Correcto, al cambiar struct a class, el control de acceso cambia de public a private, por lo que naturalmente no se puede usar {} para asignar valores iniciales. Agrega un public, y descubrirás que class también puede usar {}, ¡¡¡sin ninguna diferencia con struct!!!

    Como resumen, de las diferencias anteriores podemos ver que struct es más adecuado para ser visto como una implementación de estructura de datos, y class es más adecuado para ser visto como una implementación de objeto.

    Fuera de la clase, en realidad también se puede usar un puntero para acceder a los miembros privados de la clase, por ejemplo:

    #include <iostream>
using namespace std;

class a    // 定义了类a
{
    long a0;   // 定义私有成员 a0
    public:
    a(long b)
    {
        a0=b;
    }
    void geta()
    {
        cout<<a0<<endl;
    }
};
int main()
{
    a b(5);          // 定义对象b，并给 b 中的 a0 赋初值
    long *p;
    p=(long*)&b;     // 令指针 p 指向 b 中前 4 个字节，在这里相当于指向 a0
    b.geta();        // 用内部函数访问 a0
    cout<<*p<<endl;  // 在外部直接访问 a0
    *p=8;            // 在外部改变 a0 的值
    b.geta();        // 输出改变后的结果
    cout<<*p<<endl;
    return 0;
}

    Cabe señalar que, aunque este método puede usarse en el desarrollo de algunos programas basados en el principio de polimorfismo de clases, viola el principio de encapsulación de la clase y es extremadamente inseguro en clases que usan punteros, por lo que no se recomienda su uso.

    ¿Qué sucede cuando se asigna un objeto a otro objeto?

    Box Box1;        // 创建 Box1，执行后Box1已存在
Box Box2;        // 创建 Box2，执行后Box2已存在
Box2 = Box1;     // 这时是把Box1的成员变量值复制给了Box2，Box2还是原来的对象，并没有被销毁，对象地址还是原来的  地址。
Box &Box3 = Box1; // 创建Box1的引用变量Box3.

    DondeBox &Box3 = Box1, similar a la de JavaBox3 = Box1。

    y la diferencia con Java: la referencia en C++ debe inicializarse al crearse y, después de crearse, ya no puede apuntar a otro objeto, mientras que en Java un nombre de objeto puede apuntar en cualquier momento a otro objeto de la misma clase.

    La conclusión anterior se obtiene con el siguiente ejemplo:

    return length * breadth * height;

{

    breadth = bre;
    height = hei;
}
int main( )
{

   // box 2 详述
   volume = Box2.get(); 
   cout << "Box2 的地址：" << &Box2 <<endl;
   cout << "Box2 的体积：" << volume <<endl;
    
   Box2 = Box1;
   volume = Box2.get();

    // 1. 基础准备
#include <iostream>   // 引入输入输出库
using namespace std;  // 使用标准命名空间（简化代码书写）

// 2. 盒子类的声明
class Box {
public:               // 公有访问权限（初学者先记住这是必要结构）
    // 成员变量（物体的三维属性）
    double length;    // 长
    double breadth;   // 宽
    double height;    // 高
    
    // 成员函数声明（能力说明）
    double get();     // 获取体积
    void set(double l, double b, double h); // 设置尺寸
};

// 3. 成员函数具体实现
double Box::get() {   // 双冒号表示属于Box类的函数
    return length * breadth * height; // 体积计算公式
}

void Box::set(double l, double b, double h) {
    length = l;      // 将参数值赋给成员变量
    breadth = b;
    height = h;
}

// 4. 主程序（使用案例）
int main() {
    // 创建三个不同的盒子对象
    Box Box1, Box2, Box3; 
    double volume = 0;  // 临时存储计算结果

    /* 操作方式对比 */
    // 方式一：直接操作成员变量（公开访问）
