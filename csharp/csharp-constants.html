C# Constantes

Las constantes son valores fijos que no cambian durante la ejecución del programa. Las constantes pueden ser de cualquier tipo de datos básico, como constantes enteras, constantes de coma flotante, constantes de caracteres o constantes de cadenas, así como constantes de enumeración.

Las constantes pueden tratarse como variables normales, solo que su valor no puede modificarse después de definirse.

Constantes enteras

Las constantes enteras pueden ser decimales, octales o hexadecimales. El prefijo especifica la base: 0x o 0X indica hexadecimal, 0 indica octal, y sin prefijo indica decimal.

Las constantes enteras también pueden tener sufijos, que pueden ser una combinación de U y L, donde U y L representan unsigned y long respectivamente. Los sufijos pueden ser mayúsculas o minúsculas, y varios sufijos se combinan en cualquier orden.

Aquí hay algunos ejemplos de constantes enteras:

212         /* 合法 */
215u        /* 合法 */
0xFeeL      /* 合法 */
078         /* 非法：8 不是一个八进制数字 */
032UU       /* 非法：不能重复后缀 */

Los siguientes son ejemplos de constantes enteras de varios tipos:

85         /* 十进制 */
0213       /* 八进制 */
0x4b       /* 十六进制 */
30         /* int */
30u        /* 无符号 int */
30l        /* long */
30ul       /* 无符号 long */

Constantes de coma flotante

Una constante de coma flotante se compone de parte entera, punto decimal, parte fraccionaria y exponente. Puede representar constantes de coma flotante en forma decimal o exponencial.

Aquí hay algunos ejemplos de constantes de coma flotante:

3.14159       /* 合法 */
314159E-5L    /* 合法 */
510E          /* 非法：不完全指数 */
210f          /* 非法：没有小数或指数 */
.e55          /* 非法：缺少整数或小数 */

Al representar en forma de coma flotante, debe incluir punto decimal, exponente o ambos. Al representar en forma exponencial, debe incluir parte entera, parte fraccionaria o ambas. El exponente con signo se representa con e o E.

Constantes de caracteres

Las constantes de caracteres se escriben entre comillas simples, por ejemplo, 'x', y se pueden almacenar en una variable de tipo carácter simple. Una constante de carácter puede ser un carácter ordinario (por ejemplo, 'x'), una secuencia de escape (por ejemplo, '\t') o un carácter universal (por ejemplo, '\u02C0').

En C#, hay ciertos caracteres que tienen un significado especial cuando van precedidos de una barra invertida, y se pueden usar para representar un salto de línea (\n) o una tabulación (\t). Aquí se enumeran algunos códigos de secuencias de escape:

Secuencia de escapeSignificado
\\\ Carácter
\'' Carácter
\"" Carácter
\?? Carácter
\aAlerta o campana
\bRetroceso (Backspace)
\fAvance de página (Form feed)
\nNueva línea (Newline)
\rRetorno de carro
\tTabulación horizontal (tab)
\vTabulación vertical (tab)
\oooNúmero octal de uno a tres dígitos
\xhh . . .Número hexadecimal de uno o más dígitos

Los siguientes son algunos ejemplos de caracteres de secuencias de escape:

namespace EscapeChar
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("Hello\tWorld\n\n");
            Console.ReadLine();
        }
    }
}

Cuando el código anterior se compila y ejecuta, produce los siguientes resultados:

Hello   World

Constantes de cadenas

Las constantes de cadena están entre comillas dobles""o entre@""Las constantes de cadena contienen caracteres similares a las constantes de carácter: caracteres ordinarios, secuencias de escape y caracteres universales.

Al usar constantes de cadena, puede dividir una línea muy larga en varias líneas, y puede usar espacios para separar las partes.

Aquí hay algunos ejemplos de constantes de cadena. Las distintas formas que se enumeran a continuación representan la misma cadena.

string a = "hello, world";                  // hello, world
string b = @"hello, world";               // hello, world
string c = "hello \t world";               // hello     world
string d = @"hello \t world";               // hello \t world
string e = "Joe said \"Hello\" to me";      // Joe said "Hello" to me
string f = @"Joe said ""Hello"" to me";   // Joe said "Hello" to me
string g = "\\\\server\\share\\file.txt";   // \\server\share\file.txt
string h = @"\\server\share\file.txt";      // \\server\share\file.txt
string i = "one\r\ntwo\r\nthree";
string j = @"one
two
three";

Definir constantes

Las constantes se definen usando laconstpalabra clave. La sintaxis para definir una constante es la siguiente:

const <data_type> <constant_name> = value;

El siguiente código demuestra cómo definir y usar constantes en un programa:

Ejemplo

using System;

public class ConstTest
{
    class SampleClass
    {
        public int x;
        public int y;
        public const int c1 = 5;
        public const int c2 = c1 + 5;

        public SampleClass(int p1, int p2)
        {
            x = p1;
            y = p2;
        }
    }

    static void Main()
    {
        SampleClass mC = new SampleClass(11, 22);
        Console.WriteLine("x = {0}, y = {1}", mC.x, mC.y);
        Console.WriteLine("c1 = {0}, c2 = {1}",
                          SampleClass.c1, SampleClass.c2);
    }
}

Cuando el código anterior se compila y ejecuta, produce los siguientes resultados:

x = 11, y = 22
c1 = 5, c2 = 10

    1. La diferencia entre Convert.ToDouble y Double.Parse. En realidad, Convert.ToDouble y Double.Parse son bastante similares; de hecho, Convert.ToDouble internamente llama a Double.Parse:

    (1) Cuando el parámetro es null:

    • Cuando el parámetro de Convert.ToDouble es null, devuelve 0.0;
    • Cuando el parámetro de Double.Parse es null, lanza una excepción.

    (2) Cuando el parámetro es "":

    • Cuando el parámetro de Convert.ToDouble es "", lanza una excepción;
    • Cuando el parámetro de Double.Parse es "", lanza una excepción.

    (3) Otras diferencias:

    • Convert.ToDouble puede convertir más tipos;
    • Double.Parse solo puede convertir cadenas de tipo numérico.
    • Double.TryParse es bastante similar a Double.Parse, pero no produce excepciones; devuelve true si la conversión es exitosa y false si falla. El último parámetro es el valor de salida; si la conversión falla, el valor de salida es 0.0.

    Código de prueba adjunto:

    using System;
using System.Collections.Generic;
using System.Linq;
using System.Text;

namespace ConsoleApplication1
{
    class Program
    {
        static void Main(string[] args)
        {
            try
            {
                //string a = "0.2";
                //string a = null;
                string a = "";
                try
                {
                    double d1 = Double.Parse(a);
                }
                catch (Exception err)
                {
                    Console.WriteLine("d1转换出错:" + err.Message);
                }

                try
                {
                    double d2 = Convert.ToDouble(a);
                }
                catch (Exception err)
                {
                    Console.WriteLine("d2转换出错:" + err.Message);

                }
                try
                {
                    double d3;
                    Double.TryParse(a,out d3);
                }
                catch (Exception err)
                {
                    Console.WriteLine("d3转换出错:" + err.Message);
                }
            }
            finally
            {
                Console.ReadKey();
            }

        }
    }
}

    2. La diferencia entre Convert.ToInt32() y int.Parse()

    Si no tienes claras las sutiles diferencias entre Convert.ToInt32 y int.Parse(), no las uses a la ligera, de lo contrario pueden producirse resultados inesperados. Por ejemplo: supongamos que se toma el valor de un parámetro page de una URL; sabemos que este valor es un int, por lo que se puede usar tanto Convert.ToInt32(Request.QueryString["page"]) como int.Parse(Request.QueryString["page"]). Pero si el parámetro page no existe en la URL, el primero devolverá 0, y 0 puede ser un valor válido, por lo que no sabrás que el parámetro no estaba en la URL y continuarás con el siguiente paso, lo que puede tener efectos inesperados. Con el segundo método, si no existe el parámetro page, se lanzará una excepción; podemos capturar la excepción y luego hacer el manejo correspondiente, como indicar al usuario que falta el parámetro, en lugar de tratar el valor del parámetro como 0.

    (1) La mayor diferencia entre estos dos métodos es su manejo del valor null:

    Convert.ToInt32(null) devuelve 0 sin lanzar ninguna excepción, pero int.Parse(null) lanza una excepción.

    (2) Diferencia al redondear datos

    a. Convert.ToInt32(double value)

    Si value es un número entre dos enteros, devuelve el número par de ambos; es decir, 3.5 se convierte a 4, 4.5 se convierte a 4, y 5.5 se convierte a 6. Sin embargo, 4.6 se convierte a 5, y 4.4 se convierte a 4.

    b. int.Parse("4.5")

    Lanza un error directamente: "El formato de la cadena de entrada es incorrecto".

    c. int(4.6) = 4

    Al convertir otros tipos numéricos a Int, no hay redondeo; es una conversión forzada.

    (3) Diferencia en el tipo a convertir

    int.Parse convierte un String a int

    Convert.ToInt32 convierte objetos que heredan de Object a int (pueden ser muchos otros tipos de datos).

    Si obtienes un objeto object y quieres convertirlo a int, no puedes usar int.Parse; debes usar Convert.ToInt32.

    1. Constante estática (constante en tiempo de compilación) const

    El valor se determina en tiempo de compilación; debe inicializarse en el momento de la declaración y no puede modificarse después. Se puede definir en clases y métodos. La forma de definición es la siguiente:

    const double a=3.14；// 正确声明常量的方法
const int b;         // 错误，没有初始化

    2. Constante dinámica (constante en tiempo de ejecución) readonly

    El valor se determina en tiempo de ejecución; solo se puede inicializar en la declaración o en el constructor, y solo se puede definir en clases. La forma de definición es la siguiente:

    class Program
{
    readonly int a=1;  // 声明时初始化
    readonly int b;    // 构造函数中初始化
    Program()
    {
        b=2;
    }
    static void Main()
    {
    }
}

    Reglas sobre la nomenclatura de variables constantes:

    Las constantes con modificador de acceso private deben nombrarse con notación camello, es decir, comenzando con un guion bajo, con la primera letra de la primera palabra en minúscula y la primera letra de las palabras restantes en mayúscula.

    private const string _bookName = "新华字典";

    Las constantes con modificador público public, protegido protected, etc., deben nombrarse con notación Pascal, es decir, la primera letra de cada palabra en mayúscula.

    public const int BookPrice = 10;

    El valor de const debe conocerse en tiempo de compilación; en otras palabras, debes dar a la constante un valor inicial y no puedes usar una variable para inicializar la constante:

    static void Main(string[] args)
{
  int a=14;//必须要有初始值
  const int b=a;//报错
}

    Al compilar la constante, el valor de la constante reemplaza a la constante, lo que puede mejorar la eficiencia de ejecución.

    Pero si cambias el valor de una constante (a) en un ensamblado (A) (lo cambias de 12 a 14) pero no has ejecutado el ensamblado A, entonces para el ensamblado (B) que referencia esta constante (a), el valor de la constante seguirá siendo 12.

    Además, no todos los valores pueden inicializar constantes. Si quieres usar un valor que no es compatible con constantes, usa readonly.

    static A a;
readonly A a1=a;
const A a2=a;// 只能为 null

    Y readonly resuelve las desventajas de const:

    Se traduce como campo de solo lectura, por lo que solo se puede declarar dentro de una clase.

    Se puede calcular o cargar en tiempo de ejecución, y también se puede inicializar en el constructor:

    int a1=14;
readonly int a;
A()
{
  a=a1;
}

    Usar readonly también puede evitar las desventajas de const con respecto a los ensamblados.
