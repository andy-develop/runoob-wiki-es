C# Directivas de preprocesador

Las directivas de preprocesador (Preprocessor Directives) guían al compilador para preprocesar la información antes de que comience la compilación real.

A través de estas directivas, se puede controlar cómo compila el compilador los archivos o qué partes compila. Las directivas de preprocesador comunes incluyen la compilación condicional, la definición de macros, etc.

Todas las directivas de preprocesador comienzan con#y, en una sola línea, solo pueden aparecer caracteres de espacio en blanco delante de la directiva de preprocesador.

Las directivas de preprocesador no son instrucciones, por lo que no terminan con un punto y coma;al final.

El compilador de C# no tiene un preprocesador separado, pero las directivas se procesan como si hubiera un preprocesador separado. En C#, las directivas de preprocesador se utilizan para la compilación condicional. A diferencia de C y C++, no se utilizan para crear macros. Una directiva de preprocesador debe ser la única directiva en esa línea.

Lista de directivas de preprocesador de C#

La siguiente tabla enumera las directivas de preprocesador disponibles en C#:

DirectivaDescripción
#defineDefine un símbolo que se puede utilizar para la compilación condicional.
#undefCancela la definición de un símbolo.
#ifInicia un bloque de compilación condicional; si el símbolo está definido, se incluye el bloque de código.
#elifSi la condición anterior#if 或 #elifno se cumple, y la condición actual se cumple, entonces se incluye el bloque de código.
#elseSi la condición anterior#if 或 #elifno se cumple, entonces se incluye el bloque de código.
#endifFinaliza un bloque de compilación condicional.
#warningGenera un mensaje de advertencia del compilador.
#errorGenera un mensaje de error del compilador.
#regionMarca una región de código que se puede plegar y expandir en el IDE, facilitando la organización y lectura del código.
#endregionFinaliza una región de código.
#lineCambia el número de línea y el nombre de archivo en la salida del compilador; puede utilizarse para depurar o para código generado por herramientas.
#pragmaSe utiliza para enviar instrucciones especiales al compilador, por ejemplo, deshabilitar o restaurar advertencias específicas.
#nullableControla el contexto y las anotaciones de nulabilidad, lo que permite habilitar o deshabilitar las comprobaciones del compilador para los tipos de referencia anulables.

#if DEBUG

Directivas de preprocesador #define y #undef

#defineSe utiliza para definir un símbolo (generalmente para compilación condicional),#undefSe utiliza para cancelar la definición de un símbolo.

#define DEBUG

#undef RELEASE

#define le permite definir un símbolo; de esta manera, al usar el símbolo como expresión pasada a la directiva #if, la expresión devolverá true. Su sintaxis es la siguiente:

#define symbol

El siguiente programa ilustra esto:

Ejemplo

#define PI
using System;
namespace PreprocessorDAppl
{
   class Program
   {
      static void Main(string[] args)
      {
         #if (PI)
            Console.WriteLine("PI is defined");
         #else
            Console.WriteLine("PI is not defined");
         #endif
         Console.ReadKey();
      }
   }
}

Cuando el código anterior se compila y se ejecuta, produce el siguiente resultado:

PI is defined

Directivas condicionales: #if, #elif, #else y #endif

Puede utilizar la#ifdirectiva para crear una directiva condicional.

Las directivas condicionales se utilizan para comprobar si un símbolo es verdadero. Si es verdadero, el compilador ejecuta#ifel código comprendido entre esa directiva y la siguiente.

La sintaxis de las directivas condicionales es:

#if symbol [operator symbol]...

Donde,symboles el nombre del símbolo que se va a probar. También puede usar true y false, o colocar el operador de negación delante del símbolo.

Los operadores comunes son:

  • == (igual a)
  • != (no igual a)
  • && (y)
  • || (o)

También puede usar paréntesis para agrupar símbolos y operadores. Las directivas condicionales se utilizan para compilar código en versiones de depuración o al compilar una configuración específica. Una directiva que comience con#ifdebe terminar explícitamente con una#endifdirectiva.

#define DEBUG

#if DEBUG
    Console.WriteLine("Debug mode");
#elif RELEASE
    Console.WriteLine("Release mode");
#else
    Console.WriteLine("Other mode");
#endif

El siguiente programa demuestra el uso de las directivas condicionales:

Ejemplo

#define DEBUG
#define VC_V10
using System;
public class TestClass
{
   public static void Main()
   {

      #if (DEBUG && !VC_V10)
         Console.WriteLine("DEBUG is defined");
      #elif (!DEBUG && VC_V10)
         Console.WriteLine("VC_V10 is defined");
      #elif (DEBUG && VC_V10)
         Console.WriteLine("DEBUG and VC_V10 are defined");
      #else
         Console.WriteLine("DEBUG and VC_V10 are not defined");
      #endif
      Console.ReadKey();
   }
}

Cuando el código anterior se compila y ejecuta, produce el siguiente resultado:

DEBUG and VC_V10 are defined

#warning y #error

#warning se utiliza para generar advertencias del compilador y #error para generar errores del compilador.

#warning This is a warning message
#error This is an error message

#region y #endregion

Se utilizan para plegar código, haciendo que el código sea más legible.

#region MyRegion
    // Your code here
#endregion

#line

Se utiliza para cambiar el número de línea y el nombre de archivo en la salida del compilador.

#line 100 "MyFile.cs"
    // The next line will be reported as line 100 in MyFile.cs
    Console.WriteLine("This is line 100");
#line default
    // Line numbering returns to normal

#pragma

Se utiliza para enviar instrucciones especiales al compilador. El uso más común es deshabilitar advertencias específicas.

#pragma warning disable 414
    private int unusedVariable;
#pragma warning restore 414

Consideraciones sobre el uso de directivas de preprocesador

  • Mejorar la legibilidad del código: usar#regionpuede ayudar a separar bloques de código, mejorando la organización del código.
  • Compilación condicional: mediante#ify otras directivas, se puede compilar código diferente en entornos de desarrollo y producción, lo que facilita la depuración y la publicación.
  • Advertencias y errores: mediante#warning和#errorse puede indicar a los desarrolladores en tiempo de compilación que presten atención a problemas específicos.

Al utilizar correctamente estas directivas de preprocesador, se puede controlar mejor el proceso de compilación del código y mejorar la flexibilidad y la mantenibilidad del código.

    Comprensión del propósito de las directivas de preprocesador:

    Desempeñan un papel importante en la depuración y ejecución de programas. Por ejemplo, las directivas de preprocesador pueden evitar que el compilador compile una parte del código. Si se planea publicar dos versiones del código, es decir, una versión básica y una versión empresarial con más funciones, se pueden utilizar estas directivas de preprocesador para controlarlo. Al compilar la versión básica del software, el uso de directivas de preprocesador también puede evitar que el compilador compile código relacionado con funciones adicionales. Además, al escribir código que proporciona información de depuración, también se pueden utilizar directivas de preprocesador para controlarlo. En general, su función es similar a la de las sentencias de control ordinarias (como if), y la ventaja es que las partes no ejecutadas incluidas por las directivas de preprocesador no necesitan ser compiladas.

    #define PI
using System;
namespace PreprocessorDAppl
{
   class Program
   {
      static void Main(string[] args)
      {
         #if (PI)
            Console.WriteLine("PI is defined");     //PI不存在，则这条语句不编译
         #else
            Console.WriteLine("PI is not defined"); //PI存在，则这条语句不编译
         #endif
         Console.ReadKey();
      }
   }
}

    Otras directivas de preprocesador:

    #warning y #error:

    Cuando el compilador las encuentra, genera una advertencia o un error, respectivamente. Si el compilador encuentra una directiva #warning, muestra al usuario el texto que sigue a la directiva #warning y la compilación continúa. Si el compilador encuentra una directiva #error, muestra al usuario el texto posterior como un mensaje de error de compilación y sale inmediatamente de la compilación. Estas dos directivas se pueden utilizar para comprobar si una instrucción #define se ha hecho incorrectamente, y la instrucción #warning se puede utilizar para recordarse a uno mismo realizar alguna acción.

    #if DEBUG && RELEASE  
#error "You've defined DEBUG and RELEASE simultaneously!"  
#endif  
#warning "Don't forget to remove this line before the boss tests the code!"  
Console.WriteLine("*I hate this job.*");

    2. #region y #endregion

    Las directivas #region y #endregion se utilizan para marcar un bloque de código con un nombre determinado, como se muestra a continuación:

    #region Member Field Declarations
int x;
double d;
Currency balance;
#endregion

    Esto puede parecer que no sirve de mucho, ya que no afecta al proceso de compilación. La ventaja de estas directivas es que pueden ser reconocidas por algunos editores, incluido el editor de Visual Studio .NET. Estos editores pueden utilizar estas directivas para organizar mejor el código en la pantalla.

    3. #line

    La directiva #line se puede utilizar para cambiar el nombre de archivo y el número de línea que el compilador muestra en los mensajes de advertencia y error; no se usa con frecuencia.

    Si al escribir código, antes de enviarlo al compilador, se utilizan ciertos paquetes de software para modificar el código de entrada, se puede usar esta directiva, porque esto significa que el número de línea o el nombre de archivo informado por el compilador no coincide con el número de línea del archivo o con el nombre del archivo editado. La directiva #line se puede utilizar para restaurar esa coincidencia. También se puede usar la sintaxis #line default para restaurar el número de línea al número de línea predeterminado:

    #line 164 "Core.cs" // 在文件的第 164 行
// Core.cs, before the intermediate
// package mangles it.
// later on
#line default // 恢复默认行号

    4. #pragma

    La directiva #pragma puede suprimir o restaurar advertencias de compilación específicas. A diferencia de las opciones de línea de comandos, la directiva #pragma se puede ejecutar a nivel de clase o método, lo que permite un control más preciso sobre el contenido de las advertencias suprimidas y el momento de la supresión. Como se muestra a continuación:

    #pragma warning disable 169    // 取消编号 169 的警告（字段未使用的警告）
public class MyClass
{
    int neverUsedField;       // 编译整个 MyClass 类时不会发出警告
}
#pragma warning restore 169   // 恢复编号 169 的警告
