Patrón Decorador

El patrón decorador (Decorator Pattern) permite añadir nuevas funcionalidades a un objeto existente sin cambiar su estructura. Este tipo de patrón de diseño pertenece a los patrones estructurales y actúa como un envoltorio de una clase existente.

El patrón decorador envuelve el objeto en una clase decoradora para modificar dinámicamente su comportamiento.

Este patrón crea una clase decoradora que envuelve la clase original y proporciona funcionalidad adicional manteniendo la integridad de las firmas de los métodos de la clase.

Demostramos el uso del patrón decorador con el siguiente ejemplo. En él, decoraremos una forma con diferentes colores sin modificar la clase de la forma.

Resumen

Intención

Añadir dinámicamente responsabilidades adicionales a un objeto sin cambiar su estructura. El patrón decorador ofrece una alternativa flexible a la herencia para extender funcionalidades.

Problemas principales que resuelve

  • Evita introducir características estáticas mediante la herencia, especialmente cuando el número de subclases crece desmesuradamente.
  • Permite añadir o modificar dinámicamente la funcionalidad de un objeto en tiempo de ejecución.

Escenarios de uso

  • Cuando se necesita ampliar la funcionalidad de una clase sin crear una gran cantidad de subclases.
  • Cuando se necesita añadir o eliminar dinámicamente funcionalidades de un objeto.

Método de implementación

  • Definir la interfaz del componente: crear una interfaz que establezca el estándar para los objetos a los que se pueden añadir responsabilidades dinámicamente.
  • Crear el componente concreto: clases concretas que implementan la interfaz y proporcionan la funcionalidad básica.
  • Crear el decorador abstracto: implementa la misma interfaz, mantiene una referencia a la interfaz del componente y puede añadir funcionalidades dinámicamente en cualquier momento.
  • Crear el decorador concreto: extiende el decorador abstracto y añade responsabilidades adicionales.

Código clave

  • Interfaz Component: define el estándar de los objetos que pueden ser decorados.
  • Clase ConcreteComponent: clase concreta que implementa la interfaz Component.
  • Clase abstracta Decorator: implementa la interfaz Component y contiene una referencia a la interfaz Component.
  • Clase ConcreteDecorator: extiende la clase Decorator y añade funcionalidades adicionales.

Ejemplos de aplicación

  1. Las 72 transformaciones de Sun Wukong: Sun Wukong (ConcreteComponent) obtiene nuevas habilidades mediante las transformaciones (Decorator).
  2. Marco que decora un cuadro: una pintura (ConcreteComponent) puede mejorar su presentación añadiendo vidrio (ConcreteDecorator) y un marco (ConcreteDecorator).

Ventajas

  • Bajo acoplamiento: la clase decoradora y la clase decorada pueden cambiar de forma independiente sin afectarse mutuamente.
  • Flexibilidad: se pueden añadir o eliminar funcionalidades dinámicamente.
  • Alternativa a la herencia: proporciona una forma de extender la funcionalidad de un objeto más allá de la herencia.

Desventajas

  • Complejidad: la decoración en múltiples capas puede aumentar la complejidad del sistema.

Recomendaciones de uso

  • Considere usar el patrón decorador cuando necesite extender funcionalidades dinámicamente.
  • Mantenga la coherencia entre las interfaces del decorador y del componente concreto para garantizar la flexibilidad.

Precauciones

  • El patrón decorador puede sustituir a la herencia, pero debe usarse con precaución para evitar que la decoración excesiva complique el sistema.

Estructura

El patrón decorador incluye los siguientes roles principales:

  • Componente abstracto (Component): define la interfaz común o la clase abstracta para los objetos originales y los objetos decoradores; puede ser la clase padre o la interfaz de las clases de componentes concretos.
  • Componente concreto (Concrete Component): es el objeto original que se decora y define el objeto que necesita nuevas funcionalidades.
  • Decorador abstracto (Decorator): hereda del componente abstracto, contiene un objeto del componente abstracto y define la misma interfaz que el componente abstracto; además, puede mantener otros objetos decoradores mediante composición.
  • Decorador concreto (Concrete Decorator): implementa la interfaz del decorador abstracto y se encarga de añadir nuevas funcionalidades al componente abstracto. Por lo general, el decorador concreto ejecuta sus propias operaciones antes o después de llamar al método del objeto original.

El patrón decorador, mediante la anidación y envoltura de múltiples objetos decoradores, puede lograr mejoras de funcionalidad en varios niveles. Cada clase de decorador concreto puede añadir opcionalmente nuevas funcionalidades manteniendo la coherencia de la interfaz del objeto.

public abstract class ShapeDecorator implements Shape { protected Shape decoratedShape; public ShapeDecorator(Shape decoratedShape){ this.decoratedShape = decoratedShape; } public void draw(){ decoratedShape.draw(); } }

    Implementación en Swift:

    protocol Shape {
    func draw()
}

protocol ShapeDecorator: Shape {
    var decoratedShape: Shape { get }
}

class Decorator {
    struct Rectangle: Shape {
        func draw() {
            print("Shape: Rectangle")
        }
    }

    struct Circle: Shape {
        func draw() {
            print("Shape: Circle")
        }
    }

    struct RedShapeDecorator: ShapeDecorator {
        var decoratedShape: Shape

        func draw() {
            decoratedShape.draw()
            setRedBorder(decoratedShape)
        }

        func setRedBorder(_ shape: Shape) {
            print("Border Color: Red")
        }

    }
    func execute() {
        let circle = Circle()
        let redCircle = RedShapeDecorator(decoratedShape: Circle())
        let redRectangle = RedShapeDecorator(decoratedShape: Rectangle())
        print("Circle with normal border:")
        circle.draw()
        print("Circle of red border")
        redCircle.draw()
        print("Circle of red rectangle")
        redRectangle.draw()
    }
}

    Método en Python:

    # Decorator Pattern with Python Code
from abc import  abstractmethod,ABCMeta

# 创建Shape接口
class Shape(metaclass=ABCMeta):
    @abstractmethod
    def draw(self):
        pass
# 实现Shape的实体类：Rectangle、Circle
class Rectangle(Shape):
    def draw(self):
        print("Shape: Rectangle")
class Circle(Shape):
    def draw(self):
        print("Shape: Circle")

class TextDecorator_blockword : public TextDecorator
{
private:
    string m_blockword; // 屏蔽词
public:
    TextDecorator_blockword(string bw) :m_blockword(bw) {};
    void setText(string s) {
        cout << "屏蔽词语，屏蔽词为 "<< m_blockword << endl;
        // 循环找到每个屏蔽词，并替换为*
        for (std::size_t found = s.find(m_blockword); 
            found != std::string::npos; 
            found = s.find(m_blockword)) {
            s.replace(found, m_blockword.size(), m_blockword.size(), '*'); // 屏蔽词替换成*号
        }
        TextDecorator::setText(s);
    };
};

    El patrón decorador permite agregar y eliminar dinámicamente la funcionalidad de los objetos en tiempo de ejecución, sin modificar su estructura. Evita el problema de la explosión de clases causado por la extensión con subclases, haciendo que el código sea más flexible y extensible. Al mismo tiempo, el patrón decorador también sigue el principio abierto-cerrado, lo que permite agregar fácilmente nuevas clases decoradoras sin modificar el código existente.

    A continuación se muestra un ejemplo sencillo del patrón decorador. Supongamos que hay una cafetería que puede agregar ingredientes adicionales al café según las necesidades del cliente:

    // 抽象组件 - 咖啡
interface Coffee {
    String getDescription();
    double getCost();
}

// 具体组件 - 普通咖啡
class PlainCoffee implements Coffee {
    public String getDescription() {
        return "Plain Coffee";
    }

    public double getCost() {
        return 2.0;
    }
}

// 抽象装饰器 - 咖啡装饰器
abstract class CoffeeDecorator implements Coffee {
    protected Coffee decoratedCoffee;

    public CoffeeDecorator(Coffee decoratedCoffee) {
        this.decoratedCoffee = decoratedCoffee;
    }

    public String getDescription() {
        return decoratedCoffee.getDescription();
    }

    public double getCost() {
        return decoratedCoffee.getCost();
    }
}

// 具体装饰器 - 牛奶装饰器
class MilkDecorator extends CoffeeDecorator {
    public MilkDecorator(Coffee decoratedCoffee) {
        super(decoratedCoffee);
    }

    public String getDescription() {
        return super.getDescription() + ", Milk";
    }

    public double getCost() {
        return super.getCost() + 0.5;
    }
}

// 具体装饰器 - 糖浆装饰器
class SyrupDecorator extends CoffeeDecorator {
    public SyrupDecorator(Coffee decoratedCoffee) {
        super(decoratedCoffee);
    }

    public String getDescription() {
        return super.getDescription() + ", Syrup";
    }

    public double getCost() {
        return super.getCost() + 0.8;
    }
}

// 客户端代码
public class Main {
    public static void main(String[] args) {
        Coffee coffee = new PlainCoffee();
        System.out.println(coffee.getDescription() + ", Cost: " + coffee.getCost());

        Coffee milkCoffee = new MilkDecorator(coffee);
        System.out.println(milkCoffee.getDescription() + ", Cost: " + milkCoffee.getCost());

        Coffee syrupCoffee = new SyrupDecorator(coffee);
        System.out.println(syrupCoffee.getDescription() + ", Cost: " + syrupCoffee.getCost());

        Coffee milkSyrupCoffee = new SyrupDecorator(milkCoffee);
        System.out.println(milkSyrupCoffee.getDescription() + ", Cost: " + milkSyrupCoffee.getCost());
    }
}

    En el ejemplo anterior, definimos la interfaz de componente abstracto Coffee y la clase de componente concreta PlainCoffee. Luego, definimos la clase decoradora abstracta CoffeeDecorator, así como las clases decoradoras concretas MilkDecorator y SyrupDecorator. Al anidar continuamente objetos decoradores, podemos agregar diferentes ingredientes al café.
