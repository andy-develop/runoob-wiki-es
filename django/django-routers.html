Rutas de Django

En términos simples, el enrutamiento consiste en determinar el controlador correspondiente según la URL solicitada por el usuario y devolver el resultado del procesamiento, es decir, establecer una relación de mapeo entre la URL y las vistas de Django.

El enrutamiento de Django se configura en urls.py; cada configuración en urls.py corresponde a un método de procesamiento.

La configuración de urls.py difiere ligeramente entre versiones de Django:

Versión Django 1.1.x

Método url(): Se puede usar tanto para rutas normales como para rutas de expresiones regulares; es necesario agregar manualmente los símbolos de anclaje de inicio y fin de la expresión regular.

Ejemplo

from django.conf.urls import url # Necesitas importar para usar url

urlpatterns = [
    url(r'^admin/$', admin.site.urls),
    url(r'^index/$', views.index), # Ruta normal
    url(r'^articles/([0-9]{4})/$', views.articles), # Ruta de expresión regular
]

Versiones posteriores a Django 2.2.x

  • path: se usa para rutas normales; no es necesario agregar manualmente los símbolos de anclaje de la expresión regular, ya que se agregan automáticamente en el nivel inferior.
  • re_path: se usa para rutas de expresiones regulares; es necesario agregar manualmente los símbolos de anclaje de la expresión regular.

Ejemplo

from django.urls import re_path # Necesitas importar para usar re_path
urlpatterns = [
    path('admin/', admin.site.urls),
    path('index/', views.index), # Ruta normal
    re_path(r'^articles/([0-9]{4})/$', views.articles), # Ruta de expresión regular
]

Resumen:El método url en Django 1.1.x tiene el mismo uso que re_path en Django 2.2.x.

Grupos en rutas de expresiones regulares

Grupos sin nombre en rutas de expresiones regulares

Los grupos sin nombre pasan parámetros por posición, en correspondencia uno a uno.

En views, aparte de request, el número de otros parámetros formales debe ser igual al número de grupos en urls.

urls.py

urlpatterns = [
    path('admin/', admin.site.urls),
    re_path("^index/([0-9]{4})/$", views.index),
]

views.py

from django.shortcuts import HttpResponse

def index(request, year):
    print(year) # Un parámetro formal representa el contenido de un grupo en la ruta, se empareja en orden
    return HttpResponse('Tutorial para novatos')

Grupos con nombre en rutas de expresiones regulares

Sintaxis:

(?P<组名>正则表达式)

Los grupos con nombre pasan parámetros por palabra clave, sin depender del orden de posición.

En views, aparte de request, el número de otros parámetros formales debe ser igual al número de grupos en urls, y los nombres de los parámetros formales en views deben corresponder a los nombres de los grupos en urls.

urls.py

urlpatterns = [
    path('admin/', admin.site.urls),
    re_path("^index/(?P[0-9]{4})/(?P[0-9]{2})/$", views.index),
]

views.py

from django.shortcuts import HttpResponse
def index(request, year, month):
    print(year,month) # Un parámetro formal representa el contenido de un grupo en la ruta, se empareja según la palabra clave
    return HttpResponse('Tutorial para novatos')

Grupos con nombre en rutas de expresiones regulares

Distribución de rutas (include)

Problema existente: En un proyecto Django, cuando múltiples directorios de apps comparten un solo urls, es fácil causar confusión y el mantenimiento posterior también es inconveniente.

Solución: Utilice la distribución de rutas (include) para que cada directorio de app tenga su propio urls.

Pasos:

  • 1. Cree un archivo urls.py en cada directorio de app.
  • 2. En el archivo urls del directorio del nombre del proyecto, distribuya uniformemente las rutas a cada directorio de app.

Ejemplo

from django.contrib import admin
from django.urls import path,include # Importe include desde django.urls
urlpatterns = [
    path('admin/', admin.site.urls),
    path("app01/", include("app01.urls")),
    path("app02/", include("app02.urls")),
]

En cada directorio de app, escriba su propio archivo urls.py para realizar la redirección de rutas.

Directorio app01:

from django.urls import path,re_path 
from app01 import views # 从自己的 app 目录引入 views 
urlpatterns = [ 
    re_path(r'^login/(?P<m>[0-9]{2})/$', views.index, ),
]

Directorio app02:

from django.urls import path,re_path
from app02 import views # 从自己的 app 目录引入views 
urlpatterns = [ 
    re_path("^xxx/(?P[0-9]{4})/$", views.xxx), 
]

Escriba las funciones de vista correspondientes en el archivo views.py de cada directorio de app.

Resolución inversa

A medida que aumentan las funcionalidades, si las URLs en la capa de enrutamiento cambian, es necesario modificar las URLs en la capa de vistas y la capa de plantillas, lo cual es muy problemático e inconveniente para el mantenimiento.

En este caso, podemos utilizar la resolución inversa: cuando las URLs en la capa de enrutamiento cambian, se resuelven dinámicamente las nuevas URLs en la capa de vistas y la capa de plantillas, evitando así modificaciones manuales.

La resolución inversa se usa generalmente en enlaces dentro de plantillas y en redirecciones dentro de las vistas.

Ruta normal

En urls.py, asigne un alias a la ruta,name="alias_de_la_ruta"。

path("login1/", views.login, name="login")

En views.py, importe reverse desde django.urls y utilicereverse("alias_de_la_ruta")Resolución inversa:

return redirect(reverse("login"))

En los archivos HTML de las plantillas (templates), utilice{% url "alias_de_la_ruta" %}para la resolución inversa.

<form action="{% url 'login' %}" method="post">

Ruta de expresión regular (grupos sin nombre)

En urls.py, asigne un alias a la ruta,name="alias_de_la_ruta"。

re_path(r"^login/([0-9]{2})/$", views.login, name="login")

En views.py, importe reverse desde django.urls y utilicereverse("alias_de_la_ruta", args=(parámetro_coincidente,))para la resolución inversa.

return redirect(reverse("login",args=(10,)))

En los archivos HTML de las plantillas (templates), utilice{% url "alias_de_la_ruta" parámetro_coincidente %}para la resolución inversa.

<form action="{% url 'login' 10 %}" method="post">

Ruta de expresión regular (grupos con nombre)

En urls.py, asigne un alias a la ruta,name="alias_de_la_ruta"。

re_path(r"^login/(?P<year>[0-9]{4})/$", views.login, name="login")

En views.py, importe reverse desde django.urls y utilicereverse("alias_de_la_ruta", kwargs={"nombre_del_grupo": parámetro_coincidente})para la resolución inversa.

return redirect(reverse("login",kwargs={"year":3333}))

En los archivos HTML de las plantillas (templates), utilice{% url "alias_de_la_ruta" nombre_del_grupo=parámetro_coincidente %}para la resolución inversa.

<form action="{% url 'login' year=3333 %}" method="post">

Espacio de nombres

Un espacio de nombres (en inglés: Namespace) es el ámbito de visibilidad de los identificadores.

Un identificador puede definirse en varios espacios de nombres; sus significados en diferentes espacios de nombres son independientes entre sí.

En un nuevo espacio de nombres se puede definir cualquier identificador; no entrarán en conflicto con identificadores repetidos, ya que las definiciones repetidas se encuentran en otros espacios de nombres.

Problema existente:El alias de ruta name no tiene ámbito; cuando Django realiza la resolución inversa de URLs, busca secuencialmente en todo el proyecto y, al encontrar la primera URL especificada por el alias de ruta name, la devuelve de inmediato. Cuando se define el mismo alias de ruta name en urls de diferentes directorios de app, puede provocar errores en la resolución inversa de URLs.

Solución:Utilice espacios de nombres.

Ruta normal

Para definir un espacio de nombres (dentro de include hay una tupla), el formato es el siguiente:
include(("app名称：urls"，"app名称"))

Ejemplo:

path("app01/", include(("app01.urls","app01"))) 
path("app02/", include(("app02.urls","app02")))

Defina los mismos alias de ruta en app01/urls.py.

path("login/", views.login, name="login")

Para utilizar el espacio de nombres en views.py, el formato es el siguiente:

reverse("app名称：路由别名")

Ejemplo:

return redirect(reverse("app01:login")

Para utilizar el espacio de nombres en los archivos HTML de las plantillas (templates), el formato es el siguiente:

{% url "app名称：路由别名" %}

Ejemplo:

<form action="{% url 'app01:login' %}" method="post">
