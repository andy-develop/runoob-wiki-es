Tutorial de HTML-(Estándar HTML5)

El lenguaje de marcado de hipertexto (en inglés: HyperText Markup Language, abreviado: HTML) es un lenguaje de marcado estándar utilizado para crear páginas web.

Puede utilizar HTML para crear su propio sitio WEB. HTML se ejecuta en el navegador y es analizado por el navegador.

En este tutorial, aprenderá cómo usar HTML para crear sitios web.

¡HTML es muy fácil de aprender! ¡Estamos seguros de que podrá dominarlo rápidamente!

Ejemplos de HTML

Este tutorial contiene cientos de ejemplos de HTML.

Usando el editor de este sitio, puede modificar HTML en línea fácilmente y ver los resultados de ejecución de los ejemplos.

Nota:Para páginas web en chino se debe utilizar<meta charset="utf-8">declarar la codificación, de lo contrario aparecerán caracteres ilegibles. Algunos navegadores (como el navegador 360) establecen GBK como codificación predeterminada, entonces debe configurarlo como<meta charset="gbk">。

Ejemplos

<!DOCTYPE html> <html> <head> <meta charset="utf-8"> <title>Tutorial de Novato (runoob.com)</title> </head> <body> <h1>Mi primer título</h1> <p>Mi primer párrafo.</p> </body> </html>

    "UTF-8" es la forma estándar. En Windows, PHP no distingue entre mayúsculas y minúsculas en inglés, por lo que también se puede escribir como "utf-8". En "UTF-8" también se puede omitir el "-" del medio y escribir "UTF8". Generalmente los programas lo reconocen, pero hay excepciones (como se muestra a continuación). Para ser más estrictos, es mejor usar la forma estándar en mayúsculas "UTF-8".

    En la base de datos solo se puede usar "utf8" (MySQL). En el modo de comandos de MySQL solo se puede usar "utf8", no "utf-8". Es decir, en un programa PHP solo se puede usar "set names utf8 (sin el guion)". Si agrega el "-", este comando no tendrá efecto. Sin embargo, en el header de PHP se debe agregar el "-", porque IE no reconoce "utf8" sin guion; la razón se explica a continuación.

    La diferencia entre htm y html

    El primero es Marcado de Hipertexto (Hypertext Markup)

    El segundo es Lenguaje de Marcado de Hipertexto (Hypertext Markup Language)

    Se puede decir que htm = html

    Al mismo tiempo, ambas son extensiones de archivos de páginas web estáticas. Las extensiones se pueden intercambiar entre sí sin causar errores (esto se refiere a la apertura del archivo, pero para un enlace, si apunta a un archivo htm y ese archivo htm se cambia a un archivo html, el enlace no se encontrará).

    Entonces, ¿por qué existen dos formatos de archivo?

    htm proviene del antiguo formato de archivo 8.3. El sistema operativo DOS solo podía admitir extensiones de tres caracteres, por lo que se usaba htm. Pero en Windows no hay diferencia entre HTM y HTML; html se nombró para el formato de nombres de archivo largos. Por lo tanto, htm existe para ser compatible con el formato de nombres de DOS del pasado, y no hay diferencia en la práctica. Antes, htm y html se usaban como archivos de hipertexto en diferentes servidores, pero ahora son intercambiables.

    ¿Qué es el formato de archivo 8.3? Es un formato de archivo de nombre corto en los antiguos sistemas de archivos de 16 bits Win95 o Win98. La extensión está limitada a 3 caracteres y el nombre de archivo a 8 caracteres. Si necesita interactuar con un sistema de 16 bits, por ejemplo, pasar una ruta a un programa de 16 bits, no puede usar nombres de archivo largos y debe convertirlos. Por ejemplo, convertir "C ： /MyLongestPath/MyLongerPath/MyFilename.txt" a "C ： /Mylong~1/MyLong~2/Myfile~1.txt".

    ¿De qué sirve saber esto? En DOS con formato de disco FAT solo se admite el formato de archivo 8.3. Si va a desarrollar aplicaciones en este entorno, debe prestar atención a este problema de formato de archivo. En NTFS, este formato de archivo es compatible de forma predeterminada y también se admiten nombres de archivo largos. También puede cancelar la compatibilidad con el formato 8.3 ajustando el registro.

    Elección de extensión: ¿usar htm o html?

    Se recomienda usar la extensión largahtml 。

    La nomenclatura debe seguir los principios de claridad semántica, concisión y consistencia. Claridad semántica significa que el nombre revele su significado, como aquí htm (hypertext markup) y html (hypertext markup language), ambos usan abreviaturas de las palabras en inglés, lo cual es claro. La concisión requiere que los nombres de variables sean lo más cortos posible, por ejemplo, la extensión usa abreviaturas en lugar de palabras completas. El principio de consistencia requiere que una gran cantidad de nombres de variables en el mismo entorno sigan las mismas reglas. Por ejemplo, algunas personas acostumbradas a las reglas de nomenclatura de carpetas de Linux se niegan a usar espacios al nombrar carpetas en Windows, lo que hace que los nombres de las carpetas nuevas no sean consistentes con las reglas de las carpetas antiguas.

    El principio de consistencia suele ser más importante. Por ejemplo, en el desarrollo colaborativo, no se puede hacer cada uno lo que quiera, aumentando artificialmente la dificultad del desarrollo.

    De las notas de 一路风尘, aprendemos que htm es una convención de nomenclatura heredada por la limitación de 8.3 caracteres, y que actualmente no seguimos la regla 8.3 al nombrar. Por lo tanto, al elegir entre htm y html, se debe elegir html, que permite nombres sin límite de longitud.

    Siempre me pregunté por qué, cada vez que programo, hay esta frase<!DOCTYPE html>¡Ahora por fin entiendo qué significa!

    Es la declaración de página web estándar de HTML5, cuyo nombre completo es Document Type HyperText Mark-up Language, una declaración de tipo de documento. Todos los navegadores principales que admiten el estándar HTML5 reconocen esta declaración. Indica que la página web utiliza HTML5.<!DOCTYPE html>La declaración se encuentra en la posición más adelantada del documento, antes de la etiqueta <html>. Esta etiqueta informa al navegador qué especificación de HTML o XHTML utiliza el documento.
