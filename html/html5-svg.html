HTML5 SVG

SVG se define como gráficos vectoriales escalables.

HTML5 admite SVG en línea.

HTML <svg>El elemento es el contenedor de los gráficos SVG.

SVG tiene varios métodos para dibujar trazados, cajas, círculos, texto e imágenes gráficas.

¿Qué es SVG?

  • SVG significa Gráficos Vectoriales Escalables (Scalable Vector Graphics)
  • SVG se utiliza para definir gráficos basados en vectores para la web
  • SVG define los gráficos utilizando el formato XML
  • Las imágenes SVG no pierden calidad gráfica al ampliarse o cambiar su tamaño
  • SVG es un estándar del World Wide Web Consortium (W3C)

Ventajas de SVG

En comparación con otros formatos de imagen (como JPEG y GIF), las ventajas de usar SVG son:

  • Las imágenes SVG se pueden crear y modificar con editores de texto
  • Las imágenes SVG se pueden buscar, indexar, escribir mediante scripts o comprimir
  • SVG es escalable
  • Las imágenes SVG se pueden imprimir con alta calidad a cualquier resolución
  • SVG se puede ampliar sin que la calidad de la imagen disminuya

Diferencias entre SVG y Canvas

SVG es un lenguaje que utiliza XML para describir gráficos 2D.

Canvas dibuja gráficos 2D mediante JavaScript.

SVG se basa en XML, lo que significa que cada elemento en el DOM de SVG está disponible. Puedes adjuntar manejadores de eventos de JavaScript a un elemento.

En SVG, cada gráfico dibujado se considera un objeto. Si las propiedades de un objeto SVG cambian, el navegador puede redibujar automáticamente el gráfico.

Canvas se renderiza píxel por píxel. En canvas, una vez que se dibuja un gráfico, el navegador deja de prestarle atención. Si su posición cambia, toda la escena también debe redibujarse, incluidos los objetos que quizás ya hayan sido cubiertos por el gráfico.

Comparación entre Canvas y SVG

La siguiente tabla enumera algunas diferencias entre canvas y SVG.

Canvas SVG
  • Depende de la resolución
  • No admite manejadores de eventos
  • Capacidad de renderizado de texto débil
  • Puede guardar la imagen resultante en formato .png o .jpg
  • Más adecuado para juegos con gran densidad de imágenes, donde muchos objetos se redibujan con frecuencia
  • No depende de la resolución
  • Admite manejadores de eventos
  • Más adecuado para aplicaciones con grandes áreas de renderizado (como Google Maps)
  • La alta complejidad ralentiza la velocidad de renderizado (cualquier aplicación que haga uso excesivo del DOM no es rápida)
  • No es adecuado para aplicaciones de juegos
