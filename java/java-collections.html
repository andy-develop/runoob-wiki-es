Marco de colecciones de Java

Mucho antes de Java 2, Java ya proporcionaba clases especiales (ad hoc). Por ejemplo: Dictionary, Vector, Stack y Properties. Estas clases se usaban para almacenar y manipular grupos de objetos.

Aunque estas clases eran muy útiles, carecían de un tema central y unificado. Por esta razón, la forma de usar la clase Vector era muy diferente de la forma de usar la clase Properties.

El marco de colecciones fue diseñado para cumplir los siguientes objetivos.

  • El marco debe ser de alto rendimiento. Las implementaciones de las colecciones básicas (arrays dinámicos, listas enlazadas, árboles, tablas hash) también deben ser eficientes.

  • El marco permite que diferentes tipos de colecciones funcionen de manera similar, con un alto grado de interoperabilidad.

  • La extensión y adaptación de una colección debe ser sencilla.

Para ello, todo el marco de colecciones se diseñó en torno a un conjunto de interfaces estándar. Puedes usar directamente las implementaciones estándar de estas interfaces, como por ejemplo:LinkedList, HashSet, yTreeSetetc. Además, también puedes implementar tus propias colecciones a través de estas interfaces.

Como se puede ver en el diagrama del marco de colecciones anterior, el marco de colecciones de Java incluye principalmente dos tipos de contenedores: uno es Collection, que almacena un conjunto de elementos, y el otro es Map, que almacena asignaciones de clave/valor. La interfaz Collection tiene a su vez 3 subtipos: List, Set y Queue. Después hay algunas clases abstractas y, finalmente, las clases de implementación concretas. Las de uso común sonArrayList、LinkedList、HashSet、LinkedHashSet、HashMap, LinkedHashMap, etc.

El marco de colecciones es una arquitectura unificada para representar y manipular colecciones. Todos los marcos de colecciones incluyen lo siguiente:

  • Interfaces:

    Son tipos de datos abstractos que representan colecciones. Por ejemplo: Collection, List, Set, Map, etc. La razón por la que se definen múltiples interfaces es para poder operar con los objetos de colección de diferentes maneras.

  • Implementaciones (clases):Son implementaciones concretas de las interfaces de colección. En esencia, son estructuras de datos reutilizables, por ejemplo: ArrayList, LinkedList, HashSet, HashMap.

  • Algoritmos:Son cálculos útiles ejecutados por métodos en objetos que implementan interfaces de colección, por ejemplo: búsqueda y ordenación. Estos algoritmos implementan polimorfismo, porque el mismo método puede tener diferentes implementaciones en interfaces similares.

Además de las colecciones, el marco también define varias interfaces y clases Map. Map almacena pares clave/valor. Aunque Map no es una colección, están totalmente integrados en las colecciones.

Interfaces de colección

El marco de colecciones define algunas interfaces. Esta sección ofrece una descripción general de cada interfaz:

N.º Descripción de la interfaz
1 Interfaz Collection

Collection es la interfaz de colección más básica. Una Collection representa un grupo de objetos, es decir, los elementos de la Collection. Java no proporciona clases que hereden directamente de Collection, solo proporciona subinterfaces que heredan de ella (como List y Set).

La interfaz Collection almacena un grupo de objetos no únicos y desordenados.
2 Interfaz List

La interfaz List es una Collection ordenada. Con esta interfaz se puede controlar con precisión la posición de inserción de cada elemento. Se puede acceder a los elementos de la List mediante un índice (la posición del elemento en la List, similar al subíndice de un array). El índice del primer elemento es 0 y se permiten elementos duplicados.

La interfaz List almacena un grupo de objetos no únicos y ordenados (orden de inserción).
3 Set

Set tiene exactamente la misma interfaz que Collection, solo que su comportamiento es diferente: Set no almacena elementos duplicados.

La interfaz Set almacena un grupo de objetos únicos y desordenados.
4 SortedSet
Hereda de Set y almacena colecciones ordenadas.
5 Map

La interfaz Map almacena un grupo de objetos de pares clave-valor y proporciona la asignación de clave (key) a valor (value).
6 Map.Entry
Describe un elemento (par clave/valor) en un Map. Es una interfaz interna de Map.
7 SortedMap
Hereda de Map y mantiene las claves en orden ascendente.
8 Enumeration
Esta es una interfaz tradicional y define métodos mediante los cuales se pueden enumerar (obtener uno a la vez) los elementos de una colección de objetos. Esta interfaz tradicional ha sido reemplazada por los iteradores.

Diferencias entre Set y List

  • 1. Las instancias de la interfaz Set almacenan datos desordenados y no duplicados. Las instancias de la interfaz List almacenan elementos ordenados y duplicables.

  • 2. En Set, la eficiencia de búsqueda es baja, pero la de eliminación e inserción es alta; la inserción y eliminación no provocan cambios en la posición de los elementos.<Las clases de implementación incluyen HashSet, TreeSet>。

  • 3. List es similar a un array; puede crecer dinámicamente y su longitud aumenta automáticamente según la longitud de los datos realmente almacenados. La eficiencia de búsqueda de elementos es alta, pero la de inserción y eliminación es baja, porque provoca cambios en la posición de otros elementos.<Las clases de implementación incluyen ArrayList, LinkedList, Vector> 。

Clases de implementación de colecciones (clases de colección)

Java proporciona un conjunto de clases de colección estándar que implementan la interfaz Collection. Algunas de ellas son clases concretas que se pueden usar directamente, mientras que otras son clases abstractas que proporcionan implementaciones parciales de la interfaz.

Las clases de colección estándar se resumen en la siguiente tabla:

N.º Descripción de la clase
1 AbstractCollection 
Implementa la mayoría de las interfaces de colección.
2 AbstractList 
Hereda de AbstractCollection e implementa la mayor parte de la interfaz List.
3 AbstractSequentialList 
Hereda de AbstractList y proporciona acceso en cadena (enlazado) a los elementos de datos en lugar de acceso aleatorio.
4 LinkedList

Esta clase implementa la interfaz List y permite elementos null (nulos). Se utiliza principalmente para crear estructuras de datos de listas enlazadas. Esta clase no tiene métodos sincronizados. Si varios subprocesos acceden a una List simultáneamente, debes implementar la sincronización de acceso por tu cuenta. La solución es construir una List sincronizada al crear la List. Por ejemplo:

List list=Collections.synchronizedList(newLinkedList(...));

LinkedList tiene baja eficiencia de búsqueda.
5 ArrayList

Esta clase también implementa la interfaz List, implementa arrays de tamaño variable y ofrece mejor rendimiento en el acceso aleatorio y la iteración de elementos. Esta clase tampoco está sincronizada; no la uses en entornos de subprocesos múltiples. ArrayList aumenta su longitud actual en un 50% y la inserción y eliminación tienen baja eficiencia.
6 AbstractSet 
Hereda de AbstractCollection e implementa la mayor parte de la interfaz Set.
7 HashSet

Esta clase implementa la interfaz Set, no permite elementos duplicados, no garantiza el orden de los elementos del conjunto y permite elementos con valor null, pero como máximo uno.
8 LinkedHashSet
Con un orden de iteración predecible,Setimplementación de tabla hash y lista enlazada de la interfaz.
9 TreeSet

Esta clase implementa la interfaz Set y puede realizar funciones como la ordenación.
10 AbstractMap 
Implementa la mayor parte de la interfaz Map.
11 HashMap
HashMap es una tabla hash; su contenido almacena asignaciones de pares clave-valor.
Esta clase implementa la interfaz Map, almacena datos según el valor HashCode de la clave, tiene una velocidad de acceso muy rápida, permite como máximo que la clave de un registro sea null y no admite sincronización de subprocesos.
12 TreeMap
Hereda de AbstractMap y utiliza un árbol.
13 WeakHashMap
Hereda de la clase AbstractMap y usa una tabla hash con claves débiles.
14 LinkedHashMap
Hereda de HashMap y ordena los elementos según su orden natural.
15 IdentityHashMap
Hereda de la clase AbstractMap y utiliza la igualdad por referencia al comparar claves y valores.

En el tutorial anterior ya se han discutido las clases definidas en el paquete java.util, como se muestra a continuación:

N.º Descripción de la clase
1 Vector

Esta clase es muy similar a ArrayList, pero está sincronizada y puede usarse en entornos de subprocesos múltiples. Esta clase permite establecer la longitud de crecimiento predeterminada; la forma de expansión predeterminada es el doble de la original.
2 Stack
Stack es una subclase de Vector e implementa una pila estándar de último en entrar, primero en salir (LIFO).
3 Dictionary
La clase Dictionary es una clase abstracta que se utiliza para almacenar pares clave/valor; su función es similar a la clase Map.
4 Hashtable

Hashtable es una subclase de la clase Dictionary (diccionario) y se encuentra en el paquete java.util.
5 Properties
Properties hereda de Hashtable y representa un conjunto de propiedades persistente. En la lista de propiedades, cada clave y su valor correspondiente son una cadena.
6 BitSet
La clase BitSet crea un tipo especial de array para almacenar valores de bits. El tamaño del array en BitSet aumenta según sea necesario.

Cómo usar iteradores

Normalmente, querrás recorrer los elementos de una colección. Por ejemplo, mostrar cada elemento de la colección.

Generalmente, para recorrer arrays se usan el bucle for o el for mejorado; estos dos métodos también se pueden usar en el framework de colecciones, pero hay otro método que consiste en usar un iterador para recorrer el framework de colecciones. Es un objeto que implementaIteratorla interfaz Iterator o la interfaz ListIterator.

Los iteradores te permiten obtener o eliminar elementos de una colección mediante bucles. ListIterator hereda de Iterator para permitir el recorrido bidireccional de listas y la modificación de elementos.

Ejemplo

import java.util.*; public class Test{ public static void main(String[] args) { List<String> list=new ArrayList<String>(); list.add("Hello"); list.add("World"); list.add("HAHAHAHA"); //El primer método de recorrido usa For-Each para recorrer la List. for (String str : list) { //También se puede reescribir en la forma for(int i=0;i<list.size();i++) System.out.println(str); } //El segundo método de recorrido convierte la lista en un array para recorrer su contenido. Iterator<String> ite=list.iterator(); while(ite.hasNext())//Comprueba si hay un valor después del siguiente elemento. { System.out.println(ite.next()); } } }

Análisis:

Los tres métodos se usan para recorrer la colección ArrayList; el tercer método utiliza un iterador, y con este método no hay que preocuparse por exceder la longitud de la colección durante el recorrido.

Ejemplo

import java.util.*; public class Test{ public static void main(String[] args) { Map<String, String> map = new HashMap<String, String>(); map.put("1", "value1"); map.put("2", "value2"); map.put("3", "value3"); //Primero: uso común, obtener el valor dos veces. System.out.println("Recorrer key y value mediante Map.keySet:"); for (String key : map.keySet()) { System.out.println("key= "+ key + " and value= " + map.get(key)); } //Segundo System.out.println("Recorrer key y value usando iterator mediante Map.entrySet:"); Iterator<Map.Entry<String, String>> it = map.entrySet().iterator(); while (it.hasNext()) { Map.Entry<String, String> entry = it.next(); System.out.println("key= " + entry.getKey() + " and value= " + entry.getValue()); } //Tercero: recomendado, especialmente cuando la capacidad es grande. Resumen

El framework de colecciones de Java proporciona a los programadores estructuras de datos y algoritmos preempaquetados para manipularlos.

Una colección es un objeto que puede contener referencias a otros objetos. La interfaz Collection declara las operaciones que se pueden realizar sobre cada tipo de colección.

Las clases e interfaces del framework de colecciones están en el paquete java.util.

Cualquier objeto que se añade a una clase de colección se convierte automáticamente al tipo Object, por lo que al extraerlo es necesario realizar una conversión de tipos forzada.

    Acerca demap.entrySet() 和 keySet():

    1. Al recorrer hashMap(), el método entrySet() obtiene todos los key y value, por lo que la sobrecarga de rendimiento es predecible. En cambio, al recorrer con keySet(), se consulta el value correspondiente según el key obtenido; así, si los key son estructuras relativamente simples (como 1,2,3...), el consumo de rendimiento es menor que con entrySet(), pero a medida que aumenta la complejidad de los key, la ventaja de entrySet() se hace evidente.

    2. En comparación general, es una elección razonable usar keySet() al recorrer solo los key, usar values() al recorrer solo los value, y usar entrySet() al recorrer key-value.

    3. Al recorrer TreeMap, a diferencia de HashMap, al recorrer los key-value de TreeMap es imprescindible usar entrySet(), que tiene un rendimiento mucho mayor que los otros dos; de igual manera, usar keySet() al recorrer solo los key y usar values() al recorrer solo los value también se aplica a TreeMap.

    Las colecciones también tienen mecanismos de fail-fast (fallo rápido) y fail-safe (fallo seguro). Si quieres profundizar, debes informarte al respecto (Fail-fast y fail-safe en Java). Aquí he organizado las soluciones:

    1. Durante el recorrido en un solo hilo, si se necesita realizar una operación remove, se puede llamar al método remove del iterador en lugar del método remove de la clase de colección.

    2. Usa las clases del paquete de concurrencia de Java (java.util.concurrent) en lugar de ArrayList y HashMap. Por ejemplo, usa CopyOnWriterArrayList en lugar de ArrayList. CopyOnWriterArrayList es casi igual que ArrayList en su uso. CopyOnWriter es un contenedor de copia en escritura (COW), que es seguro para subprocesos durante la lectura y escritura. Este contenedor, en operaciones como add y remove, no modifica sobre el array original, sino que copia el array original, modifica sobre el nuevo array y, una vez completado, reemplaza la referencia que apuntaba al array antiguo por la referencia al nuevo array. Por lo tanto, CopyOnWriterArrayList no produce el fenómeno fail-fast durante la iteración. Sin embargo, el contenedor CopyOnWrite solo puede garantizar la consistencia final de los datos, no la consistencia en tiempo real. Para HashMap, se puede usar ConcurrentHashMap, que emplea un mecanismo de bloqueo y es seguro para subprocesos. En cuanto a la iteración, ConcurrentHashMap utiliza un enfoque de iteración diferente. En este enfoque, cuando el iterador se ha creado y la colección cambia, ya no se lanza ConcurrentModificationException; en su lugar, se crean nuevos datos al cambiar para no afectar los datos originales. Cuando el iterador termina, el puntero de cabecera se reemplaza por los nuevos datos. De este modo, el hilo que itera puede usar los datos antiguos originales, mientras que el hilo de escritura puede completar los cambios de manera concurrente. Es decir, la iteración no produce fail-fast, pero no se garantiza obtener los datos más recientes.

    Aquí se corrige la diferencia entre List y Set: la eficiencia de búsqueda de Set es mayor que la de List.

    De Set,la eficiencia de búsquedaen comparación con List, es más alta,la razón es que Set se basa en estructuras de datos como tablas hash o árboles para almacenar elementos. Al buscar un elemento, Set primero calcula el valor hash del elemento o utiliza un comparador para comparar, y luego busca el elemento en la estructura de datos según el valor hash o el resultado de la comparación. La complejidad temporal de este método es O(1) o O(logN), por lo tanto, la eficiencia de búsqueda de Set es relativamente alta.

    La eficiencia de búsqueda de List es relativamente baja en comparación con la de Set. La razón es que List se basa en estructuras de datos como arreglos o listas enlazadas para almacenar elementos. Al buscar un elemento, List necesita recorrer los elementos uno por uno hasta encontrar el elemento objetivo o hasta recorrer todos los elementos. La complejidad temporal de este método es O(N), por lo que la eficiencia de búsqueda de List es relativamente baja.

    Lo que se suele confundir es el acceso aleatorio a elementos y la búsqueda de elementos; estos dos no son lo mismo.

    Acceso aleatorio a elementosSe refiere a que se puede acceder a los elementos de una colección mediante un índice o un desplazamiento, por ejemplo usando el método get(int index) de ArrayList. La eficiencia del acceso aleatorio a elementos suele ser muy alta, porque puede acceder directamente a los elementos de la estructura de datos interna, con una complejidad temporal de O(1).

    Búsqueda de elementosSe refiere al proceso de encontrar un elemento específico en una colección, por ejemplo usando el método contains(Object o) de Set. La eficiencia de la búsqueda depende de la implementación de la colección y de la cantidad de elementos; normalmente es necesario recorrer todos los elementos de la colección para encontrar el elemento objetivo, con una complejidad temporal de O(N).

    Un punto adicional: para datos a gran escala, Set ocupa más memoria, mientras que ArrayList tiene mejor rendimiento.
