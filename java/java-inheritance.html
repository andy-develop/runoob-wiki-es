Herencia en Java

Concepto de herencia

La herencia es una piedra angular de la tecnología de programación orientada a objetos de Java, porque permite crear clases jerárquicas por niveles.

La herencia consiste en que la subclase hereda las características y comportamientos de la clase padre, de modo que los objetos (instancias) de la subclase tienen los campos de instancia y métodos de la clase padre, o la subclase hereda métodos de la clase padre, haciendo que la subclase tenga los mismos comportamientos que la clase padre.

Herencia en la vida cotidiana:

Los conejos y las ovejas pertenecen a la clase de los herbívoros; los leones y los leopardos pertenecen a la clase de los carnívoros.

Los herbívoros y los carnívoros, a su vez, pertenecen a la clase de los animales.

Por lo tanto, la relación que debe cumplir la herencia es: is-a (es-un), la clase padre es más general y la subclase es más específica.

Aunque los herbívoros y los carnívoros pertenecen a los animales, sus atributos y comportamientos difieren, por lo que la subclase poseerá las características generales de la clase padre y también sus propias características.

Formato de herencia de clases

En Java, mediante la palabra clave extends se puede declarar que una clase hereda de otra clase; la forma general es la siguiente:

Formato de herencia de clases

classClase padre{ } classSubclaseextendsClase padre{ }

Por qué se necesita la herencia

A continuación, explicaremos esta necesidad mediante un ejemplo.

Desarrolle una clase de animales, donde los animales son el pingüino y el ratón, con los siguientes requisitos:

  • Pingüino: atributos (nombre, id), métodos (comer, dormir, presentarse)
  • Ratón: atributos (nombre, id), métodos (comer, dormir, presentarse)

Clase Pingüino:

public class Penguin { private String name; private int id; public Penguin(String myName, int myid) { name = myName; id = myid; } public void eat(){ System.out.println(name+"Comiendo"); } public void sleep(){ System.out.println(name+"Durmiendo"); } public void introduction() { System.out.println("¡Hola a todos! Soy" + id + "号" + name + "."); } }

Clase Ratón:

public class Mouse { private String name; private int id; public Mouse(String myName, int myid) { name = myName; id = myid; } public void eat(){ System.out.println(name+"Comiendo"); } public void sleep(){ System.out.println(name+"Durmiendo"); } public void introduction() { System.out.println("¡Hola a todos! Soy" + id + "号" + name + "."); } }

Como se puede observar en estos dos fragmentos de código, hay código repetido, lo que hace que el código sea extenso y redundante, y además sea difícil de mantener (principalmente porque cuando se necesita modificar más adelante, hay que cambiar mucho código y es fácil cometer errores). Para resolver fundamentalmente el problema de estos dos fragmentos de código, se necesita la herencia, extrayendo las partes comunes de ambos fragmentos para formar una clase padre:

Clase padre común:

public class Animal { private String name; private int id; public Animal(String myName, int myid) { name = myName; id = myid; } public void eat(){ System.out.println(name+"Comiendo"); } public void sleep(){ System.out.println(name+"Durmiendo"); } public void introduction() { System.out.println("¡Hola a todos! Soy" + id + "号" + name + "."); } }

Esta clase Animal puede servir como clase padre. Después de que las clases Pingüino y Ratón hereden de ella, tendrán los atributos y métodos de la clase padre, la subclase ya no tendrá código repetido, el mantenimiento mejorará, el código será más conciso y se aumentará la reutilización del código (la reutilización significa principalmente que se puede usar varias veces sin tener que escribir el mismo código repetidamente). Código después de la herencia:

Clase Pingüino:

public class Penguin extends Animal { public Penguin(String myName, int myid) { super(myName, myid); } }

Clase Ratón:

public class Mouse extends Animal { public Mouse(String myName, int myid) { super(myName, myid); } }

Tipos de herencia

Cabe señalar que Java no admite la herencia múltiple, pero sí admite la herencia multinivel.

Características de la herencia

  • La subclase posee los atributos y métodos no privados de la clase padre.

  • La subclase puede tener sus propios atributos y métodos, es decir, la subclase puede extender la clase padre.

  • La subclase puede implementar los métodos de la clase padre a su manera.

  • La herencia en Java es herencia única, pero puede ser multinivel. La herencia única significa que una subclase solo puede heredar de una clase padre. La herencia multinivel significa, por ejemplo, que la clase B hereda de la clase A y la clase C hereda de la clase B, por lo que en la relación, la clase B es la clase padre de la clase C, y la clase A es la clase padre de la clase B. Esta es una característica que distingue la herencia de Java de la herencia de C++.

  • Aumenta el acoplamiento entre clases (una desventaja de la herencia: un acoplamiento alto hace que la conexión entre el código sea más estrecha y la independencia del código sea menor).

Palabras clave de la herencia

La herencia se puede implementar con las palabras clave extends e implements, y todas las clases heredan de java.lang.Object. Cuando una clase no utiliza ninguna de estas dos palabras clave para heredar, hereda Object por defecto (esta clase está enjava.langel paquete, por lo que no es necesarioimportla clase ancestro.

La palabra clave extends

En Java, la herencia de clases es única, es decir, una subclase solo puede tener una clase padre, por lo que extends solo puede heredar de una clase.

La palabra clave extends

public class Animal { private String name; private int id; public Animal(String myName, int myid) { //Inicializar el valor de los atributos } public void eat() { //Implementación concreta del método comer } public void sleep() { //Implementación concreta del método dormir } } public class Penguin extends Animal{ }

La palabra clave implements

El uso de la palabra clave implements puede hacer que Java tenga herencia múltiple de manera indirecta. Su ámbito de uso es cuando una clase hereda interfaces; puede heredar varias interfaces simultáneamente (las interfaces se separan con comas).

La palabra clave implements

public interface A { public void eat(); public void sleep(); } public interface B { public void show(); } public class C implements A,B { }

Las palabras clave super y this

Palabra clave super:Podemos acceder a los miembros de la clase padre mediante la palabra clave super, que se utiliza para hacer referencia a la clase padre del objeto actual.

Palabra clave this:Es una referencia que apunta a sí mismo, hace referencia al objeto actual, es decir, a la instancia del objeto al que pertenecen el método o constructor en el que se encuentra.

Ejemplo

class Animal { void eat() { System.out.println("animal : eat"); } } class Dog extends Animal { void eat() { System.out.println("dog : eat"); } void eatTest() { this.eat(); //this llama a su propio método super.eat(); //super llama al método de la clase padre } } public class Test { public static void main(String[] args) { Animal a = new Animal(); a.eat(); Dog d = new Dog(); d.eatTest(); } }

El resultado de salida es:

animal : eat
dog : eat
animal : eat

La palabra clave final

final se puede utilizar para modificar variables (incluidos atributos de clase, atributos de objeto, variables locales y parámetros formales), métodos (incluidos métodos de clase y métodos de objeto) y clases.

El significado de final es 'definitivo'.

Declarar una clase con la palabra clave final define la clase como una clase final que no puede ser heredada, o se usa para modificar un método, y ese método no puede ser reescrito por subclases:

  • Declarar clase:

    final class 类名 {//类体}

  • Declarar método:

    修饰符(public/private/default/protected) final 返回值类型 方法名(){//方法体}

Nota:En una clase definida como final, sus atributos y métodos no son final.

Constructor

La subclase no hereda el constructor de la clase padre (método constructor o función constructora), solo lo invoca (implícita o explícitamente). Si el constructor de la clase padre tiene parámetros, entonces se debe invocar explícitamente en el constructor de la subclase mediantesuperla palabra clave para invocar al constructor de la clase padre, junto con la lista de parámetros adecuada.

Si el constructor de la clase padre no tiene parámetros, entonces no es necesario usar en el constructor de la subclasesuperla palabra clave para invocar al constructor de la clase padre; el sistema invocará automáticamente el constructor sin parámetros de la clase padre.

Ejemplo

class SuperClass { private int n; //Constructor sin parámetros public SuperClass() { System.out.println("SuperClass()"); } //Constructor con parámetros public SuperClass(int n) { System.out.println("SuperClass(int n)"); this.n = n; } } //La clase SubClass hereda class SubClass extends SuperClass { private int n; //Constructor sin parámetros: llama automáticamente al constructor sin parámetros de la clase padre public SubClass() { System.out.println("SubClass()"); } //Constructor con parámetros: llama al constructor con parámetros de la clase padre public SubClass(int n) { super(300); System.out.println("SubClass(int n): " + n); this.n = n; } } //La clase SubClass2 hereda class SubClass2 extends SuperClass { private int n; //Constructor sin parámetros: llama al constructor con parámetros de la clase padre public SubClass2() { super(300); System.out.println("SubClass2()"); } //Constructor con parámetros: llama automáticamente al constructor sin parámetros de la clase padre public SubClass2(int n) { System.out.println("SubClass2(int n): " + n); this.n = n; } } public class TestSuperSub { public static void main(String[] args) { System.out.println("------Herencia de la clase SubClass------"); SubClass sc1 = new SubClass(); SubClass sc2 = new SubClass(100); System.out.println("------Herencia de la clase SubClass2------"); SubClass2 sc3 = new SubClass2(); SubClass2 sc4 = new SubClass2(200); } }

El resultado de salida es:

SuperClass()
SubClass()
SuperClass(int n)
SubClass(int n): 100
------SubClass2 类继承------

SubClass2()
SuperClass()

    Programación orientada a objetos: herencia y polimorfismo

    //---Citando los apuntes de mi profesor de clase (Profesor Zhan)

    1. ¿Por qué usar la herencia?

    Derivar una nueva clase a partir de una clase existente se llama herencia.

    En diferentes clases también puede haber características y acciones comunes; se pueden colocar esas características y acciones comunes en una clase para que otras clases las compartan.

    Por lo tanto, se puede definir una clase genérica y luego extenderla a otras clases específicas, que heredan las características y acciones de la clase genérica.

    La herencia es un medio importante para lograr la reutilización de software en Java, evita la duplicación, es fácil de mantener y fácil de entender.

    2. Clase padre y clase hija

    Si la clase B se deriva de la clase A, o se dice que la clase B extiende a la clase A, o que la clase B hereda de la clase A,entonces se llama a la clase A "clase padre", también conocida como superclase o clase base;

    se llama a la clase B "clase hija", también conocida como subclase, clase extendida o clase derivada.

    La subclase hereda de su clase padre los campos de datos y métodos accesibles, y también puede añadir nuevos campos de datos y nuevos métodos.

    Sintaxis para definir herencia:

    修饰符 class 子类名 extends 父类名

    Por ejemplo: la clase Shape es la clase padre, y sus subclases pueden ser las clases Circle, Rectangle, Triangle, etc.

    Puntos a tener en cuenta sobre la herencia:

    • La subclase no es un subconjunto de la clase padre; generalmente la subclase contiene más campos de datos y métodos que la clase padre.
    • Los campos de datos private de la clase padre no son visibles en la subclase, por lo tanto no se pueden usar directamente en la subclase.
    • La herencia modela relaciones "es un/una"; entre la clase padre y su subclase debe existir una relación "es un/una"; de lo contrario, no se puede usar herencia.
      Pero no todas las relaciones "es un/una" deberían usar herencia. Por ejemplo, un cuadrado es un rectángulo, pero no se debe hacer que la clase Square herede de la clase Rectangle, porque un cuadrado no puede obtener nada al extender de un rectángulo. La relación de herencia correcta es que la clase Square herede de la clase Shape.
    • Java solo permite herencia única (es decir, una subclase solo puede tener una clase padre directa); C++ permite herencia múltiple (es decir, una subclase puede tener varias clases padre directas).

    3. La palabra clave super

    super representa la clase padre de la clase que lo usa. super se puede usar para:

    • llamar al constructor de la clase padre;
    • llamar a un método de la clase padre (cuando la subclase ha sobrescrito el método de la clase padre);
    • acceder a los campos de datos de la clase padre (se puede usar así, pero no es necesario).

    Sintaxis para llamar al constructor de la clase padre:

    super();  

或   

super(参数列表);

    Nota: la sentencia super debe ser la primera sentencia del constructor de la subclase. No se puede usar el nombre del constructor de la clase padre para llamar al constructor de la clase padre dentro de la subclase. El constructor de la clase padre no se hereda en la subclase. La única forma de llamar al constructor de la clase padre es usando la palabra clave super. Si la subclase no lo llama explícitamente, el compilador añade automáticamente super(); como la primera sentencia del constructor de la subclase. Esto forma una cadena de constructores.

    No se puede usar la palabra clave super en métodos estáticos.

    Sintaxis para llamar a un método de la clase padre:

    super.方法名(参数列表);

    Si es un método heredado, no es necesario usar super para llamarlo; se puede llamar directamente. Pero si la subclase sobrescribe o reescribe un método de la clase padre, solo se puede llamar al método reescrito de la clase padre dentro de la subclase usando super.

    4. La palabra clave this

    La palabra clave this representa el objeto actual. Se puede usar para:
    • llamar al constructor de la clase actual, y debe ser la primera sentencia del método. Por ejemplo: this(); llama al constructor predeterminado. this(parámetros); llama al constructor con parámetros.
    • restringir las variables de campo de datos del objeto actual. Generalmente se usa cuando una variable local dentro de un método tiene el mismo nombre que una variable de campo de datos del objeto. Por ejemplo, this.num = num. this.num representa la variable de campo de datos num del objeto actual, mientras que num representa la variable local del método.

    El efecto de final varía según el tipo que modifica.

    1. final modifica atributos o variables de la clase.

    Ya sea que el atributo sea de tipo primitivo o de tipo referencia, el efecto de final es que el "valor" almacenado en la variable no puede cambiar.

    Este valor, para los tipos primitivos, es el valor concreto almacenado en la variable, como 1, "abc", etc.

    Mientras que una variable de tipo referencia almacena una dirección, por lo que usar final para modificar una variable de tipo referencia significa que la dirección dentro de ella no puede cambiar; no significa que el contenido del objeto o array al que apunta esa dirección no pueda cambiar. Se debe tener mucho cuidado con esto.

    Por ejemplo: si una clase tiene un atributo comofinal Person p=new Person("name");Entonces no se puede reasignar p, pero se puede cambiar el valor de las propiedades dentro de p.p.setName('newName');

    Cuando final modifica un atributo, no es necesario asignarle valor al declarar la variable, pero una vez asignado, no se puede modificar. Un atributo final se puede asignar en tres lugares: en la declaración, en el bloque de inicialización o en el constructor; en resumen, debe asignarse.

    2. final modifica métodos de la clase.

    Función: puede ser heredado, pero no puede ser sobrescrito después de la herencia.

    3. final modifica una clase.

    Función: la clase no puede ser heredada.

    Cuando un archivo Java se compila a un archivo .class, en la primera línea (primera sentencia) de todos los constructores de la subclase se añade automáticamente por defecto la sentencia super(). Antes de ejecutar el constructor de la subclase, siempre se ejecuta primero el constructor de la clase padre.

    Al escribir código, se debe tener en cuenta:

    • 1. Si la clase padre no contiene un constructor predeterminado (es decir, NombreClase()), entonces la sentencia super() en la subclase fallará y el sistema reportará un error. Generalmente, el constructor predeterminado se añade automáticamente en tiempo de compilación, pero si la clase ya tiene un constructor, no se añade.
    • 2. La sentencia que ejecuta el constructor de la clase padre solo puede colocarse como la primera sentencia dentro de la función; de lo contrario, se producirá un error.

    En una relación de herencia, al llamar a una función (método) o a una variable miembro de la clase, la JVM (Máquina Virtual de Java) primero comprueba si la clase actual (es decir, la subclase) contiene dicha función o variable miembro.     • Dentro de todos los constructores de la subclase, la primera línea llama (implícitamente) de forma automática al constructor sin parámetros de la clase padre, super();
    • Si la primera línea del constructor de la subclase llama explícitamente a un constructor de la clase padre, el sistema ya no llamará al super() sin parámetros.

    Ejemplo:

    class Base {
    public Base() {
        System.out.println("Base--默认构造方法");
    }
    
    public Base(int c){
        System.out.println("Base--有参构造方法--" + c);
    }
}

public class Derived extends Base {
    public Derived() {
        // super(); //系统会自动隐式先调用父类的无参构造函数 super(); //必须是第一行，否则不能编译 
        System.out.println("Derived--默认构造方法");
    }
    
    public Derived(int c) {
        // super(); //系统会自动隐式先调用父类的无参构造函数 super(); //必须是第一行，否则不能编译
        System.out.println("Derived--有参构造方法" + c);
    }
    
    public Derived(int a, int b) {
        super(a); //如果子类构造方法第一行显式调用了父类构造方法，系统就不再调用无参的super()了。
        System.out.println("Derived--有参构造方法--" + b);
    }
    
    public static void main(String[] args) {
        System.out.println("============子类无参============");
        Derived no = new Derived();
        System.out.println("============子类有参============");
        Derived have = new Derived(33);
        System.out.println("============子类有参============");
        Derived have2 = new Derived(33, 55);
    }
}

    El problema de la conversión de tipos en Java en realidad no es complicado; solo recuerda una frase: una referencia de clase padre apunta a un objeto de clase hija.

    ¿Qué significa que una referencia de clase padre apunte a un objeto de clase hija? Déjame explicarlo poco a poco.

    Empecemos por 2 términos:: conversión ascendente (upcasting) 、conversión descendente (downcasting)。

    Por ejemplo: hay 2 clases, Father es la clase padre y la clase Son hereda de Father.

    Father f1 = new Son();   // 这就叫 upcasting （向上转型)
// 现在 f1 引用指向一个Son对象

Son s1 = (Son)f1;   // 这就叫 downcasting (向下转型)
// 现在f1 还是指向 Son对象

    Segundo ejemplo:

    Father f2 = new Father();
Son s2 = (Son)f2;       // 出错，子类引用不能指向父类对象

    Quizás te preguntes: en el primer ejemplo, ¿por qué es correcto Son s1 = (Son)f1;?

    Es muy sencillo, porque f1 apunta a un objeto de la subclase,Father f1 = new Son();una referencia de subclase s1, por supuesto, puede apuntar a un objeto de la subclase.

    Mientras que f2 se pasó a un objeto Father,Father f2 = new Father();una referencia de subclase s1 no puede apuntar a un objeto de la clase padre.

    Resumen:

    1. Una referencia de clase padre puede apuntar a un objeto de subclase, pero una referencia de subclase no puede apuntar a un objeto de clase padre.

    2. Asignar directamente un objeto de subclase a una referencia de clase padre se llama upcasting (conversión ascendente). La conversión ascendente no requiere conversión forzada, por ejemplo:

    Father f1 = new Son();

    3. Asignar una referencia de clase padre que apunta a un objeto de subclase a una referencia de subclase se llama downcasting (conversión descendente), y requiere conversión forzada, por ejemplo:

    f1 es una referencia de clase padre que apunta a un objeto de subclase. Asignar f1 a la referencia de subclase s1 es:Son s1 = (Son)f1;

    Aquí, (Son) delante de f1 debe añadirse para realizar la conversión forzada.

    Para más contenido, consulte:Problema de conversión de tipos en Java

    Para comprender la herencia, lo más importante es saber qué se hereda, o mejor dicho, qué obtiene la subclase de la clase padre. La respuesta es: todo. Todos los miembros de la clase padre, incluidas variables y métodos, se convierten en miembros de la subclase, excepto los constructores. Los constructores son exclusivos de la clase padre porque sus nombres son el nombre de la clase, por lo que los constructores de la clase padre no existen en la subclase. Aparte de eso, la subclase hereda todos los miembros de la clase padre.

    Pero obtener no significa que se pueda usar libremente. Cada miembro tiene diferentes atributos de acceso. La subclase hereda todos los miembros de la clase padre, pero los diferentes atributos de acceso hacen que la subclase use estos miembros de manera distinta: algunos miembros de la clase padre se convierten directamente en la interfaz externa de la subclase, otros están profundamente ocultos, incluso la propia subclase no puede acceder directamente a ellos. La siguiente tabla enumera los atributos de acceso de los miembros de la clase padre en la subclase:

    Atributos de acceso de los miembros de la clase padreSignificado en la clase padre Significado en la subclase
    publicAbierto a todosAbierto a todos
    protectedSolo otras clases del mismo paquete, la propia clase y las subclases pueden accederSolo otras clases del mismo paquete, la propia clase y las subclases pueden acceder
    Por defectoSolo otras clases del mismo paquete pueden accederSi la subclase y la clase padre están en el mismo paquete: solo otras clases del paquete pueden acceder; de lo contrario: equivale a private, no se puede acceder
    privateSolo la propia clase puede accederNo se puede acceder

    Los miembros public se convierten directamente en miembros public de la subclase; los miembros protected también se convierten directamente en miembros protected de la subclase. En Java, protected significa que es accesible dentro del paquete y para las subclases, por lo que es más amplio que el atributo de acceso por defecto. En cuanto a los miembros de la clase padre con atributo de acceso por defecto (sin definir), son visibles dentro del paquete de la clase padre. Si la subclase no pertenece al paquete de la clase padre, entonces dentro de la subclase estos miembros con atributo por defecto son iguales que los miembros private: invisibles. Los miembros private de la clase padre siguen existiendo en la subclase, pero la subclase no puede acceder directamente a ellos. No podemos redefinir en la subclase los atributos de acceso de los miembros heredados. Si intentamos redefinir una variable miembro que ya existe en la clase padre, entonces estamos definiendo una variable completamente independiente de la variable miembro de la clase padre; en la subclase podemos acceder a esta variable definida en la subclase, y en los métodos de la clase padre se accede a la de la clase padre. Aunque tienen el mismo nombre, no se afectan mutuamente.

    Al construir un objeto de una subclase, el constructor de la clase padre también se invoca, y el constructor de la clase padre se invoca antes que el constructor de la subclase. Durante la ejecución del programa, parte del espacio del objeto de la subclase almacena el objeto de la clase padre. Debido a que la subclase hereda de la clase padre, durante la inicialización del objeto de la subclase se pueden utilizar miembros de la clase padre. Por lo tanto, el espacio de la clase padre debe inicializarse primero, y luego se inicializa el espacio de la subclase. En este proceso, si el constructor de la clase padre requiere parámetros, es importante cómo pasarlos.

    Sobre el problema de la herencia de las clases internas miembro. En general, las clases internas rara vez se utilizan para herencia. Pero cuando se usan para heredar, hay que tener en cuenta dos puntos:

    • 1) La referencia de la clase interna miembro debe ser Outter.Inner.
    • 2) El constructor debe tener una referencia al objeto de la clase externa, y a través de esta referencia se llama a super(). Este código está extraído de 'Thinking in Java'.
    class WithInner {
    class Inner{
         
    }
}
class InheritInner extends WithInner.Inner {
      
    // InheritInner() 是不能通过编译的，一定要加上形参
    InheritInner(WithInner wi) {
        wi.super(); //必须有这句调用
    }
  
    public static void main(String[] args) {
        WithInner wi = new WithInner();
        InheritInner obj = new InheritInner(wi);
    }
}
