Polimorfismo en Java

El polimorfismo es la capacidad de un mismo comportamiento de tener múltiples formas o manifestaciones diferentes.

El polimorfismo es que la misma interfaz, al usar diferentes instancias, ejecuta diferentes operaciones, como se muestra en la figura:

El polimorfismo es la manifestación de las múltiples formas de un objeto.

En la vida real, por ejemplo, la acción de presionar la tecla F1:

  • Si estás en la interfaz de Flash, aparece la documentación de ayuda de AS 3;
  • Si estás en Word, aparece la ayuda de Word;
  • Si estás en Windows, aparece la ayuda y el soporte de Windows.

El mismo evento que ocurre en diferentes objetos produce diferentes resultados.

Ventajas del polimorfismo

  • 1. Eliminar el acoplamiento entre tipos
  • 2. Sustituibilidad
  • 3. Extensibilidad
  • 4. Capacidad de interfaz
  • 5. Flexibilidad
  • 6. Simplicidad

Tres condiciones necesarias para que exista el polimorfismo

  • Herencia
  • Sobrescritura
  • Una referencia de la clase padre apunta a un objeto de la clase hija:Parent p = new Child();

class Shape {
    void draw() {}
}
 
class Circle extends Shape {

        System.out.println("Circle.draw()");
    }
}
 
class Square extends Shape {

        System.out.println("Square.draw()");
    }
}
 
class Triangle extends Shape {
    void draw() {
        System.out.println("Triangle.draw()");
    }
}

Cuando se llama a un método mediante polimorfismo, primero se verifica si la clase padre tiene ese método; si no lo tiene, se produce un error de compilación; si lo tiene, se llama al método del mismo nombre en la clase hija.

Los beneficios del polimorfismo: permite que el programa tenga una buena extensibilidad y pueda procesar de manera genérica los objetos de todas las clases.

Funciones virtuales

Las funciones virtuales existen para el polimorfismo.

En Java, en realidad no existe el concepto de función virtual; sus funciones normales equivalen a las funciones virtuales de C++. La vinculación dinámica es el comportamiento predeterminado de Java. Si en Java no se desea que una función tenga características de función virtual, se puede añadir la palabra clave final para convertirla en una función no virtual.

Sobrescritura

Vamos a explicar cómo, en Java, al diseñar clases, el comportamiento de los métodos sobrescritos afecta al polimorfismo.

Ya hemos hablado de la sobrescritura de métodos, es decir, que una subclase puede sobrescribir los métodos de la clase padre.

Cuando un objeto de la subclase llama a un método sobrescrito, se llama al método de la subclase, no al método sobrescrito de la clase padre.

Para llamar al método sobrescrito de la clase padre, se debe utilizar la palabra clavesuper。

Código del archivo Employee.java:

/*Nombre de archivo: Employee.java*/ public class Employee { private String name; private String address; private int number; public Employee(String name, String address, int number) { System.out.println("Constructor de Employee"); this.name = name; this.address = address; this.number = number; } public void mailCheck() { System.out.println("Enviar cheque a:" + this.name + " " + this.address); } public String toString() { return name + " " + address + " " + number; } public String getName() { return name; } public String getAddress() { return address; } public void setAddress(String newAddress) { address = newAddress; } public int getNumber() { return number; } }

Análisis del ejemplo

  • En el ejemplo, se instanciaron dos objetos Salary: uno usando la referencia Salary s, y otro usando la referencia Employee e.

  • Cuando se llama a s.mailCheck(), el compilador encuentra mailCheck() en la clase Salary durante la compilación, y durante la ejecución la JVM llama a mailCheck() de la clase Salary.

  • e es una referencia de Employee, pero la referencia e finalmente ejecuta el método mailCheck() de la clase Salary.

  • En tiempo de compilación, el compilador usa el método mailCheck() de la clase Employee para verificar la sentencia, pero en tiempo de ejecución, la Máquina Virtual de Java (JVM) llama al método mailCheck() de la clase Salary.

Todo el proceso anterior se denomina invocación de método virtual, y dicho método se denomina método virtual.

En Java, todos los métodos pueden comportarse de esta manera; por lo tanto, los métodos sobrescritos pueden invocarse en tiempo de ejecución, sin importar el tipo de dato de la variable de referencia en el código fuente en el momento de la compilación.

    En cuanto al polimorfismo, se pueden resumir los siguientes puntos:

    Primero: usar una referencia del tipo de la clase padre para apuntar a un objeto de la clase hija;

    Segundo: dicha referencia solo puede llamar a los métodos y variables definidos en la clase padre;

    Tercero: si la subclase sobrescribe un método de la clase padre, al llamar a este método se invocará el método de la subclase; (enlace dinámico, invocación dinámica);

    Cuarto: las variables no se pueden sobrescribir (anular); el concepto de 'sobrescritura' solo se aplica a los métodos. Si en la subclase se 'sobrescribe' una variable de la clase padre, se producirá un error de compilación.

    Clasificación del polimorfismo

    El polimorfismo generalmente se divide en dos tipos: polimorfismo por sobrescritura y polimorfismo por sobrecarga.

    Polimorfismo por sobrecargaTambién llamado polimorfismo en tiempo de compilación. Es decir, este polimorfismo ya está determinado en tiempo de compilación. La sobrecarga es conocida por todos: un grupo de métodos con el mismo nombre pero diferente lista de parámetros es sobrecarga. Al llamar a estos métodos sobrecargados, se obtienen diferentes resultados al pasar diferentes parámetros.

    Pero aquí hay ambigüedad; algunos piensan que la sobrecarga no debería considerarse polimorfismo. Porque mucha gente entiende el polimorfismo como: el tipo concreto al que apunta la variable de referencia definida en el programa y la llamada al método emitida a través de dicha variable de referencia no se determinan en tiempo de programación, sino durante la ejecución del programa; esta situación se llama polimorfismo. Lo que describe esta definición es nuestro segundo tipo de polimorfismo: el polimorfismo por reescritura. Además, el polimorfismo por sobrecarga no es exclusivo de la programación orientada a objetos, mientras que el polimorfismo es una de las tres características principales de la orientación a objetos (si no estoy en lo correcto, recuerda decírmelo...).

    No creo que sea necesario profundizar demasiado en la definición. Mi entendimiento es: la capacidad de un mismo comportamiento de tener múltiples formas o manifestaciones diferentes es polimorfismo, por lo que considero que la sobrecarga también es un tipo de polimorfismo. Si no estás de acuerdo con esta opinión, también lo acepto.

    重写式多态También llamado polimorfismo en tiempo de ejecución. Este polimorfismo se implementa mediante la técnica de enlace dinámico (dynamic binding), que consiste en determinar el tipo real del objeto referenciado durante la ejecución y llamar a su método correspondiente según su tipo real. Es decir, solo cuando el programa se ejecuta sabes qué método de la subclase se está llamando. Este polimorfismo se logra mediante la reescritura de funciones y la conversión ascendente (upcasting). El ejemplo de código anterior es un polimorfismo por reescritura completo. Todo el polimorfismo del que hablaremos a continuación es polimorfismo por reescritura, porque es el verdadero polimorfismo en la programación orientada a objetos.

    Si el método de la subclase sobrescribe el método de la clase padre, también decimos que ese método de la clase padre tiene una nueva versión o una nueva implementación en la subclase. La nueva versión sobrescrita tiene la misma firma de método que la versión anterior: el mismo nombre de método y la misma lista de parámetros. Por lo tanto, desde el exterior, la subclase no ha añadido un nuevo método; sigue siendo el método definido en la clase padre. La diferencia es que se trata de una nueva versión, así que al llamar a este método a través de un objeto de la subclase, se ejecuta el método propio de la subclase.

    La relación de sobrescritura no significa que el método de la clase padre ya no exista, sino que cuando se llama a este método a través de un objeto de la subclase, el método de la subclase reemplaza al de la clase padre, y el método de la clase padre queda «oculto» por la sobrescritura y no se ve. Pero cuando se llama a este método a través de un objeto de la clase padre, en realidad se sigue ejecutando el método de la clase padre. Nótese que aquí hablamos de objetos, no de variables, porque una variable de tipo padre podría apuntar en realidad a un objeto de la subclase.

    Cuando se llama a un método, el asunto de a qué método se debe llamar exactamente se llama enlace (binding). El enlace indica qué método usamos al invocar un método. Hay dos tipos de enlace: uno es el enlace temprano, también llamado enlace estático, que se determina en tiempo de compilación; el otro es el enlace tardío, es decir, el enlace dinámico. El enlace dinámico decide dinámicamente el método a llamar según el tipo real del objeto al que apunta la variable en ese momento durante la ejecución. Java usa el enlace dinámico por defecto.

    JAVA – Funciones virtuales, funciones abstractas, clases abstractas e interfaces

    1. Funciones virtuales de Java

    La existencia de las funciones virtuales es para el polimorfismo.

    En C++, una función miembro ordinaria se convierte en función virtual al añadir la palabra clave `virtual`.

    En Java, en realidad no existe el concepto de función virtual; sus funciones ordinarias equivalen a las funciones virtuales de C++, y el enlace dinámico es el comportamiento predeterminado de Java. Si en Java no se desea que una función tenga características de función virtual, se puede añadir la palabra clave `final` para convertirla en una función no virtual.

    PS: En realidad, C++ y Java tienen opiniones similares sobre las funciones virtuales; es el mismo resultado por diferentes medios.

    2. Funciones abstractas de Java (funciones virtuales puras)

    La existencia de funciones abstractas, o funciones virtuales puras, es para definir interfaces.

    La forma de una función virtual pura en C++ es:

    virtual void print() = 0;

    La forma de una función virtual pura en Java es:

    abstract void print();

    PS:En cuanto a las funciones abstractas, C++ y Java no cambian la esencia; es lo mismo con otra apariencia.

    3. Clases abstractas de Java

    La existencia de la clase abstracta se debe a que la clase padre incluye tanto definiciones concretas de funciones comunes a las subclases como interfaces de funciones que deben implementar cada una de las subclases. Una clase abstracta puede tener miembros de datos y métodos no abstractos.

    En C++, una clase abstracta solo necesita incluir funciones virtuales puras para ser una clase abstracta. Si solo incluye funciones virtuales, no puede definirse como clase abstracta, porque en la clase realmente no hay concepto de abstracción.

    Una clase abstracta en Java es una clase declarada con el modificador `abstract`.

    PS:Una clase abstracta es en realidad algo mitad virtual y mitad concreto; puede ser completamente virtual, y en ese caso se convierte en una interfaz.

    4. Java 接口

    La existencia de las interfaces es para formar un contrato. Una interfaz no puede tener variables miembro ordinarias ni funciones virtuales no puras.

    En C++, una interfaz es en realidad una clase base completamente virtual.

    En Java, una interfaz es una clase modificada con la palabra clave interface.

    PS:Una interfaz es una clase abstracta virtualizada al extremo.

    5. 小结

    C++ 虚函数    ==  Java 普通函数

C++ 纯虚函数  ==  Java 抽象函数

C++ 抽象类    ==  Java 抽象类

C++ 虚基类    ==  Java 接口

    En la referencia ascendente, los métodos miembro no estáticos y las variables miembro del mismo nombre de la subclase sobrescriben los métodos miembro no estáticos y las variables miembro del mismo nombre de la clase padre; los métodos miembro estáticos del mismo nombre de la subclase quedan ocultos por los métodos miembro estáticos del mismo nombre de la clase padre, es decir, quedan sobrescritos.

    Se puede utilizar la palabra clave `super` en la subclase para invocar explícitamente los métodos miembro no estáticos y las variables miembro de la clase padre que han sido sobrescritos.

    public class Test {
    public static void main(String[] args) {
        System.out.println("Polymorghpic Test");
        Animal a = new Dog();
        Animal b = new Dog("smith", 5);
        // 子类的非静态方法与变量覆盖父类     
        a.getInfo();
        // 子类通过super调用父类的非静态成员方法和变量  
        a.getSuperInfo();
        // 子类的静态方法被父类隐藏   
        a.hello();
        b.getInfo();
        b.hello();
    }
}

    Cuando un método estático es sobrescrito por la subclase, depende de si la referencia de la clase padre o la referencia de la subclase apunta al objeto de la subclase. Si es una referencia de la clase padre apuntando a un objeto de la subclase, al llamar al método estático se invocará el método estático de la clase padre. Si es una referencia de la subclase apuntando a un objeto de la subclase, al llamar al método estático se invocará el método estático de la subclase.

    public class Test {
    public static void main(String[] args) {
        System.out.println("Polymorghpic Test");
        Animal a = new Dog();
        Animal b = new Dog("smith", 5);
        Dog c = new Dog();
        // 子类的非静态方法与变量覆盖父类
        a.getInfo();
        // 子类通过super调用父类的非静态成员方法和变量
        a.getSuperInfo();
        // 子类的静态方法被父类隐藏
        a.hello();
        b.getInfo();
        b.hello();
        // 调用子类的静态方法
        c.hello();
    }
}
