Clases de datos y clases selladas de Kotlin

数据类

Kotlin puede crear una clase que solo contenga datos; la palabra clave esdata：

data class User(val name: String, val age: Int)

El compilador extrae automáticamente las siguientes funciones del constructor principal en función de todas las propiedades declaradas:

  • equals() / hashCode()
  • toString()格式如"User(name=John, age=42)"
  • componentN() functionsCorresponden a las propiedades, en orden de declaración
  • copy()函数

Si estas funciones ya están definidas explícitamente en la clase, o se heredan de una superclase, no se generarán.

Para garantizar la coherencia y el significado del código generado, las clases de datos deben cumplir las siguientes condiciones:

  • El constructor primario debe contener al menos un parámetro.

  • Todos los parámetros del constructor principal deben marcarse comoval或者var ;

  • Las clases de datos no pueden declararse comoabstract, open, sealed或者inner;

  • Las clases de datos no pueden heredar de otras clases (pero pueden implementar interfaces).

复制

Copia: usando la función copy(), podemos copiar un objeto y modificar algunas propiedades. Para la clase User anterior, su implementación sería similar a la siguiente:

fun copy(name: String = this.name, age: Int = this.age) = User(name, age)

实例

Usando copy para copiar la clase de datos User y modificar la propiedad age:

data class User(val name: String, val age: Int)


fun main(args: Array<String>) {
    val jack = User(name = "Jack", age = 1)
    val olderJack = jack.copy(age = 2)
    println(jack)
    println(olderJack)

}

El resultado de salida es:

User(name=Jack, age=1)
User(name=Jack, age=2)

Clases de datos y declaraciones de desestructuración

Las funciones de componente permiten que las clases de datos se usen en declaraciones de desestructuración:

val jane = User("Jane", 35)
val (name, age) = jane
println("$name, $age years of age") // prints "Jane, 35 years of age"

标准数据类

La biblioteca estándar proporcionaPair 和 TripleEn la mayoría de los casos, nombrar las clases de datos es una mejor opción de diseño, porque así el código es más legible y proporciona nombres y propiedades significativos.

密封类

Las clases selladas se usan para representar estructuras de herencia restringidas: cuando un valor tiene un número limitado de tipos y no puede tener ningún otro tipo. En cierto sentido, son una extensión de las clases de enumeración: el conjunto de valores de un tipo de enumeración también es limitado, pero cada constante de enumeración existe solo como una instancia, mientras que una subclase de una clase sellada puede tener varias instancias que pueden contener estado.

Para declarar una clase sellada, usasealedClase modificadora: una clase sellada puede tener subclases, pero todas las subclases deben estar anidadas dentro de la clase sellada.

sealed no puede aplicarse a interface ni a abstract class (emitirá un warning, pero no causará un error de compilación)

sealed class Expr
data class Const(val number: Double) : Expr()
data class Sum(val e1: Expr, val e2: Expr) : Expr()
object NotANumber : Expr()

fun eval(expr: Expr): Double = when (expr) {
    is Const -> expr.number
    is Sum -> eval(expr.e1) + eval(expr.e2)
    NotANumber -> Double.NaN
}

La principal ventaja de usar clases selladas es que, al usar una expresión `when`, si se puede verificar que la declaración cubre todos los casos, no es necesario añadir una cláusula `else` para dicha declaración.

fun eval(expr: Expr): Double = when(expr) {
    is Expr.Const -> expr.number
    is Expr.Sum -> eval(expr.e1) + eval(expr.e2)
    Expr.NotANumber -> Double.NaN
    // 不再需要 `else` 子句，因为我们已经覆盖了所有的情况
}

    Mi entendimiento es que una clase sellada es un tipo de clase diseñada específicamente para usarse con la declaración `when`. Por ejemplo, si en Android tenemos una `view` y queremos usar una declaración `when` para realizar dos operaciones sobre la `view`: mostrar y ocultar, entonces se puede hacer así:

    sealed class UiOp {
    object Show: UiOp()
    object Hide: UiOp()
} 
fun execute(view: View, op: UiOp) = when (op) {
    UiOp.Show -> view.visibility = View.VISIBLE
    UiOp.Hide -> view.visibility = View.GONE
}

    Las funciones anteriores en realidad se pueden implementar completamente con enumeraciones, pero si ahora queremos añadir dos operaciones: traslación horizontal y traslación vertical, y además llevar algunos datos, como cuánta distancia se trasladó, el tipo de animación del proceso de traslación, etc., con enumeraciones claramente no es tan fácil. En este momento se puede aprovechar la ventaja de las clases selladas, por ejemplo:

    sealed class UiOp {
    object Show: UiOp()
    object Hide: UiOp()
    class TranslateX(val px: Float): UiOp()
    class TranslateY(val px: Float): UiOp()
}

 

fun execute(view: View, op: UiOp) = when (op) {
    UiOp.Show -> view.visibility = View.VISIBLE
    UiOp.Hide -> view.visibility = View.GONE
    is UiOp.TranslateX -> view.translationX = op.px // 这个 when 语句分支不仅告诉 view 要水平移动，还告诉 view 需要移动多少距离，这是枚举等 Java 传统思想不容易实现的
    is UiOp.TranslateY -> view.translationY = op.px
}

    En el código anterior, `TranslateX` es una clase que puede llevar más de una información; por ejemplo, además de decirle a la `view` que necesita traslación horizontal, también puede indicarle a la `view` cuántos píxeles trasladar, e incluso puede indicarle el tipo de animación de la traslación, etc. Creo que este es aproximadamente el propósito de la existencia de las clases selladas.

    Además, si las ramas de la declaración `when` no necesitan llevar otra información además de "mostrar u ocultar la `view`" (es decir, solo necesitan indicar la rama de `when` sin llevar datos adicionales), se puede crear un singleton con la palabra clave `object`, y en ese caso la cláusula `when` no necesita usar la palabra clave `is`. Solo cuando se necesita llevar información adicional se definen subclases de la clase sellada, y al usar una clase sellada no se necesita la cláusula `else`. Cada vez que añadimos una subclase o singleton de la clase sellada, el compilador dará una advertencia en la declaración `when`, lo que permite detectar errores en la fase de compilación. Esta es también una función que las antiguas declaraciones `switch-case` y las enumeraciones no tienen.

    Finalmente, incluso podemos encapsular este conjunto de operaciones en una función para poder invocarla más adelante, como se muestra a continuación:

    // 先封装一个UI操作列表
class Ui(val uiOps: List = emptyList()) {
    operator fun plus(uiOp: UiOp) = Ui(uiOps + uiOp)
}

// 定义一组操作
val ui = Ui() +
        UiOp.Show +
        UiOp.TranslateX(20f) +
        UiOp.TranslateY(40f) +
        UiOp.Hide
// 定义调用的函数
fun run(view: View, ui: Ui) {
    ui.uiOps.forEach { execute(view, it) }
}

run(view, ui) // 最终调用
