LangChain Memoria de Conversación -- Checkpointer

Por defecto, cada agent.invoke() es independiente; el Agent no recuerda lo que se habló anteriormente.

Checkpointer (guardador de puntos de control) permite que el Agent recuerde el historial de la conversación, logrando verdaderas conversaciones de múltiples turnos.

El problema de no usar Checkpointer

Veamos primero qué sucede sin Checkpointer:

Ejemplo

from dotenv import load_dotenv
load_dotenv()

from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain.messages import HumanMessage

model = init_chat_model("deepseek:deepseek-v4-flash", temperature=0)
agent = create_agent(
    model=model,
    system_prompt="Eres el asistente del tutorial RUNOOB.",
)

# Primera ronda
result1 = agent.invoke({
    "messages": [HumanMessage(content="Me llamo Xiaoming")]
})
print(f"Primera ronda: {result1['messages'][-1].content}")

# Segunda ronda: ¡el Agent no recuerda el contenido de la primera!
result2 = agent.invoke({
    "messages": [HumanMessage(content="¿Cómo me llamo?")]
})
print(f"Segunda ronda: {result2['messages'][-1].content}")

Resultado de la ejecución:

Primera ronda: ¡Hola Xiaoming! Encantado de conocerte.
Segunda ronda: Lo siento, no tengo tu información, no sé cómo te llamas.

Usar Checkpointer para recordar conversaciones

Tras añadir Checkpointer, las conversaciones bajo el mismo thread_id se asocian automáticamente:

Ejemplo

from langgraph.checkpoint.memory import InMemorySaver
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain.messages import HumanMessage

# Crea un Checkpointer en memoria
checkpointer = InMemorySaver()

model = init_chat_model("deepseek:deepseek-v4-flash", temperature=0)
agent = create_agent(
    model=model,
    checkpointer=checkpointer,  # Pasa el Checkpointer
    system_prompt="Eres el asistente del tutorial RUNOOB.",
)

# Usa thread_id para identificar el hilo de conversación
config = {"configurable": {"thread_id": "user-001"}}

# Primera ronda
result1 = agent.invoke(
    {"messages": [HumanMessage(content="Me llamo Xiaoming, estoy aprendiendo Python")]},
    config=config,
)
print(f"Primera ronda: {result1['messages'][-1].content}")

# Segunda ronda: con el mismo thread_id, ¡el Agent lo recuerda!
result2 = agent.invoke(
    {"messages": [HumanMessage(content="¿Cómo me llamo? ¿Qué estoy aprendiendo?")]},
    config=config,
)
print(f"Segunda ronda: {result2['messages'][-1].content}")

Resultado de la ejecución:

第一轮: 你好小明！Python 是一门很好的入门语言，有什么需要帮助的吗？
第二轮: 你叫小明，你正在学习 Python。有什么具体问题我可以帮你吗？

thread_id es la clave. Las conversaciones bajo el mismo thread_id son continuas, mientras que las conversaciones con diferentes thread_id están totalmente aisladas. Esto te permite atender a varios usuarios simultáneamente con una única instancia del Agent.

Cómo funciona Checkpointer

Checkpointer guarda automáticamente una instantánea del estado (checkpoint) después de cada ejecución del Agent. La próxima vez que se invoque con el mismo thread_id, el estado se restaura automáticamente desde el checkpoint más reciente.

Flujo de trabajo detallado:

  1. Se llama a agent.invoke() pasando el config (que contiene thread_id)
  2. El Agent comprueba si existe un checkpoint para ese thread_id
  3. Si existe, carga los mensajes históricos, añade los nuevos mensajes y continúa
  4. Al terminar la ejecución, guarda automáticamente un nuevo checkpoint

Ejemplo

from langgraph.checkpoint.memory import InMemorySaver
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain.messages import HumanMessage

checkpointer = InMemorySaver()
agent = create_agent(
    model=init_chat_model("deepseek:deepseek-v4-flash", temperature=0),
    checkpointer=checkpointer,
    system_prompt="Eres el asistente del tutorial RUNOOB.",
)

config = {"configurable": {"thread_id": "demo-001"}}

# Simula una conversación de varios turnos
questions = [
    "Me llamo Xiaoming",
    "Estoy aprendiendo Python",
    "Resume la información sobre mí",
]

for i, q in enumerate(questions, 1):
    result = agent.invoke(
        {"messages": [HumanMessage(content=q)]},
        config=config,
    )

    # Consulta el estado del checkpoint
    state = agent.get_state(config)
    print(f"\nDespués de la ronda {i}:")
    print(f" Número de mensajes: {len(state.values.get('messages', []))}")
    print(f" Siguiente paso: {state.next}")
    print(f" Respuesta: {result['messages'][-1].content[:80]}...")

Resultado de la ejecución:

第 1 轮后:
  消息数: 2
  下一步: ()
  回复: 你好小明！很高兴认识你。

第 2 轮后:
  消息数: 4
  下一步: ()
  回复: Python 是一门非常流行的编程语言，简单易学。

第 3 轮后:
  消息数: 6
  下一步: ()
  回复: 根据我们的对话，你的信息如下：你叫小明，正在学习 Python。

Tipos de Checkpointer

Tipo Ubicación de almacenamiento Persistencia Instalación Escenarios de uso
InMemorySaver Memoria No (se pierde al salir del programa) Integrado Depuración de desarrollo, pruebas unitarias
SqliteSaver Base de datos SQLite 是 langgraph-checkpoint-sqlite Despliegue en un solo equipo, aplicaciones pequeñas
PostgresSaver PostgreSQL 是 langgraph-checkpoint-postgres Entorno de producción, uso compartido entre múltiples instancias

Si el Agent utilizaainvoke()llamadas asíncronas, debe cambiarse a la versión asíncrona correspondienteAsyncSqliteSaver / AsyncPostgresSaver, el uso es similar a la versión síncrona, solo que debe utilizarse junto conasync withpara su uso.

Ejemplo de SqliteSaver

InMemorySaverSolo se guarda en memoria; los datos se pierden al salir del programa. Si deseas que la conversación se guarde de forma persistente, puedes usarSqliteSaver。

La primera vez que se usa, es necesario instalar SQLite Checkpointer:

pip install langgraph-checkpoint-sqlite

Ejemplo

from langgraph.checkpoint.sqlite import SqliteSaver
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain.messages import HumanMessage

model = init_chat_model(
    "deepseek:deepseek-v4-flash",
    temperature=0,
)

# Debe usarse la sentencia with para entrar; al salir se cierra automáticamente la conexión a la base de datos
with SqliteSaver.from_conn_string("conversations.db") as checkpointer:
    agent = create_agent(
        model=model,
        checkpointer=checkpointer,
        system_prompt="Eres el asistente del tutorial RUNOOB.",
    )

    config = {"configurable": {"thread_id": "user-001"}}

    result = agent.invoke(
        {
            "messages": [
                HumanMessage(content="Hola")
            ]
        },
        config=config,
    )

    print(result["messages"][-1].content)

SqliteSaver guarda en la base de datos SQLite el checkpoint generado en cada conversación. Incluso si el programa se cierra o se reinicia, mientras se sigan usando el mismo archivo de base de datos ythread_id, el Agent podrá recuperar el estado de conversación guardado anteriormente. Nota:withAl terminar el bloque de código se cierra la conexión a la base de datos, por lo que toda la lógica que implique múltiples llamadas al Agent debe colocarse dentro del bloquewith; si se trata de un servicio de larga duración (como una aplicación web), se recomienda mantener la conexión durante todo el ciclo de vida de la aplicación, o cambiar a la versión asíncrona deAsyncSqliteSaver。

Gestionar hilos de conversación

Ver el estado de la conversación

Ejemplo

# Consulta el estado de la conversación
state = agent.get_state(config)
print(f"Siguiente paso: {state.next}")  # () indica inactividad
print(f"Número de mensajes: {len(state.values.get('messages', []))}")

# Consulta el historial de la conversación
for msg in state.values.get("messages", []):
    print(f"  [{msg.type}] {str(msg.content)[:60]}")
