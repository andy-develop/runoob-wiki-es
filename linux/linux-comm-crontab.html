Manual completo de comandos Linux

Linux crontabEs un comando del sistema Linux que se utiliza para establecer instrucciones que se ejecutan periódicamente.

Cuando se completa la instalación del sistema operativo, este comando de programación de tareas se inicia de forma predeterminada.

crondEl comando revisa periódicamente cada minuto si hay trabajos que ejecutar; si los hay, los ejecuta automáticamente.

Nota:Las tareas cron recién creadas no se ejecutan inmediatamente; deben pasar al menos 2 minutos. Por supuesto, puedes reiniciar cron para que se ejecuten de inmediato.

El trabajo de programación de tareas de Linux se divide principalmente en las siguientes dos categorías:

  • 1. Trabajos ejecutados por el sistema:Trabajos que el sistema debe realizar periódicamente, como respaldar datos del sistema, limpiar caché.
  • 2. Trabajos ejecutados por el usuario:Trabajos que un usuario debe realizar periódicamente, como revisar cada 10 minutos si el servidor de correo tiene nuevos mensajes. Estos trabajos pueden ser configurados por cada usuario.

Herramienta en línea para expresiones Cron:https://www.jyshare.com/front-end/9444/

Tareas programadas Cron en Linux:https://www.runoob.com/w3cnote/linux-cron-task.html

Sintaxis

crontab [ -u user ] file

或

crontab [ -u user ] { -l | -r | -e }

Descripción:

crontab se utiliza para que el usuario ejecute programas en un horario fijo o a intervalos fijos; en otras palabras, es similar a una agenda del usuario.

-u user se refiere a configurar la agenda del usuario especificado. Para ello, debes tener permisos (por ejemplo, ser root) para poder especificar la agenda de otros. Si no se usa -u user, se configura la propia agenda.

Descripción de parámetros：

  • -e : Ejecuta un editor de texto para configurar la agenda. El editor de texto predeterminado es Vi/Vim. Si deseas usar otro editor, configura primero la variable de entorno VISUAL para especificar el editor (por ejemplo, setenv VISUAL joe)
  • -r : Elimina la agenda actual
  • -l : Lista la agenda actual

Ver el archivo crontab del usuario actual:

crontab -l

Editar el archivo crontab del usuario actual:

crontab -e

Eliminar el archivo crontab del usuario actual:

crontab -r

Listar el archivo crontab de un usuario (se necesitan los permisos correspondientes):

crontab -u username -l

Editar el archivo crontab de un usuario (se necesitan los permisos correspondientes):

crontab -u username -e

Formato

El formato de tiempo es el siguiente:

f1 f2 f3 f4 f5 program
  • Donde f1 representa los minutos, f2 representa las horas, f3 representa el día del mes, f4 representa el mes, f5 representa el día de la semana. program representa el programa a ejecutar.
  • Cuando f1 es *, significa que program se ejecuta cada minuto; cuando f2 es *, significa que el programa se ejecuta cada hora; y así sucesivamente.
  • Cuando f1 es a-b, significa que debe ejecutarse durante el periodo del minuto a al minuto b; cuando f2 es a-b, significa que debe ejecutarse de la hora a a la hora b; y así sucesivamente.
  • Cuando f1 es */n, significa que se ejecuta cada n minutos; cuando f2 es */n, significa que se ejecuta cada n horas; y así sucesivamente.
  • Cuando f1 es a, b, c,..., significa que debe ejecutarse en los minutos a, b, c,...; cuando f2 es a, b, c,..., significa que debe ejecutarse en las horas a, b, c,...; y así sucesivamente.
*    *    *    *    *
-    -    -    -    -
|    |    |    |    |
|    |    |    |    +----- 星期中星期几 (0 - 6) (星期天 为0)
|    |    |    +---------- 月份 (1 - 12) 
|    |    +--------------- 一个月中的第几天 (1 - 31)
|    +-------------------- 小时 (0 - 23)
+------------------------- 分钟 (0 - 59)

Ejemplos

Ejecutar /bin/ls una vez por minuto:

* * * * * /bin/ls

En diciembre, todos los días de 6:00 a 12:00, ejecutar /usr/bin/backup cada 3 horas en el minuto 0:

0 6-12/3 * 12 * /usr/bin/backup

De lunes a viernes a las 5:00 p. m., enviar una carta a alex@domain.name:

0 17 * * 1-5 mail -s "hi" alex@domain.name < /tmp/maildata

Todos los días, a las 0:20, 2:20, 4:20... (cada dos horas en el minuto 20), ejecutar echo 'haha':

20 0-23/2 * * * echo "haha"

A continuación, veamos algunos ejemplos específicos:

0 */2 * * * /sbin/service httpd restart  意思是每两个小时重启一次apache 

50 7 * * * /sbin/service sshd start  意思是每天7：50开启ssh服务 

50 22 * * * /sbin/service sshd stop  意思是每天22：50关闭ssh服务 

0 0 1,15 * * fsck /home  每月1号和15号检查/home 磁盘 

1 * * * * /home/bruce/backup  每小时的第一分执行 /home/bruce/backup这个文件 

00 03 * * 1-5 find /home "*.xxx" -mtime +4 -exec rm {} \;  每周一至周五3点钟，在目录/home中，查找文件名为*.xxx的文件，并删除4天前的文件。

30 6 */10 * * ls  意思是每月的1、11、21、31日是的6：30执行一次ls命令

Nota:Cuando el programa se ejecuta en el tiempo especificado, el sistema envía un correo electrónico al usuario actual con el contenido de la ejecución. Si no deseas recibir dichos correos, agrega un espacio en cada línea y añade> /dev/null 2>&1y listo, por ejemplo:

20 03 * * * . /etc/profile;/bin/sh /var/www/runoob/test.sh > /dev/null 2>&1

Problema: el script no se ejecuta

Si usamos crontab para ejecutar un script programado y este no se ejecuta, pero al ejecutarlo directamente mediante un comando (por ejemplo, ./test.sh) funciona correctamente, se debe principalmente a que no se pueden leer las variables de entorno.

Solución:

  • 1. Todos los comandos deben escribirse en forma de ruta absoluta, por ejemplo:/usr/local/bin/docker。

  • 2. Usa el siguiente código al inicio del script de shell:

    #!/bin/sh

. /etc/profile
. ~/.bash_profile

  • 3. En/etc/crontabagrega variables de entorno, y antes del comando ejecutable agrega el comando. /etc/profile;/bin/sh, para que las variables de entorno tengan efecto, por ejemplo:

    20 03 * * * . /etc/profile;/bin/sh /var/www/runoob/test.sh
