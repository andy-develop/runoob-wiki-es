Métodos Limit y Skip de MongoDB

Método MongoDB Limit()

Si necesita leer una cantidad específica de registros de datos en MongoDB, puede usar el método limit() de MongoDB. Si desea omitir una cantidad específica de documentos y leer los datos, puede usar el método skip().

El método limit() se utiliza para limitar el número de documentos devueltos por los resultados de la consulta, mientras que el método skip() se utiliza para omitir una cantidad específica de documentos. Estos dos métodos suelen usarse juntos para implementar consultas paginadas o procesamiento por lotes en grandes conjuntos de datos.

Método limit()

El método limit() se utiliza para limitar el número de documentos devueltos por los resultados de la consulta.

Sintaxis

La sintaxis básica del método limit() es la siguiente:

db.collection.find().limit(<limit>)
  • <limit>Número de documentos a devolver.

Ejemplo

// Devuelve los primeros 10 documentos
db.myCollection.find().limit(10);

Método skip()

Además de usar el método limit() para leer una cantidad específica de datos, también podemos usar el método skip() para omitir una cantidad específica de datos. El método skip() también acepta un parámetro numérico como el número de registros a omitir.

El método skip() se utiliza para omitir una cantidad específica de documentos, logrando así consultas paginadas o por lotes.

Sintaxis

La sintaxis del método skip() es la siguiente:

db.collection.find().skip(<skip>)
  • <skip>Número de documentos a omitir.

Ejemplo

// Omite los primeros 10 documentos y devuelve los siguientes 10 documentos
db.myCollection.find().skip(10).limit(10);

Ejemplo

El siguiente ejemplo solo mostrará los datos del segundo documento.

>db.col.find({},{"title":1,_id:0}).limit(1).skip(1)
{ "title" : "Java 教程" }
>

Consulta paginada:

Ejemplo

// Primera página, 10 documentos por página
db.myCollection.find().skip(0).limit(10);

// Segunda página, 10 documentos por página
db.myCollection.find().skip(10).limit(10);

// Tercera página, 10 documentos por página
db.myCollection.find().skip(20).limit(10);

Nota:El parámetro predeterminado del método skip() es 0.

Precauciones

  • skip() 和 limit()Los métodos suelen utilizarse en combinación para implementar consultas paginadas. Sin embargo, usarlos en grandes conjuntos de datosskip()puede causar problemas de rendimiento, porque MongoDB necesita escanear y omitir una cantidad específica de documentos al ejecutar la consulta, por lo que se recomienda usarlo solo cuando sea necesarioskip()el método, y evitar usarlo continuamente en conjuntos de datos grandes.
  • Cuando se combinenskip() 和 limit(),skip()debelimit()usarse antes, para evitar comportamientos inesperados.

Mediante el uso dellimit() 和 skip()método, se puede implementar la paginación de los resultados de consultas en MongoDB, mejorando la flexibilidad y el rendimiento de las consultas.

    Observación complementaria: los métodos skip y limit solo son adecuados para paginación de pequeños volúmenes de datos. Si son millones, la eficiencia será muy baja, porque el método skip cuenta los datos uno por uno. Se recomienda usar where_limit.

    Después de consultar algunos materiales, descubrí que todos dicen lo mismo:

    No use Skip para consultas a la ligera; de lo contrario, cuando el volumen de datos sea grande, el rendimiento caerá drásticamente. Esto se debe a que Skip cuenta los datos uno por uno; cuando son muchos, naturalmente se vuelve lento.

    Entonces, ¿debería evitarse el uso de Skip? ¿Cómo evitarlo? Primero revisemos la solución de paginación por marca de tiempo en la paginación SQL. Este método utiliza la naturaleza ordenada de los campos y consultas para obtener datos, lo que puede evitar directamente una gran cantidad de conteos. Es decir, si se puede agregar tal condición, la eficiencia de la consulta mejorará. ¿Es realmente así? Vamos a verificarlo:

    Aquí supongamos que consultamos el dato número 100001, cuyo valor de Amount es: 2399927. Escribimos dos declaraciones respectivamente de la siguiente manera:

    b.test.sort({"amount":1}).skip(100000).limit(10)  //183ms
db.test.find({amount:{$gt:2399927}}).sort({"amount":1}).limit(10)  //53ms

    El resultado ya está adjunto en los comentarios. Es obvio que el rendimiento del segundo es un tercio del primero; la diferencia es muy grande. También confirma la teoría de que Skip tiene baja eficiencia.

    limit(n) se utiliza para especificar el número de registros a mostrar, mientras que skip(n) se utiliza para especificar cuántos registros omitir desde el primer registro entre los que cumplen la condición. Estas dos funciones pueden usarse de forma intercambiable.

    Por ejemplo: find({},{age:1,_id:0}).limit(2).skip(1), entre los documentos que cumplen la condición, se deben mostrar dos documentos, y la posición de visualización comienza después de omitir el primer registro. Esto no es muy fácil de entender.

    Si se escribe find({},{age:1,_id:0}).skip(1).limit(2), entre los documentos que cumplen la condición, primero se omite el primer documento y luego se muestran dos documentos. Así es más fácil de entender.
