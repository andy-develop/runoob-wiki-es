Manual completo de comandos de Ollama

Este capítulo presenta los comandos de ejecución relacionados con Ollama, incluyendo instalación, gestión de modelos, parámetros de ejecución, Modelfile, API REST, variables de entorno y resolución de problemas comunes, todo basado en Ollama 0.17.x.

Instalación y arranque

En las tres plataformas hay un método de instalación estándar. Una vez instalado, Ollama se ejecuta automáticamente como servicio en segundo plano y escucha en127.0.0.1:11434。

PlataformaMétodo de instalaciónDescripción
macOSbrew install ollamaTambién se puede descargar el paquete de instalación dmg desde el sitio web oficial
Linuxcurl -fsSL https://ollama.com/install.sh | shScript oficial de un clic, configura automáticamente el servicio systemd
WindowsDescargar el paquete de instalación desde el sitio web oficialInstalar mediante el asistente, se registra automáticamente como servicio del sistema
Dockerdocker run -d -v ollama:/root/.ollama -p 11434:11434 ollama/ollamaVolumen de datos: Ollama guarda los modelos de forma persistente

En la mayoría de los casos no es necesario iniciar el servicio manualmente, pero se utiliza para solucionar problemas y cambiar temporalmente la configuración.ollama serve。

Ejemplo

# Inicia el servicio en primer plano, los registros se imprimen directamente en la terminal, es lo más usado para solucionar problemas
ollama serve

# Verifica si el servicio está listo: si devuelve "Ollama is running", todo es normal
curl http://localhost:11434

Si indica que el puerto está ocupado, significa que el servicio en segundo plano ya está en ejecución. En este caso, ejecutar `ollama serve` en otra terminal dará un error, lo cual es normal; simplemente use la línea de comandos o la API.

Tabla completa de comandos de gestión de modelos

La gestión de modelos es la parte principal de la línea de comandos de Ollama; hay alrededor de diez comandos, todos listados en la siguiente tabla.

ComandoFunciónEjemplo
ollama pull <model>Descarga un modelo desde el repositorio de modelos; si no se especifica una etiqueta, por defecto se obtiene `latest`ollama pull qwen3.5:4b
ollama run <model>Ejecuta un modelo de forma interactiva; si no está local, lo descarga automáticamenteollama run qwen3.5
ollama list / ollama lsLista los modelos locales, su tamaño y fecha de modificaciónollama list
ollama show <model>Muestra los detalles del modelo: parámetros, plantilla, aviso del sistema, etc.ollama show qwen3.5
ollama psMuestra los modelos cargados en memoria y el tiempo de vida restanteollama ps
ollama stop <model>Detiene y descarga inmediatamente el modelo en ejecuciónollama stop qwen3.5
ollama cp <src> <dst>Copia o renombra un modeloollama cp qwen3.5 runoob-clone
ollama rm <model>Elimina un modelo local y libera espacio en discoollama rm qwen3.5:0.8b
ollama create <name> -f <file>Crea un modelo personalizado basado en un Modelfileollama create runoob-coder -f Modelfile
ollama push <model>Envía el modelo a un repositorio remoto; requiere iniciar sesión primeroollama push myteam/runoob-coder
ollama serveInicia el servicio en segundo plano, normalmente se ejecuta automáticamente con el sistemaollama serve

La combinación de mayor uso diario son los cuatro comandos `run`, `list`, `ps` y `rm`: ejecutar modelos, revisar el inventario, ver la memoria y liberar espacio.

Ejemplo

# Descarga un modelo de una especificación específica
ollama pull qwen3.5:0.8b

# Crea una copia y cambia su nombre
ollama cp qwen3.5 runoob-clone

# Después de confirmar que la copia se hizo correctamente, elimina la especificación que ya no se necesita
ollama rm qwen3.5:0.8b

`rm` elimina el archivo de modelo correspondiente a esa etiqueta. Si otras etiquetas comparten los mismos pesos subyacentes (blobs), el espacio en disco solo se libera realmente cuando se elimina la última etiqueta que lo referencie.

El comando run y el modo interactivo

`run` funciona tanto como herramienta de preguntas y respuestas de una sola vez, como para entrar en modo interactivo de conversación de múltiples turnos, y también admite cambiar parámetros en tiempo de ejecución.

Parámetros de línea de comandos

Los parámetros se escriben después del nombre del modelo, solo afectan a la ejecución actual y no se guardan en la configuración del modelo.

Ejemplo

# Conversación interactiva
ollama run qwen3.5

# Pregunta y respuesta única: el aviso sigue al nombre del modelo, y sale automáticamente después de responder
ollama run qwen3.5 "Presenta runoob (Tutorial para novatos) en una frase"

# Muestra estadísticas de tokens: tiempo total, tokens por segundo y otras métricas de rendimiento
ollama run qwen3.5 --verbose

# Fuerza al modelo a generar salida en formato JSON
ollama run qwen3.5 --format json

# Aumenta la ventana de contexto (en tokens)
ollama run qwen3.5 --num-ctx 8192

# Intenta colocar la mayor cantidad posible de capas del modelo en la GPU (999 significa sin límite)
ollama run qwen3.5 --num-gpu 999

Comandos de barra diagonal dentro del modo interactivo

Después de entrar en el modo interactivo, los comandos que comienzan con barra diagonal se usan para ajustar el estado de la sesión; estos ajustes solo afectan a la sesión actual.

ComandoFunción
/set parameter <name> <value>Ajusta temporalmente los parámetros de inferencia, como `temperature`
/set system <prompt>Establece temporalmente el aviso del sistema
/show infoMuestra información del modelo actual
/show modelfileMuestra el Modelfile correspondiente al modelo actual
/save <name>Guarda la configuración de la sesión actual como un nuevo modelo
/load <name>Carga un modelo o sesión guardados
/clearLimpia el contexto de la conversación actual y comienza de nuevo
/byeSale del modo interactivo

Si quieres conservar a largo plazo los parámetros ajustados con los comandos de barra diagonal, usa `/save` para guardarlos como un nuevo modelo; detrás de esto se genera un Modelfile.

Otra forma rápida de salir del modo interactivo es presionar Ctrl+D, que tiene el mismo efecto que `/bye`.

Modelos personalizados con Modelfile

Modelfile utiliza una sintaxis similar a Dockerfile para empaquetar "modelo base + parámetros + aviso del sistema" en un nuevo modelo.

Ejemplo

# Ruta de archivo: Modelfile
# FROM especifica el modelo base (obligatorio), también puede ser la ruta de un archivo GGUF local
FROM qwen3.5

# Parámetros de inferencia comunes (opcionales)
PARAMETER temperature 0.2
PARAMETER num_ctx 8192

# Aviso del sistema, determina el rol y comportamiento del modelo (opcional)
SYSTEM Eres un ingeniero de Python senior, genera código conciso, tipado y comprobable.

Ejemplo

# Construye un nuevo modelo con Modelfile
ollama create runoob-coder -f Modelfile

# Ejecuta como un modelo normal
ollama run runoob-coder "Escribe un quicksort, con pruebas"

Para importar pesos GGUF locales solo necesitas apuntar `FROM` a la ruta del archivo; se usa a menudo para ejecutar archivos de modelo descargados de la comunidad de código abierto.

Ejemplo

# Ruta de archivo: Modelfile
# FROM apunta al archivo de pesos GGUF local
FROM ./model-file.gguf

Todas las directivas de Modelfile se muestran en la siguiente tabla; las tres primeras líneas son la combinación más utilizada.

DirectivaEfecto¿Obligatorio?
FROMEspecifica el modelo base o la ruta de archivo GGUFObligatorio
PARAMETEREstablece parámetros de inferencia: `temperature`, `num_ctx`, `top_p`, `stop`, etc.Opcional
SYSTEMEstablece el aviso del sistemaOpcional
TEMPLATEPersonaliza la plantilla de aviso de conversaciónOpcional
ADAPTERCarga adaptadores LoRAOpcional
MESSAGEProporciona ejemplos de conversación predefinidos para guiar con pocos ejemplos (few-shot)Opcional
LICENSEDeclara la licencia del modeloOpcional

Si quieres modificar un modelo existente sin empezar desde cero, primero ejecutaollama show --modelfile 模型名exporta la receta completa, modifícala y luego ejecuta `create`.

Referencia rápida de la API REST

Después de iniciar el servicio de Ollama, escucha por defecto enhttp://localhost:11434, todo lo que puede hacer la CLI también lo puede hacer la API.

EndpointMétodoFunción
/api/generatePOSTGeneración de texto de un solo turno, retorno en streaming por defecto
/api/chatPOSTConversación de múltiples turnos, pasa el historial mediante el arreglo `messages`
/api/embedPOSTGenera incrustaciones (embeddings) de texto para su uso en recuperación RAG
/api/tagsGETLista los modelos locales, corresponde a `ollama list`
/api/showPOSTMuestra los detalles del modelo, corresponde a `ollama show`
/api/pullPOSTDescarga un modelo, corresponde a `ollama pull`
/api/deleteDELETEElimina un modelo, corresponde a `ollama rm`

Ejemplo

# Generación de un solo turno (streaming)
curl http://localhost:11434/api/generate -d '{
  "model": "qwen3.5",
"prompt": "Escribe un Hola Mundo en Python"
}'

# Conversación de múltiples turnos
curl http://localhost:11434/api/chat -d '{
  "model": "qwen3.5",
"messages": [{"role": "user", "content": "Explica qué es una API REST"}]
}'

# Genera incrustaciones vectoriales
curl http://localhost:11434/api/embed -d '{
  "model": "nomic-embed-text",
"input": "El contenido de tu texto"
}'

# Lista los modelos locales
curl http://localhost:11434/api/tags

# Muestra los detalles del modelo
curl http://localhost:11434/api/show -d '{"model": "qwen3.5"}'

# Elimina un modelo
curl -X DELETE http://localhost:11434/api/delete -d '{"model": "qwen3.5"}'

Interfaz compatible con OpenAI

Ollama proporciona un endpoint compatible con OpenAI/v1/chat/completionsEl código existente del ecosistema OpenAI se puede usar directamente apuntando base_url a local.

Ejemplo

# 文件路径：openai_compat.py
from openai import OpenAI

# base_url 指向本地 Ollama；api_key 任意非空字符串即可
client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")

resp = client.chat.completions.create(
    model="qwen3.5",  # 本地已下载的模型名
    messages=[{"role": "user", "content": "你好，请介绍一下 runoob"}],
)
print(resp.choices[0].message.content)
$ python3 openai_compat.py
你好！runoob（菜鸟教程）是一个面向初学者的编程学习网站，提供大量免费的基础技术教程。

Referencia rápida de variables de entorno

Las variables de entorno son la forma principal de configurar el comportamiento del servicio Ollama. Después de cambiarlas, es necesario reiniciar el servicio para que surtan efecto.

变量说明默认值
OLLAMA_HOSTDirección de escucha del servicio; 0.0.0.0 indica que se permite el acceso desde la red de área local.127.0.0.1:11434
OLLAMA_MODELSRuta de almacenamiento de modelos, útil al cambiar a un disco más grande.~/.ollama/models
OLLAMA_NUM_GPUNúmero de capas del modelo que se colocan en la GPU; 999 significa todas.自动
OLLAMA_NUM_PARALLELNúmero de solicitudes concurrentes para el mismo modelo.自动
OLLAMA_MAX_LOADED_MODELSNúmero máximo de modelos que permanecen en memoria al mismo tiempo.自动
OLLAMA_FLASH_ATTENTIONHabilitar Flash Attention; se recomienda activarlo para contextos largos.关闭
OLLAMA_KEEP_ALIVETiempo de inactividad del modelo antes de descargarlo de la memoria.5m
OLLAMA_DEBUGActivar registros de depuración para mostrar información de ejecución más detallada.关闭

Ejemplo

# 允许局域网访问 + 模型挪到数据盘
export OLLAMA_HOST=0.0.0.0:11434
export OLLAMA_MODELS=/data/ollama-models
ollama serve

Establecer OLLAMA_KEEP_ALIVE en 0 significa que el modelo se descarga inmediatamente después de cada solicitud, ahorrando memoria pero requiriendo recargar el modelo en cada solicitud; para mantenerlo residente, establézcalo en -1. El formato de este valor varía según la versión; consulte ollama serve --help y la documentación oficial.

Solución de problemas comunes

Cuando encuentre una anomalía, primero consulte la siguiente tabla para identificarla. La mayoría de los problemas pertenecen a tres categorías: "nombre del modelo incorrecto, servicio no iniciado, recursos insuficientes".

问题排查思路
VRAM / RAM insuficiente (OOM).Cambie a una especificación de modelo más pequeña o a una precisión de cuantización más baja, por ejemplo, use 4b en lugar de 9b.
提示 model not foundVerifique que el nombre del modelo y la etiqueta sean correctos. La etiqueta se separa con dos puntos, como qwen3.5:4b en lugar de qwen3.5-4b.
connection refusedConfirmar si el servicio está en ejecución y comprobar si el puerto 11434 está ocupado.
响应速度慢Usa `ollama ps` para revisar la columna PROCESSOR y confirma si el modelo realmente se ejecuta en la GPU; reduce adecuadamente el valor de num_ctx.
Ofuscación de modelos de múltiples versionesSi no se especifica el tag, se elegirá la versión "más reciente" según las reglas internas; se recomienda indicar siempre explícitamente el tag completo.
