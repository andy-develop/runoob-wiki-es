Ollama: Parámetros de conversación y generación

Gestión de modelos de Ollama

En este capítulo explicaremos los comandos de gestión de modelos de Ollama: descargar, ver, copiar, eliminar, así como el mecanismo de residencia de los modelos en memoria.

Descargar modelos: ollama pull

El comando pull solo descarga el modelo sin iniciar una conversación, ideal para preparar el modelo con antelación.

Descargar la etiqueta predeterminada (latest):

ollama pull qwen3.5

Descargar una etiqueta de especificación específica:

ollama pull qwen3.5:4b

Tras ejecutarlo, verás la salida estándar del proceso de descarga:

$ ollama pull qwen3.5:4b
pulling manifest
pulling 87497c5f0e8f... 100% |████████████████████| 3.4GB
verifying sha256 digest
writing manifest
success

Si la descarga se interrumpe no hay que empezar de cero; Ollama verifica y almacena por capas, y al volver a ejecutar el mismo comando se reanudarán automáticamente las capas incompletas.

Cabe añadir que ollama run incluye la lógica de pull integrada: la primera vez que se ejecuta un modelo, la descarga y la carga se completan automáticamente, por lo que en el uso diario a menudo no es necesario ejecutar pull por separado.

Las diferentes etiquetas de especificación corresponden a distintos archivos de modelo predefinidos por el equipo oficial; al hacer pull no se puede especificar una precisión de cuantización adicional. Si quieres comprimir un modelo grande a un tamaño pequeño, necesitas usar el comando create para cuantizar, lo cual pertenece al capítulo de personalización de Modelfile.

Ver modelos locales: list y show

list muestra todos los modelos locales y el espacio en disco que ocupan; es el comando de inventario más utilizado.

Listar modelos locales:

ollama list

Por ejemplo:

$ ollama list
NAME               ID            SIZE      MODIFIED
qwen3.5:0.8b       9e3f4b3a1c2d  1.0GB     5 minutes ago
qwen3.5:4b         b1c7d9e2f3a4  3.4GB     2 days ago
qwen3.5:latest     a8b2c9d3e4f5  6.6GB     2 hours ago

Las cuatro columnas son: nombre del modelo, huella de versión, espacio en disco y fecha de última modificación. Cuando el disco esté al límite, lo más directo es revisar la columna SIZE.

Si quieres ver en detalle un modelo concreto, usa el comando show:

# 查看模型详情：能力、参数、系统提示词、许可证等
ollama show qwen3.5

show responde varias preguntas típicas: qué capacidades soporta este modelo (conversación, visión, llamada a herramientas), cuáles son los parámetros de generación predeterminados, qué dice el prompt del sistema y cuál es el tamaño de la ventana de contexto.

También tiene un uso avanzado: exportar la configuración completa del modelo a un Modelfile:

Ejemplo

# Exporta la receta del modelo; puedes modificarla y reconstruir tu propio modelo a partir de ella
ollama show --modelfile qwen3.5

Esta dinámica de "ver la receta - modificar - reconstruir" se desarrollará por completo en el capítulo de personalización de Modelfile.

Ver modelos en ejecución: ollama ps

list muestra el disco; ps muestra la memoria: qué modelo está cargado, cuánto ocupa y cuándo se descargará.

Ejemplo

# Lista los modelos actualmente cargados en memoria/memoria de video
ollama ps
$ ollama ps
NAME             ID            SIZE      PROCESSOR    CONTEXT    UNTIL
qwen3.5:9b       a8b2c9d3e4f5  9.6GB     100% GPU     131072     4 minutes from now

El significado de cada columna es el siguiente:

Nombre de columnaSignificado
NAME / IDNombre del modelo y huella de versión, igual que en list
SIZEMemoria total que ocupa actualmente el modelo (incluye RAM y memoria de video)
PROCESSORUbicación de carga: 100% GPU significa que está completamente en la tarjeta gráfica; 100% CPU significa que está completamente en memoria; si aparece una proporción como 48%/52% CPU/GPU, indica que la memoria de video es insuficiente y el modelo se ha dividido
CONTEXTTamaño de la ventana de contexto actualmente asignada
UNTILTiempo restante para la descarga automática (cuenta regresiva de keep-alive)

La columna PROCESSOR es la primera puerta de entrada para diagnosticar "por qué el modelo va lento": si no es 100% GPU, significa que el modelo no está completamente cargado en la memoria de video. Los métodos concretos de optimización del rendimiento se tratan en detalle en el capítulo de GPU y rendimiento.

Copiar y renombrar: ollama cp

cp asigna un nuevo nombre a un modelo existente; se usa a menudo para renombrar o conservar una instantánea.

Ejemplo

# Copia un modelo con un nuevo nombre
ollama cp qwen3.5:4b runoob-test

# Úsalo como un modelo normal
ollama run runoob-test

Tiene un truco avanzado muy práctico: "prestar el nombre" al modelo.

Algunas herramientas tienen el nombre del modelo fijo (por ejemplo, gpt-3.5-turbo); usando cp para copiar el modelo local con ese nombre, estas herramientas pueden usar directamente el modelo local:

Ejemplo

# Copia el modelo local con el nombre que espera la herramienta
ollama cp qwen3.5 gpt-3.5-turbo

cp se completa casi al instante, porque solo crea una nueva entrada en la lista de nombres de modelos que apunta al archivo del modelo original; no copia una segunda copia de varios GB en el disco.

Eliminar modelos y limpieza de disco: ollama rm

rm elimina modelos locales; es la solución al problema de que la biblioteca de modelos "solo entra y no sale".

Ejemplo

# Elimina el modelo especificado
ollama rm qwen3.5:0.8b
$ ollama rm qwen3.5:0.8b
deleted 'qwen3.5:0.8b'

El flujo recomendado para limpiar el disco es: primero usa ollama list para encontrar los modelos que sean grandes y ya no se usen, y luego elimínalos uno a uno con rm.

Si varias etiquetas comparten el mismo conjunto de archivos subyacentes, eliminar una de ellas no afecta al uso normal de las demás.

Recuerda también gestionar los modelos a los que se les "prestó" un nombre con cp: después de eliminar el modelo original, las copias con el nombre prestado siguen existiendo y ocupando espacio; no dejes que se conviertan en agujeros negros invisibles de disco.

Detener modelos y el mecanismo de residencia keep-alive

Primero veamos un diagrama del ciclo de vida del modelo; así quedará claro de un vistazo en qué paso actúa cada comando de gestión.

El mecanismo clave es keep-alive: cuando termina la conversación, el modelo no se descarga inmediatamente, sino que permanece residente en memoria o memoria de video durante 5 minutos por defecto.

Si se realiza una nueva solicitud dentro de esos 5 minutos, la respuesta ya no tendrá la espera de carga del modelo; si no hay nuevas solicitudes pasado ese tiempo, se descarga automáticamente y se libera la memoria.

Si quieres que el modelo libere recursos de inmediato, usa el comando stop para descargarlo manualmente:

Ejemplo

# Descarga inmediatamente el modelo especificado
ollama stop qwen3.5:4b

Hay tres formas de ajustar la duración de residencia:

MétodoProcedimientoEscenario aplicable
Cambiar el valor predeterminado globalConfigurar la variable de entorno OLLAMA_KEEP_ALIVE, por ejemplo 30m, 2hEl servidor desea una política de residencia unificada
Especificar por solicitudAl llamar a la API, pasar el parámetro keep_alive; por ejemplo, -1 indica residencia permanente sin descargaLa capa de aplicación trata de manera diferenciada a los distintos modelos
Descarga inmediataollama stop nombre_del_modeloLiberar temporalmente memoria de video para otras tareas
