Personalización de atajos de teclado de Pi Agent

Los atajos de teclado de Pi Agent son completamente personalizables. Este capítulo presenta la configuración predeterminada de atajos y cómo crear tu propio esquema de atajos.

Archivo de configuración

El archivo de configuración de atajos se encuentra en~/.pi/agent/keybindings.json。

Después de modificar, ejecuta/reloadpara que surta efecto, sin necesidad de reiniciar.

Formato de atajos de teclado

El formato de atajos estecla modificadora + teclaLos modificadores incluyen ctrl, shift, alt, super, y se pueden combinar.

Entre ellos, super requiere que la terminal pueda informar esa tecla modificadora de forma independiente (generalmente depende del protocolo de teclado de Kitty) para que funcione; puede no funcionar en terminales no compatibles.

Las teclas soportadas se clasifican en las siguientes categorías:

CategoríaValorEjemplo
Letrasa-zctrl+b、alt+d
Números0-9alt+1
Teclas de funciónf1-f12f2
Teclas de direcciónup、down、left、rightalt+left
Teclas especialesescape、enter、tab、space、backspace、delete、home、end、pageUp、pageDownshift+enter
Símbolos` - = [ ] ; ' , . / etc.ctrl+]、ctrl+-

En el archivo de configuración, los modificadores se escriben en minúsculas (por ejemplo, ctrl+shift+p); en las tablas del texto se suele escribir Shift+Ctrl+P. Ambos son equivalentes.

Referencia rápida de atajos predeterminados

Las siguientes cuatro tablas enumeran los enlaces predeterminados de fábrica por área funcional, como base de referencia para la personalización.

Este capítulo solo enumera los enlaces comunes; ctrl+], ctrl+alt+], pageUp/pageDown, alt+y, ctrl+z y las teclas del selector de sesiones no están incluidas. La lista completa se puede ver con /hotkeys en el modo interactivo.

Configuración personalizada de atajos

Solo tienes que enumerar en keybindings.json las operaciones que deseas sobrescribir; las operaciones no enumeradas mantienen su valor predeterminado.

Escribe el valor de un enlace como un array vacío, por ejemplo"tui.altScreen.pageUp": [], para deshabilitar completamente ese atajo.

Estilo Emacs

Si estás acostumbrado a los atajos de Emacs, puedes usar la siguiente configuración en~/.pi/agent/keybindings.jsonusar la siguiente configuración:

Ejemplo

{
  "tui.editor.historyPrevious": "ctrl+p",
  "tui.editor.historyNext": "ctrl+n",
  "tui.editor.cursorUp": ["up"],
  "tui.editor.cursorDown": ["down"],
  "tui.editor.cursorLeft": ["left", "ctrl+b"],
  "tui.editor.cursorRight": ["right", "ctrl+f"],
  "tui.editor.cursorWordLeft": ["alt+left", "alt+b"],
  "tui.editor.cursorWordRight": ["alt+right", "alt+f"],
  "tui.editor.deleteCharForward": ["delete", "ctrl+d"],
  "tui.editor.deleteCharBackward": ["backspace", "ctrl+h"],
  "tui.input.newLine": ["shift+enter", "ctrl+j"]
}

Las acciones de historial historyPrevious e historyNext no tienen enlace predeterminado; están pensadas para navegar por el historial de envíos y también cambian de entrada histórica en entradas multilínea.

Después de enlazar ctrl+p a la entrada histórica anterior, cuando el área de edición tiene el foco, Ctrl+P será capturado por este enlace de historial; el cambio al modelo siguiente deja de funcionar temporalmente en ese escenario.

Ctrl+P en listas de selección como el selector de modelo no se ve afectado y sigue ejecutando la acción propia del selector.

Estilo Vim

Si estás acostumbrado a las teclas de dirección de Vim, puedes usar la siguiente configuración:

Ejemplo

{
  "tui.editor.cursorUp": ["up", "alt+k"],
  "tui.editor.cursorDown": ["down", "alt+j"],
  "tui.editor.cursorLeft": ["left", "alt+h"],
  "tui.editor.cursorRight": ["right", "alt+l"],
  "tui.editor.cursorWordLeft": ["alt+left", "alt+b"],
  "tui.editor.cursorWordRight": ["alt+right", "alt+w"]
}

Aquí se eligen alt+h/j/k/l para evitar enlaces integrados como Ctrl+H/Ctrl+D, por eso se usa la familia Alt.

La configuración de atajos de Pi Agent sobrescribe los valores predeterminados.

Cada operación puede estar enlazada a uno o más atajos.

Las operaciones no enumeradas en el archivo de configuración mantienen sus atajos predeterminados.

Ver todos los atajos

En el modo interactivo, usa el siguiente comando para mostrar todos los atajos y sus enlaces actuales:

/hotkeys

Fragmento de salida:

编辑器
  tui.editor.cursorUp            up
  tui.editor.cursorDown          down
  tui.editor.cursorWordLeft      alt+left, ctrl+left, alt+b
  tui.input.submit               enter
模型与推理
  app.model.select               ctrl+l
  app.model.cycleForward         ctrl+p
  app.model.cycleBackward        shift+ctrl+p

Las operaciones de atajos usan IDs con espacio de nombres, con el formato «módulo.acción».

Los ids sin espacio de nombres (como cursorUp, expandTools) en archivos de configuración de versiones antiguas se migrarán automáticamente a ids con espacio de nombres al iniciar, sin necesidad de modificación manual.

Este comando lista todas las acciones de atajos de teclado disponibles, los enlaces actuales y el área funcional a la que pertenecen; es la mejor forma de solucionar conflictos de atajos o encontrar el atajo de una función específica.

Teclas en modo de pantalla completa

用 --tui-mode fullscreenAl iniciar, el registro de conversación (transcript) se desplaza dentro de la ventana del terminal, mientras que el área de edición y la barra de estado inferior permanecen fijas.

En este momento, home, end, pageUp y pageDown sin teclas modificadoras se usan para desplazar el registro de conversación, mientras que sus variantes con ctrl siguen perteneciendo al editor.

En el modo normal, ambos grupos de teclas actúan sobre el editor.

El modo de pantalla completa también tiene búsqueda y navegación exclusivas: ctrl+shift+f busca en el registro de conversación, ctrl+up y ctrl+down saltan entre el mensaje marcado anterior y el siguiente.

La prioridad de los enlaces de desplazamiento en pantalla completa es mayor que la de los enlaces del editor, y aún se pueden ajustar mediante enlaces de acciones normales.

ctrl+pageUp、ctrl+pageDownEditorEditor
ctrl+shift+f (ctrl+f en Windows/WSL)No tiene efectoBuscar en el registro de conversación
