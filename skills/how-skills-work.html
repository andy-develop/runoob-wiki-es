Cómo funcionan los Skills

Quizás te preguntes: el agente no es humano, ¿cómo sabe qué puede hacer un Skill y cómo debe hacerlo?

La respuesta es muy sencilla: leyendo archivos.

Detrás de cada Skill hay un archivo de descripción, normalmente llamadoSKILL.md, como un manual de instrucciones.

El principio de funcionamiento de los Skills

Los Skills utilizan el método de divulgación progresiva (Progressive Disclosure), permitiendo que el agente cargue información con distintos niveles de detalle en diferentes fases. Este diseño permite que el agente gestione una gran cantidad de habilidades simultáneamente sin agotar el espacio de contexto.

Tres fases

La carga de habilidades por parte del agente se divide en las siguientes tres fases:

  • 1. Fase de descubrimiento (Discovery):Cuando comienza la conversación, el agente escanea todas las carpetas de habilidades disponibles y solo lee el nombre (name) y la descripción (description) de cada habilidad. Esta es la información más ligera y suficiente para que el agente determine si una habilidad puede ser relevante para la tarea actual.

  • 2. Fase de activación (Activation):

    Cuando el agente determina que la descripción de una habilidad coincide con la solicitud del usuario, carga el contenido completo del archivo SKILL.md en el contexto. En este momento, el agente lee las instrucciones y explicaciones completas.

  • 3. Fase de ejecución (Execution):El agente ejecuta la tarea siguiendo las instrucciones de SKILL.md. Durante este proceso, el agente puede invocar scripts adjuntos a la habilidad, leer materiales de referencia o utilizar otros recursos.

Ventajas de la carga progresiva

Fase Contenido cargado Tamaño típico
Fase de descubrimiento name + description Aproximadamente 100 tokens
Fase de activación SKILL.md completo Se recomienda no superar los 5000 tokens
Fase de ejecución Scripts, materiales de referencia, etc. Carga bajo demanda

Antes de ejecutar la tarea, el agente lee este manual para aclarar tres cosas:

  • ¿Qué puede hacer este Skill? (Descripción de capacidades)
  • ¿Qué necesito proporcionar para usarlo? (Parámetros de entrada)
  • ¿Qué reglas hay para hacer esto? (Restricciones del entorno y precauciones)

Después de leerlo, el agente sabe: "Ah, este Skill es adecuado para resolver el problema actual, voy a invocarlo."

Flujo de ejecución de Skill

  • Comenzando con la instrucción del usuario, primero se realiza el reconocimiento de la intención del Skill, decidiendo si se entra en la ruta de ejecución controlada.

  • Tras activar el Skill, el sistema carga SKILL.md, establece los permisos de herramientas y los límites de comportamiento, y luego razona en combinación con el contexto.

  • Solo se invocan las herramientas externas permitidas cuando realmente es necesario; de lo contrario, la lógica se completa dentro de las reglas.

  • El resultado final se genera tras la integración de restricciones, y la siguiente entrada del usuario desencadena una nueva ronda completa del proceso.

Proceso de trabajo de los Skills

Después de que el usuario presenta su solicitud, el Agente primero comprende el contenido de la tarea y luego analiza qué capacidades (Skills) debería utilizar para completar el trabajo.

Un Skill puede entenderse como un módulo de capacidad independiente o un plugin, como consulta del clima, búsqueda, procesamiento de archivos, acceso a bases de datos, etc.

El Agente es responsable de pensar y decidir, el Skill se encarga de ejecutar las acciones; una vez completada la ejecución, el resultado se devuelve al Agente, quien lo organiza en un resultado fácil de entender para el usuario y lo genera.

Todo el proceso forma un ciclo cerrado completo: comprensión → decisión → ejecución → devolución de resultados.

Paso Fase Acciones internas del Agente Ejemplo
① El usuario realiza una solicitud Recibir la tarea en lenguaje natural "Ayúdame a consultar el clima de hoy en Pekín"
② Comprender la intención del usuario Analizar qué quiere hacer realmente el usuario y extraer los parámetros Acción: consulta; tipo: clima; ubicación: Pekín
③ Formular el plan de ejecución Dividir la tarea en pasos Buscar servicio meteorológico → Obtener datos del clima → Organizar resultados
④ Seleccionar el Skill Elegir el módulo de capacidad más adecuado Seleccionar el Skill de clima (Weather Skill)
⑤ Ejecutar el Skill Invocar herramientas externas o API Solicitar la interfaz meteorológica
⑥ Obtener el resultado de la ejecución Recibir los datos devueltos por el Skill Temperatura, humedad, calidad del aire
⑦ Generar la respuesta final Organizar y convertir a lenguaje natural "Hoy en Pekín hace sol, 18°C a 30°C"
⑧ Devolver al usuario Generar el resultado final El usuario ve la respuesta completa
