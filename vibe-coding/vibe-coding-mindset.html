Mentalidad de Vibe Coding

Diferencias de pensamiento entre la programación tradicional y Vibe Coding

La trayectoria de pensamiento de la programación tradicional es:

Tengo una necesidad → ¿Qué sintaxis necesito? → ¿Cómo escribo el código? → Escríbelo → Depurar

La trayectoria de pensamiento de Vibe Coding es:

我有需求 → 我该怎么描述这个需求？→ AI 生成代码 → 我验证结果 → 继续调整描述

La diferencia clave es: la programación tradicional esescribir código, Vibe Coding esdescribir requisitos。

Un ejemplo para sentir la diferencia

Supongamos que quieres hacer unformulario de registro de usuario, que valide nombre de usuario y contraseña.

Pensamiento de programación tradicional:

用什么框架？React 还是 Vue？
表单验证库用哪个？Formik 还是 React Hook Form？
正则表达式怎么写？
状态管理怎么设计？

Pensamiento de Vibe Coding:

¿Qué necesita hacer el usuario en este formulario?
¿Qué campos de entrada hay? ¿Qué reglas de validación existen?
¿Qué debería mostrarse cuando falla la validación?
¿A dónde debería redirigir después de una validación exitosa?

El primero se centra en cómo implementarlo; el segundo, en qué necesita el usuario.

Vibe Coding eleva tu pensamiento de la implementación técnica al diseño de producto. No necesitas saber cómo escribir expresiones regulares, pero debes conocerel nombre de usuario debe tener al menos 3 caracteresesta regla.

Tres ideas centrales de Vibe Coding

Idea 1: Eres el director, no el actor

El director no necesita interpretar cada papel personalmente; lo que necesita es:

  • Saber qué debe transmitir esta escena (requisitos claros).

  • Poder juzgar si el actor actúa bien (validación de resultados).

  • Poder dar instrucciones de ajuste concretas (retroalimentación precisa).

En Vibe Coding, la IA es tu equipo de actores y tú eres el director.

  • Lo incorrecto: dejar que la IA improvise, sin establecer límites ni revisar los resultados, y terminar con algo que "se ve bien pero no sirve".

  • Lo correcto: dar a la IA un escenario, un rol y unos estándares claros, revisar cada salida y dar retroalimentación específica sobre lo que no te satisfaga.

Idea 2: Iterar es mejor que acertar a la primera

El desarrollo tradicional busca escribir bien a la primera; Vibe Coding busca iterar rápido hasta lograrlo.

Un proceso de iteración típico de Vibe Coding:

第 1 轮：先让 AI 做一个能跑的版本，即使很简陋
第 2 轮：添加核心功能，让它能用
第 3 轮：修复明显的 bug 和体验问题
第 4 轮：优化细节和边缘情况
第 5 轮：添加测试和文档

En cada ronda tú validas, das retroalimentación y ajustas; en cada ronda la IA mejora sobre la base de la ronda anterior.

Principios clave:Primero que funcione, luego que esté bien, y al final que sea refinado.

Idea 3: La capacidad de describir > la capacidad de programar

En Vibe Coding, tu habilidad más importante no es escribir código, sino describir claramente lo que quieres.

Una buena descripción de requisitos incluye cinco elementos:

ElementoDescripciónEjemplo
ObjetivoQué se va a hacerCrear un formulario de inicio de sesión de usuario
RestriccionesQué limitaciones hayUsar React + TypeScript, sin librerías de UI de terceros
EntradaQué datos recibeNombre de usuario (3-20 caracteres) y contraseña (más de 6 caracteres)
SalidaQué resultado produceValidar llamando a la API; si falla, mostrar un mensaje de error
Criterios de aceptaciónQué se considera aprobadoSi el nombre de usuario está vacío y se hace clic en enviar, mostrar "Por favor, introduce el nombre de usuario"

Práctica: experimenta la diferencia entre dos formas de pensar

A continuación hay un ejercicio práctico. Con la misma tarea, descríbela de dos maneras diferentes y observa cómo cambia el resultado de la IA.

Método 1: Descripción vaga (común en principiantes)

Ayúdame a hacer un contador

La IA puede darte un contador simple, pero podría:

  • No tener estilos; ser solo un número y un botón.

  • Usar un framework que no conoces.

  • No considerar los números negativos.

  • No tener función de reinicio.

Método 2: Descripción estructurada (estilo Vibe Coding)

帮我做一个计数器组件，要求：
- 目标：一个带加减按钮的数字计数器
- 约束：使用 HTML + CSS + 原生 JavaScript，单文件
- 输入：初始值 0，最小值 0（不能减到负数），最大值 99
- 输出：显示当前数字，两个按钮（+ 和 -），一个重置按钮
- 验收标准：
  - 点 + 数字加 1，到 99 后按钮变灰不可点击
  - 点 - 数字减 1，到 0 后按钮变灰不可点击
  - 点重置回到 0
  - 数字变化时有短暂的放大动画
  - 深色背景，白色卡片，圆角设计

Envía ambas descripciones a la IA por separado y compara las diferencias en los resultados.

Descubrirás que el código obtenido con una descripción estructurada tiene una calidad y usabilidad mucho mayores que con una descripción vaga.

La IA no adivina lo que piensas. Cuanto más específica sea tu descripción, más se ajustará su resultado a lo esperado. Esto no es una limitación de la IA, sino el límite de tu capacidad.

Cuándo usar Vibe Coding y cuándo no

Vibe Coding no es una panacea. La siguiente comparación de escenarios te ayuda a decidir:

Adecuado para Vibe CodingNo adecuado para Vibe Coding
Validación de prototipos, generar MVP rápidamenteSistemas centrales con requisitos extremos de rendimiento y seguridad
Lógica de negocio tipo CRUDMódulos de bajo nivel que requieren control preciso de memoria y algoritmos
Componentes de UI y maquetación de páginasCambios que requieren comprensión profunda de una base de código compleja existente
Transformación y formateo de datosCódigo financiero/médico que implica cumplimiento normativo y legal
Generación de casos de pruebaAlgoritmos originales que requieren protección de patente
Generación de documentación y comentariosMódulos de cifrado que requieren auditoría de seguridad

Cómo describir un bug a la IA

Cuando el código tiene problemas, describir el bug a la IA también requiere pensamiento estructurado.

No digas "este código tiene un problema", sino:

我在运行以下代码时遇到了问题：
[粘贴代码]

预期行为：点击按钮后数字应该加 1
实际行为：点击按钮后数字没有变化，控制台报错：
  Uncaught TypeError: count is not defined

我的环境：Chrome 浏览器，直接在 HTML 文件中运行

Esta descripción incluye:

  • Código: la IA puede ver el contexto completo.

  • Esperado vs real: la IA sabe cuál es el objetivo y dónde está la brecha.

  • Mensaje de error: es la pista más valiosa; la IA puede localizar el problema directamente.

  • Entorno: ayuda a la IA a dar una solución específica.
