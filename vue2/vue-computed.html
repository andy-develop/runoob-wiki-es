Vue.js Propiedades computadas

Palabras clave de las propiedades computadas:computed。

Las propiedades computadas son muy útiles al manejar lógica compleja.

Puedes ver el siguiente ejemplo de inversión de cadena:

Ejemplo 1

<div id="app"> {{ message.split('').reverse().join('') }} </div>

Pruébalo »

En el ejemplo 1, la plantilla se vuelve muy compleja y no es fácil de entender.

A continuación, veamos un ejemplo que utiliza propiedades computadas:

Ejemplo 2

<div id="app"> <p>Cadena original: {{ message }}</p> <p>Cadena invertida después del cálculo: {{ reversedMessage }}</p> </div> <script>var vm = new Vue({ el: '#app', data: { message: 'Runoob!' }, computed: { // 计算属性的 getter reversedMessage: function () { // `this` 指向 vm 实例 return this.message.split('').reverse().join('') } } })</script>

Pruébalo »

En el ejemplo 2 se declara una propiedad computada `reversedMessage`.

La función proporcionada se usará como getter de la propiedad `vm.reversedMessage`.

`vm.reversedMessage` depende de `vm.message`; cuando `vm.message` cambia, `vm.reversedMessage` también se actualiza.

computed vs methods

Podemos usar `methods` en lugar de `computed`; el efecto es el mismo para ambos, pero `computed` se basa en su caché de dependencias y solo vuelve a obtener el valor cuando la dependencia relevante cambia. En cambio, al usar `methods`, la función siempre se vuelve a llamar y ejecutar al volver a renderizar.

Ejemplo 3

methods: { reversedMessage2: function () { return this.message.split('').reverse().join('') } }

Pruébalo »

Se puede decir que usar `computed` tiene mejor rendimiento, pero si no deseas almacenar en caché, puedes usar la propiedad `methods`.

computed setter

La propiedad `computed` solo tiene getter por defecto, pero si es necesario también puedes proporcionar un setter:

Ejemplo 4

var vm = new Vue({ el: '#app', data: { name: 'Google', url: 'http://www.google.com' }, computed: { site: { // getter get: function () { return this.name + ' ' + this.url }, // setter set: function (newValue) { var names = newValue.split(' ') this.name = names[0] this.url = names[names.length - 1] } } } }) //Al llamar al setter, `vm.name` y `vm.url` también se actualizan correspondientemente vm.site = 'Tutorial para novatos http://www.runoob.com'; document.write('name: ' + vm.name); document.write('<br>'); document.write('url: ' + vm.url);

Pruébalo »

Según el resultado de ejecución del ejemplo, al ejecutar `vm.site = '菜鸟教程 http://www.runoob.com';`, se llamará al setter, y `vm.name` y `vm.url` también se actualizarán correspondientemente.

    Modifiqué un poco el código; debería poder reflejar el concepto de "caché de dependencias" de la propiedad `computed` y su diferencia con `method`. Como en el siguiente código, `cnt` es una variable independiente del objeto `vm`. Al usar la propiedad computada `reversedMessage`, la primera vez se ejecuta el código y se obtiene un valor; al volver a usar `reversedMessage` después, como el objeto `vm` no ha cambiado, el renderizado de la interfaz usa directamente ese valor sin volver a ejecutar el código. Mientras que `reversedMessage2` no tiene esta caché; cada vez que se usa, el código de la función se ejecuta una vez, por lo que el valor de retorno es diferente cada vez.

    var cnt=1;
var vm = new Vue({
  el: '#app',
  data: {
    message: 'Runoob!'
  },
  computed: {
    // 计算属性的 getter
    reversedMessage: function () {
      // `this` 指向 vm 实例
      cnt+=1;
      return cnt+this.message.split('').reverse().join('')
    }
  },
  methods: {
    reversedMessage2: function () {
      cnt+=1;
      return cnt+this.message.split('').reverse().join('')
    }
  }
})

    Cuando no estés utilizando la caché de dependencias de las propiedades computadas, puedes usar métodos definidos en su lugar. Definir un método en `methods` puede lograr el mismo efecto; incluso ese método puede aceptar parámetros, lo que lo hace más flexible de usar.

    <div id ="app">My Runoob Application
    <p>原始数据：{{text}}</p>
    <!-- 注意，这里的reversedText是方法，所以要带()-->
    <p>变化后数据：{{reversedText()}}</p>
</div>
<script>
var app = new Vue({
    el: '#app',
    data: {
        text:'123,456',
    },
    methods:{
        reversedText: function(){
            return this.text.split(',').reverse().join(',');
        }
    },
});    
</script>

    computed vs method：

    En Vue.js, hay dos formas, `methods` y `computed`, que se pueden usar dinámicamente como métodos.

    • 1. Primero, la diferencia más obvia es que al llamar, `methods` debe llevar paréntesis ().
    • 2. Podemos usar `methods` en lugar de `computed`; el efecto es el mismo para ambos, pero `computed` se basa en su caché de dependencias; solo vuelve a obtener el valor cuando la dependencia relevante cambia.

    Mientras que al usar `methods`, en el re-renderizado, la función siempre se vuelve a llamar y ejecutar.

    Para facilitar la comprensión, primero veamos un fragmento de código fuente:

    <!DOCTYPE html>
<html>
    <head>
        <meta charset="utf-8">
        <title>title</title>
        <script src="https://cdn.staticfile.org/vue/2.2.2/vue.min.js"></script>
    </head>

    <body>
        <div class="test">    <!--computed计算属性-->
            <p>{{now}}</p>
            <p>{{now}}</p>
            <p>{{now}}</p>
            <p>{{now}}</p>
            <hr />            <!--横线分割-->
</div>
        <div class="test2">   <!--methods方法，注意new（）加了括号-->
            <p>{{now()}}</p>
            <p>{{now()}}</p>
            <p>{{now()}}</p>
            <p>{{now()}}</p>
        </div>
    </body>

    <script type="text/javascript">
        var myVue = new Vue({
            el: ".test",
            computed: {
                now: function() {
                    var yanshi = 0;
                    for(var o = 0; o < 2000; o++) {     //延时
                        for(var q = 0; q < 2000; q++) {
                            yanshi++;
                        }
                    }
                    return Date.now()
                }
            }
        });
        var vue2 = new Vue({
            el: '.test2',
            methods: {
                now: function() {
                    var yanshi = 0;
                    for(var o = 0; o < 2000; o++) {
                        for(var q = 0; q < 2000; q++) {
                            yanshi++;
                        }
                    }
                    return Date.now()
                }
            }
        })
    </script>

</html>

    El resultado es el siguiente:

    El resultado de ejecución es como el anterior. Se puede ver que con la propiedad computada `computed`, cada vez que se entra a la página se seguirá usando la información de la primera vez; `now` no se volverá a disparar. Esto es la caché de dependencias. (Con un retraso, las múltiples salidas tienen el mismo tiempo).

    Entonces, ¿qué significa que solo se vuelve a tomar el valor cuando la dependencia correspondiente cambia? Por ejemplo, en la propiedad computada `reversedMessage function()` se llama a la variable `message`.

    Esto significa que mientras `message` no haya cambiado, acceder varias veces a la propiedad computada `reversedMessage` devolverá inmediatamente el resultado del cálculo anterior, sin tener que ejecutar la función nuevamente.

    Mientras que `methods` es en tiempo real; al volver a renderizar, la función siempre se vuelve a llamar y ejecutar, sin caché (las múltiples salidas tienen tiempos diferentes).

    Se puede decir que usar `computed` tiene mejor rendimiento, pero si no deseas almacenar en caché, puedes usar la propiedad `methods`.

    La propiedad `computed` solo tiene getter por defecto, pero si es necesario también puedes proporcionar un setter: por lo que en realidad `computed` también puede pasar parámetros.

    Sobre la caché de dependencias de `computed`, hay otro aspecto:

    var cnt=1;
var vm = new Vue({
  el: '#app',
  data: {
    message: 'Runoob!'
  },
  computed: {
    // 计算属性的 getter
    reversedMessage: function () {
      // `this` 指向 vm 实例
      cnt+=1;
      return cnt+this.message.split('').reverse().join('')
    }
  },
  methods: {
    reversedMessage2: function () {
      cnt+=1;
      this.message = "abc";
      return cnt+this.message.split('').reverse().join('')
    }
  }
})
