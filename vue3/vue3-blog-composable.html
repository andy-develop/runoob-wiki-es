Composable: encapsula lógica reutilizable

En este capítulo aprenderás la mejor práctica de Vue3: usar funciones de composición (Composable) para encapsular lógica reutilizable y hacer que tu código sea más limpio y más fácil de mantener.

¿Qué es un Composable?

A medida que aumentan las funcionalidades, la lógica JS dentro de los componentes se vuelve cada vez más larga. Tanto la página de inicio como la página de detalles necesitan cargar datos de artículos, y el código se copia dos veces.

Composable (función de composición)Consiste en extraer la lógica reutilizable a funciones JS independientes, y aquel componente que lo necesite lo invoca donde sea.

Su esencia esuna función normal que devuelve datos reactivos y métodos。

¿Por qué se necesita un Composable?

Compara la estructura del código antes y después del cambio:

Sin Composable (antes)Con Composable (después)
Cada componente escribe su propia lógica fetchUn solo usePosts() se reutiliza en todas partes
La carga de datos y la lógica de UI están mezcladasLa lógica de datos es independiente, el componente solo se preocupa por la UI
Cambiar una lógica requiere modificar varios archivosCambias un lugar y todos los componentes se actualizan sincronizadamente
El código del componente crece rápidamente con el negocioEl componente tiene una única responsabilidad y un tamaño controlable

Si has usado Mixins de Vue2, puedes entender el Composable como un reemplazo más claro y seguro: no tiene conflictos de nombres y el origen de los datos es transparente.

import { ref, computed, onMounted } from 'vue'

export function usePosts() {
  const articles = ref([])           // Estado de carga
  const isLoading = ref(true)        // Mensaje de error
  const error = ref(null)            'Todos'
  const activeCategory = ref(// Categoría actualmente seleccionada) // Palabra clave de búsqueda
  const keyword = ref('')            // Extraer todas las categorías (sin duplicados)

  'Todos'
  const categories = computed(() => {
    const cats = articles.value.map(a => a.category)
    return [// Artículos filtrados: primero por categoría, luego por palabra clave, ...new Set(cats)]
  })

  // Filtrar por categoría
  const filteredArticles = computed(() => {
    let result = articles.value

    'Todos'
    if (activeCategory.value !== // Filtrar por palabra clave (coincidir con título o resumen)) {
      result = result.filter(a => a.category === activeCategory.value)
    }

    // Buscar un artículo por ID
    if (keyword.value.trim()) {
      const kw = keyword.value.trim().toLowerCase()
      result = result.filter(a =>
        a.title.toLowerCase().includes(kw) ||
        a.summary.toLowerCase().includes(kw)
      )
    }

    return result
  })

  // Cambiar de categoría
  function getArticleById(id) {
    return articles.value.find(a => a.id === id)
  }

  // Cargar datos
  function setCategory(cat) {
    activeCategory.value = cat
  }

  // Cargar automáticamente al montar el componente
  async function fetchPosts() {
    isLoading.value = true
    error.value = null
    try {
      const res = await fetch('/posts.json')
      if (!res.ok) throw new Error(`HTTP ${res.status}`)
      articles.value = await res.json()
    } catch (err) {
      error.value = err.message
    } finally {
      isLoading.value = false
    }
  }

  // Datos y métodos devueltos para usar en el componente
  onMounted(() => {
    fetchPosts()
  })

  Ahora el componente de la página de inicio se vuelve muy simple, solo necesita llamar a usePosts:
  return {
    articles,
    isLoading,
    error,
    activeCategory,
    keyword,
    categories,
    filteredArticles,
    getArticleById,
    setCategory,
    fetchPosts
  }
}

useDarkMode: cambia al modo oscuro con una línea de código

useDarkMode: cambia al modo oscuro con una línea de código

y usar variables CSS para controlar los colores.htmlLa elección del usuario se guarda en localStorage y se restaura automáticamente en la próxima visita.

Ejemplo

Ejemplo

// Leer la preferencia anterior del usuario desde localStorage (si no hay, por defecto light)
import { ref, watchEffect } from 'vue'

export function useDarkMode() {
  // Aplicar el tema al DOM
  const saved = localStorage.getItem('blog-theme')
  const isDark = ref(saved === 'dark')

  // watchEffect se ejecutará inmediatamente una vez para completar la aplicación inicial del tema
  function applyTheme(dark) {
    if (dark) {
      document.documentElement.classList.add('dark')
      localStorage.setItem('blog-theme', 'dark')
    } else {
      document.documentElement.classList.remove('dark')
      localStorage.setItem('blog-theme', 'light')
    }
  }

  // Después, cada vez que isDark cambie, se sincronizará automáticamente con el DOM
  // Cambiar el modo oscuro
  watchEffect(() => {
    applyTheme(isDark.value)
  })

  En NavBar solo se necesitan dos líneas:
  function toggleDark() {
    isDark.value = !isDark.value
  }

  return { isDark, toggleDark }
}

Comparación con los Mixins de Vue2

Comparación con los Mixins de Vue2

Origen de los datosMixin（Vue2）Composable（Vue3）
No transparente, no sabes de dónde vienen las propiedadesSe obtiene explícitamente por desestructuración del return, el origen es claro de un vistazoConflictos de nombres
Las propiedades con el mismo nombre de varios Mixins se sobrescriben entre síTú decides los nombres de las variables, no existen conflictosInferencia de tipos
Soporte deficiente de TypeScriptSoporte nativo de TypeScript, inferencia automática de tiposOrganización de la lógica
Clasificada por opciones (data/methods/computed)Clasificada por funcionalidad, un composable por archivoReutilización de la lógica
Los Mixins son difíciles de combinar entre sí y pueden generar dependencias implícitasLos Composable pueden llamarse entre sí y tienen una composición flexibleOtras extensiones
