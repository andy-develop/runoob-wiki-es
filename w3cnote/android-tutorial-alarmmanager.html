10.5 AlarmManager(servicio de alarma)

clasificación Tutorial básico de introducción a Android

Introducción de esta sección:

Esta sección presenta sobre AlarmManager (servicio de alarma) en Android; por el nombre sabemos que podemos desarrollar aplicaciones de tipo despertador para teléfonos móviles. La explicación en la documentación es: en un momento específico transmite un Intent designado para nosotros. En pocas palabras, nosotros fijamos una hora, y cuando llega ese momento, AlarmManager transmitirá un Intent que hemos configurado. Por ejemplo, cuando llegue la hora, puede apuntar a una Activity o Service. Además, hay algunas cosas a tener en cuenta en la documentación oficial:

Además, hay que tener en cuenta un punto: AlarmManager se usa principalmente para ejecutar tu código en un momento determinado, ¡incluso si tu aplicación no se está ejecutando en ese momento específico! También, desde la API 19, el mecanismo de Alarm no es de entrega precisa; el sistema operativo convertirá las alarmas para minimizar las activaciones y el uso de la batería. Algunas API nuevas admiten entrega estrictamente precisa; ver setWindow(int, long, long, PendingIntent) y setExact(int, long, PendingIntent). Las aplicaciones con targetSdkVersion anterior a la API 19 seguirán usando el comportamiento anterior; todas las alarmas se entregarán de forma precisa cuando se requiera entrega precisa. Para más detalles, consulte la documentación oficial de la API:AlarmManager

Diferencia entre la clase Timer y la clase AlarmManager:

Si has aprendido J2SE, entonces Timer no te resultará desconocido. Un temporizador, en general, al escribir tareas programadas seguramente no puedes prescindir de él. Pero en Android, tiene una desventaja: no es muy adecuado para tareas programadas que necesitan ejecutarse en segundo plano durante mucho tiempo, porque los dispositivos Android tienen su propia estrategia de suspensión. Cuando no hay operación durante mucho tiempo, el dispositivo hace que la CPU entre automáticamente en estado de suspensión, lo que puede provocar que las tareas programadas en Timer no se ejecuten normalmente. Sin embargo, AlarmManager no tiene este problema, porque tiene la función de despertar la CPU, lo que garantiza que la CPU pueda funcionar normalmente cada vez que se necesite ejecutar una tarea específica. O bien, cuando la CPU está en suspensión, las alarmas registradas se conservan (pueden despertar la CPU), pero si el dispositivo se apaga o se reinicia, las alarmas se borrarán. (La alarma del teléfono Android no suena cuando está apagado...)

2. Obtener el objeto de instancia de AlarmManager:

AlarmManager alarmManager = (AlarmManager) getSystemService(ALARM_SERVICE);

3. Explicación de los métodos relacionados:

  • set(int type,long startTime,PendingIntent pi): alarma de una sola vez
  • setRepeating(int type, long startTime, long intervalTime, PendingIntent pi): Alarma repetitiva, a diferencia de la 3; el intervalo de tiempo de la alarma 3 no es fijo.
  • setInexactRepeating(int type, long startTime, long intervalTime, PendingIntent pi): alarma repetitiva, hora no fija.
  • cancel(PendingIntent pi): cancelar el servicio programado de AlarmManager
  • getNextAlarmClock(): Obtener la próxima alarma, valor de retorno AlarmManager.AlarmClockInfo
  • setAndAllowWhileIdle(int type, long triggerAtMillis, PendingIntent operation) Al igual que el método set, esta alarma funciona cuando el sistema se encuentra en modo de bajo consumo.
  • setExact(int type, long triggerAtMillis, PendingIntent operation): Ejecuta la alarma con precisión en el tiempo especificado, con mayor precisión que el método set.
  • setTime(long millis): establece la hora del sistema
  • setTimeZone(String timeZone): establece la zona horaria predeterminada persistente del sistema.
  • setWindow(int type, long windowStartMillis, long windowLengthMillis, PendingIntent operation): Establece una alarma para que se dispare dentro de una ventana de tiempo determinada. Similar a set, este método permite a la aplicación controlar con precisión el grado en que el sistema operativo ajusta el tiempo de disparo de la alarma.

Explicación de parámetros clave.：

  • Type(Tipo de alarma): Hay cinco valores opcionales: AlarmManager.ELAPSED_REALTIMELa alarma no está disponible cuando el teléfono está en modo de suspensión; en este estado, la alarma usa tiempo relativo (respecto al inicio del sistema), el valor de estado es 3; AlarmManager.ELAPSED_REALTIME_WAKEUPEl despertador despertará el sistema en estado de suspensión y ejecutará la función de aviso. En este estado, el despertador también utiliza tiempo relativo, con valor de estado 2; AlarmManager.RTCEl despertador no está disponible en el estado de suspensión; en este estado, el despertador usa el tiempo absoluto, es decir, el tiempo actual del sistema, con un valor de estado de 1; AlarmManager.RTC_WAKEUPIndica que la alarma en estado de suspensión despertará el sistema y ejecutará la función de aviso; en este estado, la alarma usa tiempo absoluto, el valor de estado es 0; AlarmManager.POWER_OFF_WAKEUPIndica que la alarma puede funcionar normalmente incluso cuando el teléfono está apagado, por lo que es uno de los estados más utilizados entre los 5 estados. En este estado, la alarma también usa tiempo absoluto y el valor del estado es 4; sin embargo, parece que este estado se ve afectado por la versión del SDK y algunas versiones no lo admiten.
  • startTime: La primera hora de ejecución de la alarma, en milisegundos, puede personalizarse, pero generalmente se usa la hora actual. Cabe señalar que esta propiedad está estrechamente relacionada con la primera propiedad (type). Si el parámetro correspondiente al primer argumento usa tiempo relativo (ELAPSED_REALTIME y ELAPSED_REALTIME_WAKEUP), entonces esta propiedad debe usar tiempo relativo (relativo al tiempo de arranque del sistema), por ejemplo, el tiempo actual se representa como: SystemClock.elapsedRealtime(); Si el primer parámetro corresponde a una alarma que usa tiempo absoluto (RTC, RTC_WAKEUP, POWER_OFF_WAKEUP), entonces esta propiedad debe usar tiempo absoluto, por ejemplo, el tiempo actual se representa como: System.currentTimeMillis().
  • intervalTime: : Indica el intervalo de tiempo entre dos ejecuciones de la alarma, también en milisegundos.
  • PendingIntent: Acciones de ejecución vinculadas a la alarma, como enviar una transmisión, mostrar una notificación, etc. PendingIntent es una clase contenedora de Intent. Cabe señalar que, si se implementa la notificación de la alarma mediante el inicio de un servicio, la obtención del objeto PendingIntent debe utilizar el método PendingIntent.getService(Context c, int i, Intent intent, int j); si se implementa mediante una transmisión, la obtención del objeto PendingIntent debe utilizar el método PendingIntent.getBroadcast(Context c, int i, Intent intent, int j); si se utiliza una Activity para implementar la notificación de la alarma, la obtención del objeto PendingIntent debe utilizar el método PendingIntent.getActivity(Context c, int i, Intent intent, int j). Si estos tres métodos se usan incorrectamente, aunque no se producirán errores, no se verá el efecto de la notificación de la alarma.

Hay que decir que este ejemplo solo funciona en sistemas Android 4.4 o inferior, no en 5.0 o superior. Si más adelante hay una solución para AlarmManager en 5.0 o superior, la añadiré entonces. Además, usar el método set aquí puede ser un poco impreciso; si se quiere más precisión, se puede usar el método setExtra() para configurar AlarmManager.

A continuación está.MainActivity.java，y también es muy simple：

public class MainActivity extends AppCompatActivity implements View.OnClickListener{

    private Button btn_set;
    private Button btn_cancel;
    private AlarmManager alarmManager;
    private PendingIntent pi;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);
        bindViews();
    }

    private void bindViews() {
        btn_set = (Button) findViewById(R.id.btn_set);
        btn_cancel = (Button) findViewById(R.id.btn_cancel);
        alarmManager = (AlarmManager) getSystemService(ALARM_SERVICE);

        Intent intent = new Intent(MainActivity.this, ClockActivity.class);
        pi = PendingIntent.getActivity(MainActivity.this, 0, intent, 0);

        btn_set.setOnClickListener(this);
        btn_cancel.setOnClickListener(this);

    }


    @Override
    public void onClick(View v) {
        switch (v.getId()){
            case R.id.btn_set:
                Calendar currentTime = Calendar.getInstance();
                new TimePickerDialog(MainActivity.this, 0,
                        new TimePickerDialog.OnTimeSetListener() {
                            @Override
                            public void onTimeSet(TimePicker view,
                                                  int hourOfDay, int minute) {
                                //设置当前时间
                                Calendar c = Calendar.getInstance();
                                c.setTimeInMillis(System.currentTimeMillis());
                                // 根据用户选择的时间来设置Calendar对象
                                c.set(Calendar.HOUR, hourOfDay);
                                c.set(Calendar.MINUTE, minute);
                                // ②设置AlarmManager在Calendar对应的时间启动Activity
                                alarmManager.set(AlarmManager.RTC_WAKEUP, c.getTimeInMillis(), pi);
                                Log.e("HEHE",c.getTimeInMillis()+"");   //这里的时间是一个unix时间戳
                                // 提示闹钟设置完毕:
                                Toast.makeText(MainActivity.this, "闹钟设置完毕~"+ c.getTimeInMillis(),
                                        Toast.LENGTH_SHORT).show();
                            }
                        }, currentTime.get(Calendar.HOUR_OF_DAY), currentTime
                        .get(Calendar.MINUTE), false).show();
                btn_cancel.setVisibility(View.VISIBLE);
                break;
            case R.id.btn_cancel:
                alarmManager.cancel(pi);
                btn_cancel.setVisibility(View.GONE);
                Toast.makeText(MainActivity.this, "闹钟已取消", Toast.LENGTH_SHORT)
                        .show();
                break;
        }
    }
}

El código es muy simple, el flujo principal es el siguiente:

  • AlarmManager alarmManager = (AlarmManager) getSystemService(ALARM_SERVICE); Obtener el objeto del servicio AlarmManager proporcionado por el sistema.
  • Intent establece el componente a iniciar.: Intent intent = new Intent(MainActivity.this, ClockActivity.class);
  • El objeto PendingIntent establece la acción: ¿inicia una Activity, un Service o un Broadcast? PendingIntent pi = PendingIntent.getActivity(MainActivity.this, 0, intent, 0);
  • ¡Llame al método set() de AlarmManager para establecer el tipo de alarma de una sola vez, la hora de inicio y el objeto PendingIntent! alarmManager.set(AlarmManager.RTC_WAKEUP,c.getTimeInMillis(), pi);
