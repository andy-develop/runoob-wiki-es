Guía de instalación rápida de CoreOS en PC

Categoría Tecnología de programación

Importancia

Permite instalar y desplegar el sistema operativo Linux a la mayor velocidad. La instalación es rápida y sencilla, y se puede empezar a ejecutar Docker casi sin perder tiempo. La velocidad de ejecución es muy alta. Usa disco de memoria.

Mi situación

Portátil con Windows 8, a veces juego, pero instalar un sistema dual con Linux podría llevarme un día entero. Todos mis servicios solo necesitan ejecutarse en Docker. Además, mi portátil tiene suficiente memoria: 16 GB (gracias al profesor Jiang de HUST).

Preparación

  1. CoreOS image Enlace de descarga
  2. EasyBCD Enlace de descarga

Manos a la obra

  1. Instalar EasyBCD, añadir la entrada de arranque ISO y usar directamente la imagen livecd de CoreOS.
    Pasos detallados con capturas de pantalla:http://jingyan.baidu.com/article/466506586ed309f549e5f81c.html
  2. Iniciar CoreOS y completar la instalación de CoreOS

Actualización

Solo es necesario actualizar el archivo ISO de arranque.

Desventajas

  1. No es persistente (ventaja: si lo rompes, basta con reiniciar).
  2. Todo el sistema operativo está en archivos generados en el disco duro que ocupan directamente espacio en él (ventaja: la velocidad del disco mejora muchísimo).
  3. Cada vez que se enciende, hay que montar manualmente el espacio del disco duro y ejecutar manualmente el script de inicialización de todo el sistema.

Considerando las ventajas y desventajas, esta configuración se recomienda para trabajos con servicios definidos; si hay muchos servicios, puede haber muchos puntos que optimizar.

Configuración

  1. Crea una partición de 100 GB en el disco duro y dale formato. Comando de referencia: mkfs.ext4 /dev/sda2, luego móntala. Si no entiendes cómo particionar, formatear y montar, consultaaquí. Este artículo es, se podría decir, el mejor que he visto sobre gestión básica de discos.
  2. Después de montar, copia la carpeta /var/lib/docker/ a la ubicación montada y luego haz un enlace simbólico de vuelta. (Así las imágenes de Docker pueden persistir en el disco duro y no se perderán al reiniciar). Operación de referencia:
    cp -rf /var/lib/docker /mnt/
rm -rf /var/lib/docker
ln -s /mnt/docker /var/lib/docker

Referencia de mi archivo de inicialización

mkdir /root/.ssh
echo "ssh-rsa xxx..(省略)....xx Li-jianying@lijianyings-MacBook-Pro.local" > /root/.ssh/authorized_keys

rm -rf /var/lib/docker
ln -s /mnt/docker /var/lib/docker
#echo 'DOCKER_OPTS="--registry-mirror=http://XXXXX.m.daocloud.io"' >> /run/flannel_docker_opts.env
#systemctl daemon-reload
systemctl restart docker
# using disk

Primero importa la clave RSA y luego crea un enlace simbólico a la ubicación de Docker.

Añade el acelerador de DaoCloud (aunque oficialmente no se indica cómo acelerar CoreOS, un experto ha proporcionado un método); como sin aceleración me va más rápido que con ella, aquí lo dejo comentado como plan alternativo.

Problemas con systemd

Si Docker devuelve el error -1, el contenedor se cae. Pero en systemd todavía existe el scope.

Al iniciar el contenedor problemático, aparecerá un aviso

Error response from daemon: Cannot start container test: [8] System error: Unit docker-e10eb86807cd9971fc03a8eee732771193d506ed2ba678fdf4292916a9fb072c.scope already exists.

Entonces

systemctl stop docker-e10eb86807cd9971fc03a8eee732771193d506ed2ba678fdf4292916a9fb072c.scope

se puede solucionar.

Problema 2 con CoreOS.iso

Confirmar KnowHosts constantemente.

Solución de referencia:https://github.com/lijianying10/FixLinux/blob/master/note/取消sshPublicKeyKnowHost认证.md

Resumen

Implementar Linux en un PC con este método es realmente muy conveniente. Si estás familiarizado con el ecosistema de Docker, puedes tenerlo resuelto en unos 20 minutos según tu propia situación.
Después de encontrar esta idea, sopesé varias opciones.

  1. Para resolver rápidamente el problema del arranque, usar EasyBCD para arrancar directamente el ISO desde memoria, en lugar de lidiar con UEFI y Grub.
  2. Para reducir el costo de tiempo de configuración del entorno, cambié de las distribuciones normales instaladas en el disco duro a CoreOS.
  3. Para evitar la inestabilidad del sistema causada por operaciones erróneas o actualizaciones de versión, cambié a Docker.
  4. En el futuro quizás cambie a RKT, RunC (espero que los expertos resuelvan los problemas pronto; RunC dijo que lanzaría este mes, no sé si se retrasará).
  5. Ten en cuenta que este esquema utiliza a toda costa la configuración de entorno más simple a cambio de tiempo de desarrollo. Los perfeccionistas a los que les gusta trastear quizás tengan que buscar otro camino.
