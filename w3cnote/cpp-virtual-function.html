Diferencia entre funciones virtuales y funciones virtuales puras

Categoría Técnicas de programación

Primero: enfatizar un concepto

Definir una función como virtual no significa que la función no esté implementada.

Definirla como virtual es para permitir usar un puntero de la clase base para invocar esta función de la subclase.

Solo cuando se define una función como virtual pura se representa que la función no está implementada.

Definir una función virtual pura es para implementar una interfaz, que cumple una función normativa: el programador que herede esta clase debe implementar esta función.

1. Introducción

Supongamos que tenemos la siguiente jerarquía de clases:

class A
{
public:
    virtual void foo()
    {
        cout<<"A::foo() is called"<<endl;
    }
};
class B:public A
{
public:
    void foo()
    {
        cout<<"B::foo() is called"<<endl;
    }
};
int main(void)
{
    A *a = new B();
    a->foo();   // 在这里，a虽然是指向A的指针，但是被调用的函数(foo)却是B的!
    return 0;
}

Este ejemplo es una aplicación típica de las funciones virtuales. A través de él, quizás ya tengas una idea sobre las funciones virtuales. Lo «virtual» reside en el llamado «enlace tardío» o «enlace dinámico»: la llamada a una función de clase no se determina en tiempo de compilación, sino en tiempo de ejecución. Dado que al escribir el código no se puede determinar si lo que se invoca es la función de la clase base o la de alguna clase derivada, se la denomina función «virtual».

Las funciones virtuales solo pueden lograr el efecto de polimorfismo mediante punteros o referencias.

Funciones virtuales puras en C++

I. Definición

Una función virtual pura es una función virtual declarada en la clase base; no tiene definición en la clase base, pero se requiere que cualquier clase derivada defina su propio método de implementación. La forma de declarar una función virtual pura en la clase base es agregar «=0» después del prototipo de la función.

virtual void funtion1()=0

II. Razones de su introducción

  • 1. Para facilitar el uso de las características del polimorfismo, a menudo necesitamos definir funciones virtuales en la clase base.
  • 2. En muchos casos, no es razonable que la propia clase base genere objetos. Por ejemplo, «Animal», como clase base, puede derivar subclases como «Tigre» y «Pavo Real», pero que la propia clase Animal genere un objeto es claramente irrazonable.

Para resolver los problemas anteriores, se introdujo el concepto de función virtual pura. Al definir una función como virtual pura (método: virtual ReturnType Function() = 0;), el compilador exige que las clases derivadas la reescriban para lograr el polimorfismo. Al mismo tiempo, una clase que contiene funciones virtuales puras se denomina clase abstracta y no puede generar objetos. De este modo, se resuelven perfectamente los dos problemas mencionados.

Una clase que declara funciones virtuales puras es una clase abstracta. Por lo tanto, el usuario no puede crear instancias de la clase; solo puede crear instancias de sus clases derivadas.

La característica más notable de las funciones virtuales puras es que deben volver a declarar la función en la clase heredera (sin el «=0» al final; de lo contrario, la clase derivada tampoco puede instanciarse), y a menudo no tienen definición en la clase abstracta.

El propósito de definir funciones virtuales puras es que las clases derivadas solo hereden la interfaz de la función.

El significado de una función virtual pura es permitir que todos los objetos de la clase (principalmente los objetos de las clases derivadas) puedan ejecutar la acción de la función virtual pura, pero la clase no puede proporcionar una implementación predeterminada razonable para ella. Por lo tanto, la declaración de una función virtual pura en una clase está diciendo al diseñador de la subclase: «Debes proporcionar una implementación de la función virtual pura, pero no sé cómo la implementarás».

Introducción a las clases abstractas

Una clase abstracta es un tipo especial de clase, establecida con fines de abstracción y diseño; se encuentra en los niveles superiores de la jerarquía de herencia.

  • （1）Definición de clase abstracta:Una clase que contiene funciones virtuales puras se denomina clase abstracta.

  • （2）Función de la clase abstracta:La función principal de una clase abstracta es organizar las operaciones relacionadas como interfaces resultantes en una jerarquía de herencia, proporcionando así una raíz común para las clases derivadas. Las clases derivadas implementarán concretamente las operaciones que actúan como interfaces en su clase base. Por lo tanto, una clase derivada describe en realidad la semántica común de las interfaces de operación de un conjunto de subclases; esta semántica también se transmite a las subclases, que pueden implementarla concretamente o transmitirla a su vez a sus propias subclases.

  • （3）Consideraciones al usar clases abstractas:a、Una clase abstracta solo puede usarse como clase base; la implementación de sus funciones virtuales puras la proporcionan las clases derivadas. Si una clase derivada no redefine las funciones virtuales puras y simplemente hereda las funciones virtuales puras de la clase base, entonces esa clase derivada sigue siendo una clase abstracta. Si la clase derivada proporciona la implementación de las funciones virtuales puras de la clase base, entonces ya no es una clase abstracta, sino una clase concreta que puede crear objetos.b、Una clase abstracta no puede definir objetos.

Resumen:

  • 1. Una función virtual pura se declara de la siguiente manera:virtual void funtion1()=0;Una función virtual pura ciertamente no tiene definición; se utiliza para estandarizar el comportamiento de las clases derivadas, es decir, la interfaz. Una clase que contiene funciones virtuales puras es una clase abstracta; una clase abstracta no puede definir instancias, pero puede declarar punteros o referencias a clases concretas que implementen dicha clase abstracta.

  • 2. Una función virtual se declara de la siguiente manera:virtual ReturnType FunctionName(Parameter);Una función virtual debe implementarse; si no se implementa, el compilador mostrará un error. El mensaje de error es:

    error LNK****: unresolved external symbol "public: virtual void __thiscall ClassName::virtualFunctionName(void)"

  • 3. Para las funciones virtuales, la clase padre y la clase hija tienen cada una su propia versión. Cuando se invocan de forma polimórfica, se produce un enlace dinámico.

  • 4. En una subclase que implementa una función virtual pura, esta se convierte en una función virtual en la subclase; la subclase de la subclase, es decir, la clase nieta, puede sobrescribir esa función virtual, y cuando se invoca de forma polimórfica se produce un enlace dinámico.

  • 5. Las funciones virtuales son el mecanismo en C++ para implementar el polimorfismo (polymorphism). La idea central es acceder a las funciones definidas en la clase derivada a través de la clase base.

  • 6. Cuando se asigna memoria dinámicamente en el montón (heap), el destructor debe ser una función virtual, pero no es necesario que sea virtual pura.

  • 7. Las funciones friend (amigas) no son funciones miembro; solo las funciones miembro pueden ser virtuales, por lo tanto, las funciones friend no pueden ser funciones virtuales. Sin embargo, el problema de la virtualidad de las funciones friend se puede resolver haciendo que la función friend llame a una función miembro virtual.

  • 8. El destructor debe ser una función virtual; de esta manera se llamará al destructor del tipo de objeto correspondiente. Por lo tanto, si el puntero apunta a un objeto de la subclase, se llamará al destructor de la subclase y, a continuación, automáticamente al destructor de la clase base.

Una clase que tiene funciones virtuales puras es una clase abstracta; no puede generar objetos, solo puede derivar. Si las funciones virtuales puras de su clase derivada no han sido sobrescritas, entonces su clase derivada sigue siendo una clase abstracta.

Definir funciones virtuales puras es precisamente para que la clase base no pueda instanciarse.

Porque instanciar una estructura de datos abstracta de este tipo no tiene sentido en sí mismo.

O proporcionar una implementación tampoco tiene sentido.

De hecho, personalmente creo que la introducción de las funciones virtuales puras tiene dos propósitos:

  • 1. Por seguridad: para evitar cualquier resultado desconocido que requiera claridad pero que podría ocurrir por descuido, y recordar a las subclases que realicen la implementación que les corresponde.

  • 2. Por eficiencia; no la eficiencia de ejecución del programa, sino la eficiencia de codificación.
