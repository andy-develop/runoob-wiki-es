Sobre la relación entre los contenedores y las imágenes de Docker

No importa qué operaciones se realicen en el contenedor, escribir archivos, borrar archivos. La imagen base de ese contenedor no cambiará en absoluto. Esto se debe a que Docker crea imágenes incrementales a partir de la imagen principal y solo almacena los cambios de cada contenedor. Por lo tanto, si tienes una imagen principal de 300 MB, y si instalas 50 MB de aplicaciones o servicios adicionales en el contenedor, tu contenedor solo tendrá 50 MB, y la imagen principal seguirá siendo de 300 MB. Sin embargo, puedes usar el comando Dockfile o commit para generar una nueva imagen combinando la imagen incremental y la imagen principal.

dock top -- 显示容器中运行的进程

Ver el nombre de usuario root y la contraseña del contenedor

docker logs <容器名orID> 2>&1 | grep '^User: ' | tail -n1

Debido a que la contraseña del usuario root se asigna aleatoriamente cuando se inicia el contenedor de Docker, de esta manera se puede obtener la contraseña del usuario root del contenedor redmine.

Ver los registros del contenedor en tiempo real

docker logs -f <容器名orID>

Eliminar todos los contenedores

docker rm $(docker ps -a -q)

Detener, iniciar o matar un contenedor

docker stop <容器名orID>
docker start <容器名orID>
docker kill <容器名orID>

Ver todas las imágenes

docker images

Eliminar todas las imágenes

docker rmi $(docker images | grep none | awk '{print $3}' | sort -r)

Eliminar todos los contenedores e imágenes (limpieza general)

Limpieza general con un solo comando:

docker kill $(docker ps -q) ; docker rm $(docker ps -a -q) ; docker rmi $(docker images -q -a)

Nota: $() en el shell es similar a un comando; ejecutará primero el contenido dentro. El script anterior producirá lo siguiente: docker kill "pids"; docker kill se usa en Docker para detener contenedores, docker rm elimina contenedores, docker rmi elimina imágenes.

Cuando no hay contenedores en ejecución o simplemente no hay contenedores, esto solo mostrará un mensaje de advertencia. Cuando quieras probarlo, es un excelente comando de una sola línea. Si solo quieres eliminar todos los contenedores, puedes ejecutar el siguiente comando:

docker kill $(docker ps -q) ; docker rm $(docker ps -a -q)

No ejecutar comandos en el Shell

Si usas el comando docker run con expansiones que requieren Shell para manejar ciertas cosas, por ejemplo, docker run --rm busybox ls '/var/log/', este comando fallará. Me tomó tiempo entender la razón de este fallo. La trampa está aquí: originalmente no tienes Shell, y ``` es una expansión de Shell, por lo que necesitas un Shell que puedas usar. La forma correcta es:

docker run --rm busybox sh -c 'ls /var/log/*'

Método para ejecutar automáticamente múltiples programas al inicio:

Cada vez que se inicia un contenedor de Docker, los comandos de inicio automático deben especificarse antes de iniciar el contenedor. Por ejemplo, el comando docker run -I -t debian /bin/bash solo ejecuta el programa /bin/bash, y ningún otro programa se ejecutará, lo cual es especialmente problemático para contenedores que necesitan ejecutar varios programas. Puedes reemplazar el comando de inicio mencionado anteriormente por

dockerrun -I -t debian /etc/rc.local

Coloca todos los comandos de inicio automático necesarios en /etc/rc.local dentro del contenedor, y así se puede lograr el inicio automático de múltiples programas.

Para ejecutarlo en segundo plano, entonces:

docker run -d -p 50001:22 debian /etc/rc.local

Eliminar el contenedor al salir

Si solo quieres ejecutar rápidamente un comando en un contenedor y luego salir, sin preocuparte por el estado del contenedor, agrega el parámetro --rm al final del comando run. Esto terminará muchos de los contenedores que has guardado y los limpiará.

docker run --rm -i -t busybox /bin/bash

Ejecutar un nuevo contenedor, al mismo tiempo nombrarlo, mapear puertos y mapear carpetas. Tomando la imagen redmine como ejemplo

docker run --name redmine -p 9003:80 -p 9023:22 -d -v /var/redmine/files:/redmine/files -v /var/redmine/mysql:/var/lib/mysql sameersbn/redmine

Un contenedor conectado a otro contenedor

docker run -i -t --name sonar -d -link mmysql:db   tpires/sonar-server
sonar

Conecta el contenedor al contenedor mmysql y renombra el contenedor mmysql como db. De esta manera, el contenedor sonar puede usar las variables de entorno relacionadas con db.

Guardar e importar imágenes

Cuando necesites migrar una imagen de una máquina a otra, debes guardar la imagen y cargarla. Máquina a

docker save busybox-1 > /home/save.tar

Usa scp para copiar save.tar a la máquina b, y luego:

docker load < /home/save.tar

Construir tu propia imagen

docker build -t <镜像名> <Dockerfile路径>

Por ejemplo, si el Dockerfile está en la ruta actual:

docker build -t xx/gitlab .

Ejecutar en segundo plano (-d) y exponer el puerto (-p)

docker run -d -p 127.0.0.1:33301:22 centos6-ssh

Copiar archivos desde el contenedor

sudo docker cp 7bb0e258aefe:/etc/debian_version .

Copiar /etc/debian_version desde 7bb0e258aefe al directorio actual.

Nota: mientras 7bb0e258aefe no haya sido eliminado, el espacio de nombres de archivos seguirá existiendo, por lo que puedes copiar con seguridad los archivos del contenedor en estado exit.
