Diferencia y relación entre extern y los archivos de cabecera (*.h)

Clasificación

用 #includeSi se pueden incluir declaraciones de variables y funciones de otros archivos de cabecera, ¿por qué se necesita la palabra clave extern?

Si quiero hacer referencia a una variable global o función a, solo tengo que incluir directamente #include<xxx.h> en el archivo fuente (xxx.h contiene la declaración de a), ¿no es suficiente? ¿Por qué usar extern?

Este problema también me ha estado molestando durante mucho tiempo de manera ambigua. Después de practicar y consultar materiales, tengo el siguiente resumen:

1. Archivos de cabecera

Primero hablemos de los archivos de cabecera. En realidad, los archivos de cabecera no tienen ningún efecto para la computadora; solo se expanden en el momento de la precompilación en#includeel lugar donde se incluyen; no tiene otro significado. En realidad, los archivos de cabecera son principalmente para que otros los lean.

Hice un experimento: cambié la extensión del archivo de cabecera a xxx.txt, y luego en el lugar donde se referenciaba usé #include "xxx.txt". La compilación y el enlace pasaron sin problemas. De esto se puede ver que el archivo de cabecera solo sirve para leer el código, ¡no tiene otra función!

Ya sea C o C++, colocas tus funciones, variables, estructuras, clases, etc., en tus archivos .c o .cpp. Luego compilas para obtener lib, dll, obj, .o, etc. Cuando otros los usan, lo más básico es gcc hisfile.cpp yourfile.o|obj|dll|lib, etc.

Pero para nosotros, los programadores, ¿cómo saben qué hay realmente dentro de tu lib, dll...? Tienen que mirar tu archivo de cabecera. Tu archivo de cabecera es una explicación para el usuario: funciones, parámetros, descripciones de diversas interfaces.

Ya que es una descripción, lo que naturalmente se pone en el archivo de cabecera son las "declaraciones" sobre funciones, variables y clases (para funciones, también se llaman prototipos de funciones). Recuerda, son "declaraciones", no "definiciones".

Entonces, asumo que todos conocen la diferencia entre declaración y definición. Por lo tanto, es mejor no definir nada tontamente en el archivo de cabecera. Por ejemplo, una variable global:

/*xx头文件*/
#ifndef _XX_头文件.H
#define _XX_头文件.H
int A;
#endif

Entonces, lo malo es que aquí `int A` es una definición de variable global. Por lo tanto, si este archivo de cabecera se referencia varias veces, tu A será definida repetidamente, lo cual es obviamente un error de sintaxis. Solo que con la compilación condicional `#ifndef`, se puede garantizar que el archivo de cabecera solo se incluya una vez, por lo que quizás no haya problemas. Pero si varios archivos .c incluyen este archivo de cabecera, seguirá habiendo errores, porque el alcance del nombre de la macro se limita a este archivo fuente .c; por lo tanto, durante la compilación de estos múltiples archivos .c no habrá error, pero en el enlace se reportará un error diciendo que definiste la misma variable en varios lugares:

Linking...
incl2.obj : error LNK2005: "int glb" (?glb@@3HA) already defined in incl1.obj
Debug/incl.exe : fatal error LNK1169: one or more multiply defined symbols found

2. extern

Esta palabra clave es realmente molesta. Al definir una variable, este extern puede omitirse (al definir, por defecto se omite); al declarar una variable, este extern debe añadirse delante de la variable, por lo que a veces no sabes si es una declaración o una definición. En otras palabras, tener extern delante de una variable no significa necesariamente que sea una declaración, mientras que sin extern solo puede ser una definición. Nota: la definición debe asignar espacio de memoria para la variable; la declaración no necesita asignar espacio de memoria para la variable.

A continuación, se explica en dos categorías: variables y funciones.

(1) Variables

Especialmente para las variables:

extern int a; // 声明一个全局变量 a
int a; // 定义一个全局变量 a
extern int a =0 ; // 定义一个全局变量 a 并给初值。
int a =0;    // 定义一个全局变量 a, 并给初值，

El cuarto es igual al tercero; ambos definen una variable global que puede ser utilizada externamente y le asignan un valor inicial.

Confundido, ¿verdad? Se ven muy similares. Pero una definición solo puede aparecer en un lugar. Es decir, ya sea `int a;`, `extern int a = 0;` o `int a = 0;`, solo pueden aparecer una vez, mientras que `extern int a` puede aparecer muchas veces.

Cuando quieras hacer referencia a una variable global, debes declararla: `extern int a;`. En este caso, extern no se puede omitir, porque si se omite, se convierte en `int a;`, que es una definición, no una declaración. Nota: en `extern int a;`, el tipo `int` se puede omitir, es decir, `extern a;`, pero para otros tipos no se puede omitir.

(2) Funciones

Funciones. Para las funciones es igual: también hay definición y declaración. Al definir se usa extern para indicar que esta función puede ser referenciada externamente; al declarar se usa extern para indicar que es una declaración. Pero como la definición y la declaración de una función son diferentes (definir una función requiere un cuerpo de función, mientras que declararla no tiene cuerpo y termina con punto y coma), se puede omitir extern tanto en la definición como en la declaración. De todos modos, otros archivos saben que esta función está definida en otro lugar, así que no hay problema si no se añade extern. Son tan diferentes que omitir extern no causa problemas.

Por ejemplo:

/*某cpp文件*/
int fun(void)
{
      return 0;
}

Muy bien, hemos definido una función global:

/*另一cpp文件*/
int fun(void);

Hicimos una declaración de ella, y luego se puede usar; con o sin extern es igual. También podemos poner la declaración de `fun` en un archivo de cabecera, y finalmente queda así:

/*fun.h*/
int fun(void);   //函数声明，所以省略了extern，完整些是extern int fun(void);
/*对应的fun.cpp文件*/
int fun(void)
{
     return 0;
}//一个完整的全局函数定义，因为有函数体，extern同样被省略了。

Entonces, un cliente, un cliente que quiere usar tu `fun`, incluye ese archivo de cabecera, ok, una declaración global. No hay problema.

Pero, en correspondencia, si este cliente quiere usar una variable global, entonces necesita `extern` + la variable; de lo contrario, se convertiría en una definición.

Resumen:

Para las variables: si quieres usar en el archivo fuente actual (por ejemplo, archivo A) una variable de otro archivo fuente (por ejemplo, archivo B), hay dos métodos: (1) En el archivo A, debes usar extern para declarar la variable definida en el archivo B (por supuesto, una variable global); (2) En el archivo A, añade el archivo de cabecera correspondiente al archivo B. Por supuesto, este archivo de cabecera contiene la declaración de la variable del archivo B, es decir, en este archivo de cabecera se debe declarar la variable con extern; de lo contrario, la variable se define una vez más.

Para las funciones: si quieres usar en el archivo fuente actual (por ejemplo, archivo A) una función de otro archivo fuente (por ejemplo, archivo B), hay dos métodos: (1) En el archivo A, declara con extern la función definida en el archivo B (en realidad, también se puede omitir extern; basta con que aparezca el prototipo de la función definida en B en el archivo A); (2) En el archivo A, añade el archivo de cabecera correspondiente al archivo B. Por supuesto, este archivo de cabecera contiene el prototipo de la función de B; en el archivo de cabecera, las funciones pueden omitir extern.

Otra forma de expresar el resumen anterior:

(a) Para un archivo que llama a una variable global de otro archivo: como las variables globales generalmente se definen en el archivo fuente .c, no podemos usar #include para incluir el archivo fuente, solo podemos incluir archivos de cabecera. Por lo tanto, el método común es usar `extern int a` para declarar la variable externa. Otro método es: si se define la variable global `int global_num` en el archivo a.c, se puede escribir `extern int global_num` en el archivo de cabecera correspondiente a.h; así, otros archivos fuente pueden incluir a.h para declarar que es una variable externa.

(b) También hay ejemplos de diferencias entre variables y funciones.int fun(); 和 extern int fun();Son declaraciones (la definición requiere un cuerpo de implementación). Usarextern int fun()solo indica más claramente que es una declaración. Mientras queint a;es definiciónextern int a;es declaración.

(3) Además, el modificador extern se puede usar para el problema de la especificación de llamar a funciones de C en programas C++.

Por ejemplo, para llamar a funciones de la biblioteca C en C++, es necesario usar `extern "C"` en el programa C++ para declarar la función que se va a referenciar. Esto se usa para el enlazador, indicándole que en el enlace use la especificación de funciones de C. La razón principal es que, después de la compilación, las reglas de nomenclatura en el código objeto difieren entre C++ y C.

El lenguaje C++, al compilar, para resolver el problema del polimorfismo, combina el nombre y los parámetros para generar un nombre intermedio, mientras que el lenguaje C no lo hace. Por lo tanto, puede causar que en el enlace no se encuentre la correspondencia. En este caso, C necesita usar `extern "C"` para especificar el enlace, lo que le dice al compilador: "por favor, mantén mi nombre, no me generes un nombre intermedio para el enlace".

3. Relación entre extern y los archivos de cabecera

Esta relación también resuelve los dos problemas planteados al principio:

(a) Si con #include se pueden incluir declaraciones de variables y funciones de otros archivos de cabecera, ¿por qué se necesita la palabra clave extern?

(b) Si quiero hacer referencia a una variable global o función a, solo tengo que incluir directamente en el archivo fuente #include(xxx.h contiene la declaración de a), ¿no es suficiente? ¿Por qué usar extern?

Respuesta: Si un archivo (supongamos archivo A) necesita hacer muchas referencias a variables o funciones definidas en otro archivo (supongamos archivo B), usar un archivo de cabecera es más eficiente y la estructura del programa es más estándar. Otros archivos (por ejemplo, archivos C, D, etc.) que quieran hacer referencia a variables o funciones definidas en el archivo B solo necesitan usar #include para incluir el archivo de cabecera correspondiente al archivo B (por supuesto, este archivo de cabecera solo contiene declaraciones de variables o funciones, nunca definiciones).

Esa fue una era olvidada, una época en la que los compiladores solo conocían los archivos .c (o .cpp) y no sabían qué era .h.

En aquel entonces, la gente escribía muchos archivos .c (o .cpp). Gradualmente, descubrieron que las declaraciones de variables o prototipos de funciones en muchos archivos .c (o .cpp) eran idénticos, pero tenían que teclear estos contenidos repetidamente, palabra por palabra, en cada archivo .c (o .cpp). Pero lo más aterrador era que cuando una de las declaraciones cambiaba, tenían que revisar todos los archivos .c (o .cpp) y modificar las declaraciones en ellos. ¡Ah~, era como si llegara el fin del mundo!

Finalmente, alguien (o tal vez algunos) ya no pudo soportar tal tortura. Él (ellos) extrajo las partes repetidas, las puso en un nuevo archivo, y luego en los archivos .c (o .cpp) que lo necesitaban, tecleó una declaración como `#include XXXX`. Así, incluso si una declaración cambiaba, ya no era necesario buscar y modificar por todas partes: ¡el mundo sigue siendo tan hermoso!

Debido a que este nuevo archivo a menudo se colocaba al principio (cabeza) del archivo .c (o .cpp), se le llamó "archivo de cabecera", con extensión .h.

Desde entonces, el compilador (en realidad, su preprocesador) sabe que en el mundo, además de los archivos .c (o .cpp), también existen archivos .h, así como un comando llamado #include.
