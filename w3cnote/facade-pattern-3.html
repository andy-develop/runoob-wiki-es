Patrón de diseño Java: Patrón Fachada (Patrón de Apariencia)

Categoría Técnicas de programación

El ejemplo del hospital

Los sistemas de software modernos son bastante complejos. Un método común que usan los diseñadores para manejar sistemas complejos es "dividir y conquistar", dividiendo un sistema en varios subsistemas más pequeños. Si consideramos un hospital como un subsistema, según las funciones departamentales, este sistema se puede dividir en registro, consulta externa, tarificación, análisis de laboratorio, cobro, dispensación de medicamentos, etc. Los pacientes que acuden al médico tienen que tratar con estos departamentos, al igual que el cliente de un subsistema tiene que tratar con las distintas clases de un subsistema, lo cual no es tarea fácil.

Primero, el paciente debe registrarse y luego ir a consulta externa. Si el médico solicita análisis de laboratorio, el paciente primero debe obtener la tarificación, luego pagar, y solo entonces puede ir al departamento de laboratorio para hacerse los análisis. Después de los análisis, regresa a la consulta externa. La imagen anterior describe la experiencia del paciente en el hospital; los cuadros en la imagen representan el hospital.La forma de resolver este inconveniente es introducir el patrón fachada. El hospital puede establecer un puesto de recepcionista, donde el recepcionista se encarga de hacer el registro, la tarificación, el pago, la recogida de medicamentos, etc. en nombre del paciente. Este recepcionista es la manifestación del patrón fachada: el paciente solo contacta con el recepcionista, y es el recepcionista quien trata con los distintos departamentos.

La estructura del patrón fachada

El patrón fachada no tiene una descripción de diagrama de clases generalizada; el mejor método de descripción es, en realidad, explicarlo con un ejemplo.

Dado que el diagrama estructural del patrón fachada es demasiado abstracto, vamos a hacerlo un poco más concreto. Supongamos que dentro del subsistema hay tres módulos: ModuleA, ModuleB y ModuleC, cada uno con un método de ejemplo. En ese caso, el diagrama de estructura general del ejemplo es el siguiente: En este diagrama de objetos aparecen dos roles:
  • Rol de fachada (Facade):El cliente puede llamar a los métodos de este rol. Este rol conoce las funciones y responsabilidades de los subsistemas relacionados (uno o más). En circunstancias normales, este rol delega todas las solicitudes provenientes del cliente al subsistema correspondiente.
  • Rol de subsistema (SubSystem):Puede haber uno o más subsistemas al mismo tiempo. Cada subsistema no es una clase individual, sino una colección de clases (como el subsistema anterior, que está compuesto por las tres clases ModuleA, ModuleB y ModuleC). Cada subsistema puede ser llamado directamente por el cliente, o llamado por el rol de fachada. El subsistema no sabe de la existencia de la fachada; para el subsistema, la fachada es simplemente otro cliente.

Código fuente

Clases en el rol de subsistema:

public class ModuleA {
    //示意方法
    public void testA(){
        System.out.println("调用ModuleA中的testA方法");
    }
}
public class ModuleB {
    //示意方法
    public void testB(){
        System.out.println("调用ModuleB中的testB方法");
    }
}
public class ModuleC {
    //示意方法
    public void testC(){
        System.out.println("调用ModuleC中的testC方法");
    }
}

Clase del rol de fachada:

public class Facade {
    //示意方法，满足客户端需要的功能
    public void test(){
        ModuleA a = new ModuleA();
        a.testA();
        ModuleB b = new ModuleB();
        b.testB();
        ModuleC c = new ModuleC();
        c.testC();
    }
}

Clase del rol de cliente:

public class Client {
 
    public static void main(String[] args) {
        
        Facade facade = new Facade();
        facade.test();
    }
 
}

La clase Facade es en realidad equivalente a la interfaz de apariencia de los módulos A, B y C. Con esta clase Facade, el cliente ya no necesita llamar personalmente a los módulos A, B y C del subsistema, ni conocer los detalles de implementación interna del sistema, e incluso no necesita saber que los módulos A, B y C existen. El cliente solo necesita interactuar con la clase Facade, logrando así un mejor desacoplamiento entre el cliente y los módulos A, B y C del subsistema, y haciendo que el sistema sea más fácil de usar para el cliente.

Implementación del patrón fachada

Usar el patrón fachada tiene un beneficio adicional: puede exponer métodos de forma selectiva. Los métodos definidos en un módulo se pueden dividir en dos partes: una parte se usa externamente al subsistema, y otra parte se usa para las llamadas mutuas entre los módulos internos del subsistema. Con la clase Facade, los métodos utilizados para las llamadas mutuas entre módulos internos del subsistema no necesitan exponerse al exterior del subsistema.

Por ejemplo, definamos los siguientes módulos A, B y C.

public class ModuleA {
    /**
     * 提供给子系统外部使用的方法
     */
    public void a1(){};
    
    /**
     * 子系统内部模块之间相互调用时使用的方法
     */
    private void a2(){};
    private void a3(){};
}
public class ModuleB {
    /**
     * 提供给子系统外部使用的方法
     */
    public void b1(){};
    
    /**
     * 子系统内部模块之间相互调用时使用的方法
     */
    private void b2(){};
    private void b3(){};
}
public class ModuleC {
    /**
     * 提供给子系统外部使用的方法
     */
    public void c1(){};
    
    /**
     * 子系统内部模块之间相互调用时使用的方法
     */
    private void c2(){};
    private void c3(){};
}
public class ModuleFacade {
    
    ModuleA a = new ModuleA();
    ModuleB b = new ModuleB();
    ModuleC c = new ModuleC();
    /**
     * 下面这些是A、B、C模块对子系统外部提供的方法
     */
    public void a1(){
        a.a1();
    }
    public void b1(){
        b.b1();
    }
    public void c1(){
        c.c1();
    }
}

Definir una clase ModuleFacade de esta manera puede ocultar eficazmente los detalles internos, evitando que el cliente, al llamar a la clase Module, encuentre métodos que no necesita conocer. Por ejemplo, los métodos a2() y a3() no necesitan ser conocidos por el cliente; de lo contrario, se exponen detalles internos y se confunde al cliente. Para el cliente, ¿tendría que pensar para qué sirven los métodos a2() y a3()? En realidad, a2() y a3() son métodos de interacción entre módulos internos, que originalmente no estaban destinados al exterior del subsistema, así que es mejor que el cliente no los conozca.

¿Cuántas clases de fachada puede tener un sistema?

En el patrón fachada, normalmente solo se necesita una clase de fachada, y esta clase de fachada tiene una única instancia; en otras palabras, es una clase singleton. Por supuesto, esto no significa que solo haya una clase de fachada en todo el sistema, sino que solo hay una clase de fachada para cada subsistema. O dicho de otro modo, si un sistema tiene varios subsistemas, cada subsistema tiene una clase de fachada, y todo el sistema puede tener varias clases de fachada.

Añadir nuevo comportamiento al subsistema

　　

Los principiantes suelen pensar que heredando de una clase de fachada se puede añadir nuevo comportamiento al subsistema, lo cual es incorrecto. El propósito del patrón fachada es proporcionar un canal de comunicación centralizado y simplificado para el subsistema, y no puede añadir nuevo comportamiento al subsistema. Por ejemplo, el recepcionista del hospital no es personal médico; el recepcionista no puede proporcionar servicios médicos a los pacientes.

Ventajas del patrón fachada

Acoplamiento flexible: el patrón fachada afloja la relación de acoplamiento entre el cliente y el subsistema, permitiendo que los módulos internos del subsistema sean más fáciles de extender y mantener.

Sencillo y fácil de usar: el patrón fachada hace que el subsistema sea más fácil de usar. El cliente ya no necesita conocer la implementación interna del subsistema, ni interactuar con los numerosos módulos internos del subsistema; solo necesita interactuar con la clase de fachada.

Mejor división de niveles de acceso: mediante el uso razonable de Facade, podemos dividir mejor los niveles de acceso. Algunos métodos son para el exterior del sistema, y otros son para uso interno del sistema. Concentrar las funciones que deben exponerse al exterior en la fachada facilita el uso por parte del cliente y también oculta muy bien los detalles internos.
