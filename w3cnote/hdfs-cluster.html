5.0 Clúster HDFS

Categoría Tutorial de Hadoop

El clúster HDFS se construye sobre el clúster Hadoop. Dado que HDFS es el proceso daemon principal de Hadoop, el proceso de configuración del clúster HDFS es representativo del proceso de configuración del clúster Hadoop.

Usar Docker permite construir un entorno de clúster de forma más conveniente y eficiente.

Configuración en cada computadora

Cómo Hadoop configura el clúster y qué configuración debería tener cada computadora son preguntas que surgen durante el aprendizaje. La configuración de este capítulo proporcionará un ejemplo típico, pero los elementos de configuración de Hadoop, complejos y variados, van mucho más allá de esto.

El control remoto de los DataNodes por parte del NameNode de HDFS se realiza mediante SSH, por lo que los elementos de configuración clave deben configurarse en el NameNode, y los elementos de configuración no críticos deben configurarse en cada DataNode. Es decir, la configuración de los DataNodes puede ser diferente de la del NameNode, y la configuración entre diferentes DataNodes también puede variar.

Sin embargo, para facilitar la creación del clúster, este capítulo sincronizará los mismos archivos de configuración a todos los nodos del clúster mediante imágenes de Docker; esto se explica especialmente.

Pasos específicos

La idea general es la siguiente: primero usamos una imagen que contiene Hadoop para configurarla de modo que todos los nodos del clúster puedan compartirla; luego, usando esa imagen como prototipo, generamos varios contenedores para formar un clúster.

Configurar el prototipo

Primero, usaremos la imagen `hadoop_proto` preparada anteriormente para iniciarla como contenedor:

docker run -d --name=hadoop_temp --privileged hadoop_proto /usr/sbin/init

Ingrese al directorio de archivos de configuración de Hadoop:

cd $HADOOP_HOME/etc/hadoop

Ahora se hace una breve descripción de la función de estos archivos:

ArchivoFunción
workersRegistra los nombres de host o direcciones IP de todos los DataNodes.
core-site.xmlConfiguración central de Hadoop
hdfs-site.xmlElementos de configuración de HDFS
mapred-site.xmlElementos de configuración de MapReduce
yarn-site.xmlElementos de configuración de YARN
Nota: YARN proporciona servicios de gestión de recursos para MapReduce; por ahora no se necesita aquí.

Ahora diseñamos un clúster simple como el siguiente:

  • 1 NameNode: nn
  • 2 DataNodes: dn1, dn2

Primero edite `workers` y cambie el contenido del archivo a:

dn1
dn2

Luego edite `core-site.xml` y agregue los siguientes elementos de configuración en `<configuration>`:

<!-- 配置 HDFS 主机地址与端口号 -->
<property>
    <name>fs.defaultFS</name>
    <value>hdfs://nn:9000</value>
</property>
<!-- 配置 Hadoop 的临时文件目录 -->
<property>
    <name>hadoop.tmp.dir</name>
    <value>file:///home/hadoop/tmp</value>
</property>

Configure `hdfs-site.xml` y agregue los siguientes elementos de configuración en `<configuration>`:

<!-- 每个数据块复制 2 份存储 -->
<property>
    <name>dfs.replication</name>
    <value>2</value>
</property>

<!-- 设置储存命名信息的目录 -->
<property>
    <name>dfs.namenode.name.dir</name>
    <value>file:///home/hadoop/hdfs/name</value>
</property>

Finalmente, debe configurar SSH:

ssh-keygen -t rsa -P "" -f ~/.ssh/id_rsa
ssh-copy-id -i ~/.ssh/id_rsa hadoop@localhost

En este punto, el prototipo del clúster está completamente configurado. Puede salir del contenedor y subir el contenedor como una nueva imagen `cluster_proto`:

docker stop hadoop_temp
docker commit hadoop_temp cluster_proto

Si es necesario, puede eliminar la imagen temporal `hadoop_temp`.

Desplegar el clúster

A continuación, desplegamos el clúster.

Primero, cree una red dedicada `hnet` para el clúster Hadoop:

docker network create --subnet=172.20.0.0/16 hnet

Luego cree los contenedores del clúster:

docker run -d --name=nn --hostname=nn --network=hnet --ip=172.20.1.0 --add-host=dn1:172.20.1.1 --add-host=dn2:172.20.1.2 --privileged cluster_proto /usr/sbin/init
docker run -d --name=dn1 --hostname=dn1 --network=hnet --ip=172.20.1.1 --add-host=nn:172.20.1.0 --add-host=dn2:172.20.1.2 --privileged cluster_proto /usr/sbin/init
docker run -d --name=dn2 --hostname=dn2 --network=hnet --ip=172.20.1.2 --add-host=nn:172.20.1.0 --add-host=dn1:172.20.1.1 --privileged cluster_proto /usr/sbin/init

Ingrese al NameNode:

docker exec -it nn su hadoop

Formatee HDFS:

hdfs namenode -format

Si no hay errores, el siguiente paso es iniciar HDFS:

start-dfs.sh

Después de un inicio exitoso, el comando `jps` debería mostrar la existencia de NameNode y SecondaryNameNode. El NameNode no tiene un proceso DataNode, porque este proceso se ejecuta en `dn1` y `dn2`.

En este punto, puede verificar el funcionamiento de HDFS de la misma manera descrita en el capítulo anterior sobre el modo pseudo-clúster; la forma de usar HDFS tampoco difiere (el NameNode representa a todo el clúster).
