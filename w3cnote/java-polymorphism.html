Polimorfismo en Java

Clasificación Tecnología de programación

El polimorfismo generalmente se divide en dos tipos: polimorfismo por anulación (override) y polimorfismo por sobrecarga (overload).

  • Polimorfismo por sobrecarga, también llamado polimorfismo en tiempo de compilación. Es decir, este tipo de polimorfismo ya queda determinado en tiempo de compilación. Todos saben qué es la sobrecarga: un grupo de métodos con el mismo nombre pero diferentes listas de parámetros es sobrecarga. Al llamar a un método sobrecargado de este tipo, se obtienen resultados diferentes según los parámetros que se pasen.

    Pero aquí hay ambigüedad; algunos consideran que la sobrecarga no debería contarse como polimorfismo. Porque muchas personas entienden el polimorfismo como: el tipo concreto al que apunta una variable de referencia definida en el programa y la llamada al método realizada a través de esa variable de referencia no se determinan al programar, sino durante la ejecución del programa; esta situación se llama polimorfismo. Lo que describe esta definición es nuestro segundo tipo de polimorfismo: el polimorfismo por anulación. Además, el polimorfismo por sobrecarga no es exclusivo de la programación orientada a objetos, mientras que el polimorfismo es una de las tres características principales de la orientación a objetos (si no estoy en lo cierto, recuerda decírmelo...).

    Creo que no es necesario profundizar demasiado en la definición. Mi entendimiento es: la capacidad de un mismo comportamiento de tener múltiples formas o manifestaciones diferentes es polimorfismo, por lo que creo que la sobrecarga también es un tipo de polimorfismo. Si no estás de acuerdo con este punto de vista, también lo acepto.

  • Polimorfismo por anulación, también llamado polimorfismo en tiempo de ejecución. Este tipo de polimorfismo se implementa mediante la técnica de enlace dinámico (dynamic binding), que consiste en determinar el tipo real del objeto referenciado durante la ejecución y llamar a su método correspondiente según su tipo real. Es decir, solo cuando el programa se ejecuta sabes qué método de qué subclase se está llamando. Este tipo de polimorfismo se implementa mediante la anulación de métodos y el upcasting. El ejemplo del código anterior es un polimorfismo por anulación completo. Todos los polimorfismos que explicaremos a continuación son polimorfismo por anulación, porque es el verdadero polimorfismo en la programación orientada a objetos.

Upcasting

Convertir un objeto referenciado por una referencia de subclase al tipo de la clase padre se llama upcasting. En términos sencillos, es convertir un objeto de subclase en un objeto de clase padre. Aquí la clase padre puede ser una interfaz.

Veamos un ejemplo que todos conocen:

Ejemplo

public class Animal { public void eat(){ System.out.println("animal eatting..."); } } public class Cat extends Animal{ public void eat(){ System.out.println("Yo como pescado"); } } public class Dog extends Animal{ public void eat(){ System.out.println("Yo como huesos"); } public void run(){ System.out.println("Puedo correr"); } } public class Main { public static void main(String[] args) { Animal animal = new Cat(); //Upcasting animal.eat(); animal = new Dog(); animal.eat(); } } //Resultado: //Yo como pescado //Yo como huesos

Esto es el upcasting,Animal animal = new Cat();convierte el objeto de subclase Cat en un objeto de clase padre Animal. En este momento, la referencia animal llama al método de la subclase.

Problemas a tener en cuenta durante la conversión

  • Al hacer upcasting, los métodos definidos específicamente en la subclase se pierden. Por ejemplo, el método run definido en la clase Dog anterior, cuando la referencia animal apunta a una instancia de Dog, no se puede acceder al método run,animal.run()y se producirá un error.
  • Una referencia de subclase no puede apuntar a un objeto de la clase padre.Cat c = (Cat)new Animal()Eso no está permitido.

Ventajas del upcasting

  • Reduce código duplicado y hace que el código sea más conciso.
  • Mejora la escalabilidad del sistema.

Downcasting

Lo correspondiente al upcasting es el downcasting. El downcasting convierte un objeto de clase padre en un objeto de subclase. (¡Ten cuidado! Aquí hay trampas.)

Caso práctico

Primero veamos un ejemplo:

//还是上面的animal和cat dog
Animal a = new Cat();
Cat c = ((Cat) a);
c.eat();
//输出  我吃鱼
Dog d = ((Dog) a);
d.eat();
// 报错 ： java.lang.ClassCastException：com.chengfan.animal.Cat cannot be cast to com.chengfan.animal.Dog
Animal a1 = new Animal();
Cat c1 = ((Cat) a1);
c1.eat();
// 报错 ： java.lang.ClassCastException：com.chengfan.animal.Animal cannot be cast to com.chengfan.animal.Cat

¿Por qué el primer fragmento de código no da error? Supongo que ya lo sabes: como a es en sí mismo un objeto Cat, naturalmente se puede convertir hacia abajo a Cat, y por supuesto no se puede convertir a Dog. ¿Has visto alguna vez el absurdo fenómeno de que un perro se convierta de repente en un gato?

Mientras que a1 es un objeto Animal, tampoco puede convertirse hacia abajo a ningún objeto de subclase. Por ejemplo, si vas a hacer arqueología y descubres una nueva criatura, sabes que es un animal, pero no puedes decir directamente: ah, es un gato, o es un perro.

Notas sobre el downcasting

  • La premisa del downcasting es que el objeto de clase padre apunte a un objeto de subclase (es decir, antes de hacer downcasting, primero debe haberse hecho upcasting).

  • El downcasting solo puede convertir al tipo de la clase del objeto en sí (un gato no puede convertirse en perro).

Veamos un caso clásico:

Ejemplo

class A { public String show(D obj) { return ("A and D"); } public String show(A obj) { return ("A and A"); } } class B extends A{ public String show(B obj){ return ("B and B"); } public String show(A obj){ return ("B and A"); } } class C extends B{ } class D extends B{ } public class Demo { public static void main(String[] args) { A a1 = new A(); A a2 = new B(); B b = new B(); C c = new C(); D d = new D(); System.out.println("1--" + a1.show(b)); System.out.println("2--" + a1.show(c)); System.out.println("3--" + a1.show(d)); System.out.println("4--" + a2.show(b)); System.out.println("5--" + a2.show(c)); System.out.println("6--" + a2.show(d)); System.out.println("7--" + b.show(b)); System.out.println("8--" + b.show(c)); System.out.println("9--" + b.show(d)); } } //Resultado: //1--A and A //2--A and A //3--A and D //4--B and A //5--B and A //6--A and D //7--B and B //8--B and B //9--A and D //¿Puedes entender este resultado? Primero analízalo tú mismo.

Los primeros tres, si te esfuerzas en analizarlos, aún puedes entenderlos. Pero el cuarto, probablemente te quedas perplejo. ¿Por qué no es 'b and b'?

Aquí tienes que aprender algo nuevo.

Cuando una variable de referencia de un objeto de clase padre referencia a un objeto de subclase, el tipo del objeto referenciado determina de quién se llama el método miembro, y el tipo de la variable de referencia determina qué métodos se pueden llamar. Si la subclase no anula ese método, se buscará en la clase padre.

Puede sonar un poco complicado de leer, primero veamos un ejemplo simple:

Ejemplo

class X { public void show(Y y){ System.out.println("x and y"); } public void show(){ System.out.println("only x"); } } class Y extends X { public void show(Y y){ System.out.println("y and y"); } public void show(int i){ } } class main{ public static void main(String[] args) { X x = new Y(); x.show(new Y()); x.show(); } } //Resultado //y and y //only x

Y hereda de X, anula el método show(Y y) de X, pero no anula el método show().

En este momento, x, cuyo tipo de referencia es X, apunta a un objeto de tipo Y, y los métodos llamados están determinados por Y; se buscará primero en Y. Se ejecutax.show(new Y());, este método está definido en Y, por lo que se ejecuta el método de Y;

Pero al ejecutarx.show();, algunos dirán: ¿Y no tiene este método? Parece que fue a buscar el método en la clase padre, porque se llamó al método de X.

De hecho, la clase Y sí tiene el método show(), heredado de X; solo que no lo anula, por lo que no está escrito explícitamente en Y. Parece que se llama al método de X, pero en realidad se sigue llamando al de Y.

Ahora no es difícil entender la frase complicada anterior. X es el tipo de la variable de referencia, determina qué métodos se pueden llamar; se pueden llamar show() y show(Y y), mientras que show(int i) no. Y es el tipo del objeto referenciado, determina de quién se llama el método: se llama al método de y.

Lo anterior es un conocimiento simple; no es suficiente para entender ese ejemplo complejo. Veamos otro concepto:

La prioridad de las llamadas a métodos de objetos en la cadena de herencia: this.show(O), super.show(O), this.show((super)O), super.show((super)O).

Si puedes entender esta relación de llamadas, entonces dominas el polimorfismo. Volvamos al ejemplo complejo:

La relación de abcd es la siguiente: C/D —> B —> A

Primero analicemos el caso 4:a2.show(b)

  • Primero, a2 es una variable de referencia de tipo A, que apunta a un objeto de tipo B. A determina los métodos que se pueden llamar: show(D obj) y show(A obj).
  • a2.show(b) ==> this.show(b), aquí this se refiere a B.
  • Luego, se busca show(B obj) en la clase B; se encuentra, pero lamentablemente no sirve, porque el método show(B obj) no está dentro del rango invocable,this.show(O)falla, se pasa al siguiente nivel:super.show(O), super se refiere a A.
  • Se busca show(B obj) en A, falla, porque este método no está definido. Se pasa al tercer nivel:this.show((super)O), this se refiere a B.
  • Se busca show((A)O) en B; se encuentra: show(A obj), y se elige llamar a ese método.
  • Salida: B and A

Si puedes entender este proceso y analizar los demás casos, entonces realmente lo dominas.

Veamos ahora el caso 9:b.show(d)

  • Primero, b es una variable de referencia de tipo B, que apunta a un objeto de tipo B. No hay upcasting involucrado, solo se llaman métodos de la propia clase.
  • Se busca el método show(D obj) en B. Ahora no dirás que no se encuentra, ¿verdad? Se encuentra y se llama directamente a ese método.
  • Salida: A and D

Resumen

El contenido de este artículo es más o menos todo esto. Hagamos un resumen.

  1. El polimorfismo, en pocas palabras, es la capacidad de un mismo comportamiento de tener múltiples formas o manifestaciones diferentes.
  2. Clasificación del polimorfismo: polimorfismo en tiempo de ejecución y polimorfismo en tiempo de compilación.
  3. Requisitos previos del polimorfismo en tiempo de ejecución: herencia (implementación), anulación (override) y upcasting.
  4. Upcasting y downcasting.
  5. La prioridad de las llamadas a métodos de objetos en la cadena de herencia: this.show(O), super.show(O), this.show((super)O), super.show((super)O).
