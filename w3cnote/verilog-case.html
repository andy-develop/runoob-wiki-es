4.6 Sentencias de rama múltiple en Verilog

Categoría Tutorial de Verilog

Palabras clave: case, selector

La sentencia case es una forma de rama condicional de múltiples vías que puede resolver el problema de la incomodidad de usar la sentencia if cuando hay múltiples opciones de condición.

Sentencia case

El formato de la sentencia case es el siguiente:

case(case_expr)
    condition1     :             true_statement1 ;
    condition2     :             true_statement2 ;
    ……
    default        :             default_statement ;
endcase

Cuando se ejecuta la sentencia case, si condition1 es verdadera, se ejecuta true_statement1; si condition1 es falsa y condition2 es verdadera, se ejecuta true_statement2; y así sucesivamente. Si ninguna de las condiciones es verdadera, se ejecuta la sentencia default_statement.

La sentencia default es opcional, y en una sentencia case no puede haber múltiples sentencias default.

Las opciones de condición pueden ser múltiples, no limitadas a condition1, condition2, etc., y estas opciones no requieren ser mutuamente excluyentes. Aunque estas opciones se comparan concurrentemente, el efecto de ejecución es que la que esté primero y cuya condición sea verdadera es la que se ejecuta.

Las sentencias de ejecución como true_statement1 pueden ser una sola sentencia o varias. Si son varias sentencias, deben indicarse con las palabras clave begin y end.

La sentencia case admite uso anidado.

A continuación se utiliza la sentencia case en lugar de la sentencia if para implementar la funcionalidad de un multiplexor de 4 vías. Los resultados de simulación y el testbench pueden consultarse enSentencias condicionalescapítulo, ambos son completamente idénticos.

Ejemplo

module mux4to1(
    input [1:0]     sel ,
    input [1:0]     p0 ,
    input [1:0]     p1 ,
    input [1:0]     p2 ,
    input [1:0]     p3 ,
    output [1:0]    sout);
 
    reg [1:0]     sout_t ;
    always @(*)
        case(sel)
            2'b00:   begin      
                    sout_t = p0 ;
                end
            2'b01:       sout_t = p1 ;
            2'b10:       sout_t = p2 ;
            default:     sout_t = p3 ;
        endcase
    assign sout = sout_t ;
 
endmodule

Las expresiones de las opciones de condición en la sentencia case no tienen que ser constantes; también pueden ser valores x o z.

Cuando se necesita ejecutar la misma sentencia bajo múltiples opciones de condición, estas opciones pueden separarse con comas y colocarse como alternativas en el mismo bloque de sentencias.

Sin embargo, la lógica de comparación de x o z en la sentencia case no es sintetizable, por lo que generalmente no se recomienda usar x o z como valores de comparación en una sentencia case.

Por ejemplo, ampliando la sentencia case del multiplexor de 4 vías, se muestra el siguiente ejemplo:

Ejemplo

case(sel)
    2'b00:   sout_t = p0 ;
    2'b01:   sout_t = p1 ;
    2'b10:   sout_t = p2 ;
    2'b11:     sout_t = p3 ;
    2'bx0, 2'bx1, 2'bxz, 2'bxx, 2'b0x, 2'b1x, 2'bzx :
        sout_t = 2'bxx ;
    2'bz0, 2'bz1, 2'bzz, 2'b0z, 2'b1z :
        sout_t = 2'bzz ;
    default:  $display("Unexpected input control!!!");
endcase

Sentencias casex/casez

Las sentencias casex y casez son variantes de la sentencia case, utilizadas para representar elementos irrelevantes (don't care) en las opciones de condición.

casex usa "x" para representar el valor irrelevante, y casez usa el signo de interrogación "?" para representar el valor irrelevante.

La funcionalidad implementada por ambos es completamente idéntica, y la sintaxis también es exactamente la misma que la de la sentencia case.

Sin embargo, casex y casez generalmente no son sintetizables y se usan principalmente para simulación.

Por ejemplo, se usa la sentencia casez para implementar un multiplexor de 4 vías con un extremo de control de 4 bits.

Ejemplo

module mux4to1(
    input [3:0]     sel ,
    input [1:0]     p0 ,
    input [1:0]     p1 ,
    input [1:0]     p2 ,
    input [1:0]     p3 ,
    output [1:0]    sout);
 
    reg [1:0]     sout_t ;
    always @(*)
        casez(sel)
            4'b???1:     sout_t = p0 ;
            4'b??1?:     sout_t = p1 ;
            4'b?1??:     sout_t = p2 ;
            4'b1???:     sout_t = p3 ;  
        default:         sout_t = 2'b0 ;
    endcase
    assign      sout = sout_t ;
 
endmodule
