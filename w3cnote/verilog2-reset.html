5.1 Introducción al reset en Verilog

Categoría Tutorial de Verilog: Nivel avanzado

Palabras clave: reset síncrono, reset asíncrono

Para asegurar que el sistema tenga un estado inicial claro y estable después del encendido, o que pueda restaurarse al estado inicial normal cuando el estado operativo del sistema esté desordenado, el diseño de sistemas digitales debe incluir un módulo de circuito de reset. Una anomalía en el circuito de reset puede causar un funcionamiento anormal de todo el sistema, por lo que, en cierta medida, la importancia del circuito de reset no es menor que la del circuito de reloj.

El circuito de reset se puede clasificar en reset síncrono y reset asíncrono.

Reset síncrono

El reset síncrono significa que la señal de reset es efectiva cuando llega el flanco activo del reloj. Si no hay reloj, no importa cómo cambie la señal de reset, el circuito no realizará la operación de reset.

La descripción de código típica del reset síncrono es la siguiente:

Ejemplo

module sync_reset(
    input       rstn,  //señal de reset síncrono
    input       clk,   //reloj
    input       din,   //dato de entrada
    output reg  dout   //dato de salida
    );
   
    always @(posedge clk) begin   //la señal de reset no debe agregarse a la lista de sensibilidad
        if(!rstn)  dout <= 1'b0 ; //la señal rstn se sincroniza con el reloj clk
        else       dout <= din ;
    end
   
endmodule

Ventajas del reset síncrono: las señales están sincronizadas, se pueden filtrar los glitches de la señal de reset, lo que favorece el análisis de temporización.

Desventajas del reset síncrono: la mayoría de las celdas de flip-flops no tienen terminal de reset síncrono, por lo que usar reset síncrono consume más recursos lógicos adicionales. Además, el ancho de la señal de reset debe ser mayor que un período de reloj, de lo contrario se puede perder la señal de reset.

Reset asíncrono

El reset asíncrono significa que, sin importar si llega el reloj, siempre que la señal de reset sea válida, el circuito realizará la operación de reset.

La descripción de código típica del reset asíncrono es la siguiente:

Ejemplo

module async_reset(
    input       rstn,  //señal de reset asíncrono
    input       clk,   //reloj
    input       din,   //dato de entrada
    output reg  dout   //dato de salida
    );
   
    //la señal de reset debe agregarse a la lista de sensibilidad
    always @(posedge clk or negedge rstn) begin
        if(!rstn)  dout <= 1'b0 ; //la señal rstn es asíncrona con el reloj clk
        else       dout <= din ;
    end
   
endmodule

Ventajas del reset asíncrono: la mayoría de las celdas de flip-flops tienen terminal de reset asíncrono, por lo que no ocupan recursos lógicos adicionales. Además, la señal de reset asíncrono se usa directamente sin procesamiento, el diseño es relativamente simple y la identificación de la señal es rápida y conveniente.

Desventajas del reset asíncrono: la señal de reset y la señal de reloj no tienen una relación de temporización definida, y el reset asíncrono fácilmente provoca el incumplimiento de los tiempos de removal y recovery. Además, el reset asíncrono es susceptible a la interferencia de glitches, lo que produce operaciones de reset inesperadas.

Liberación síncrona de reset asíncrono

Considerando factores como el diseño y los recursos, generalmente en el diseño de sistemas digitales se utiliza reset asíncrono.

Para eliminar las deficiencias del reset asíncrono, el circuito de reset suele adoptar el método de diseño de "reset asíncrono, liberación síncrona". Es decir, cuando llega la señal de reset, no se sincroniza con la señal de reloj, pero cuando la señal de reset se libera, es necesario sincronizarla con la señal de reloj.

La descripción de código típica de reset asíncrono y liberación síncrona es la siguiente:

Ejemplo

module areset_srelease(
    input       rstn,  //señal de reset asíncrono
    input       clk,   //reloj
    input       din,   //dato de entrada
    output reg  dout   //dato de salida
    );
     
    reg   rstn_r1, rstn_r2;
    always @ (posedge clk or negedge rstn) begin
        if (!rstn) begin
            rstn_r1 <= 1'b0;     //reset asíncrono
            rstn_r2 <= 1'b0;  
        end
        else begin
            rstn_r1 <= 1'b1;     //liberación síncrona
            rstn_r2 <= rstn_r1;  //Sincronización mediante registros; si hay diferencia de temporización, se pueden retrasar varios ciclos
        end
    end
     
    //Usar rstn_r2 como reset síncrono; la señal de reset se puede agregar a la lista de sensibilidad
    always @ (posedge clk or negedge rstn_r2) begin
        if (!rstn_r2) dout <= 1'b0; //reset síncrono
        else          dout <= din;
    end

endmodule

Cabe señalar que el circuito de reset consume más recursos de lógica de hardware y área, y aumenta la complejidad del diseño del sistema. Los flip-flops sin terminal de reset también tienen un rendimiento relativamente mayor. Por lo tanto, en algunos diseños digitales donde los valores iniciales no afectan la corrección lógica, como partes de procesamiento de datos en la ruta de datos o algunos registros en pipelines de alta velocidad, se puede considerar omitir el reset para lograr el mejor rendimiento.

Para simular de manera conveniente y rápida otras funciones de la lógica no relacionada con el reset, todos los resets en los diseños digitales del tutorial se introducen como reset asíncrono desde el testbench, sin considerar los problemas de temporización del circuito de reset. Al diseñar realmente un sistema digital, se debe realizar un diseño independiente, cuidadoso y prudente del circuito de reset.
