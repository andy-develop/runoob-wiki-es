3.0 Zookeeper linux Pasos para construir un clúster de servidor

Categoría Tutorial de Zookeeper

Este capítulo demostrará los pasos para construir un clúster de servidores Zookeeper con tres máquinas.

Preparación necesaria: cree tres entornos de máquinas virtuales e instale el kit de desarrollo de Java JDK. Puede usar VM o vagrant+virtualbox para construir un entorno centos/ubuntu. Este caso se basa en el sistema host Windows 10 y utiliza vagrant+virtualbox para construir un entorno centos7. Si se usan directamente servidores en la nube o máquinas físicas, el proceso es el mismo.

Paso 1:Prepare tres entornos de Zookeeper y descargue el paquete comprimido de Zookeeper según el tutorial anterior. Los tres entornos de clúster centos son los siguientes:

Máquina 1: 192.168.3.33

Máquina 2: 192.168.3.35

Máquina 3: 192.168.3.37

Sugerencia: para ver la dirección IP, puede usarifconfigel comando.

Paso 2:No modifique la información de configuración de zoo.cfg

Funciones de los tres puertos de Zookeeper:

  • 1、2181: proporcionar servicios al cliente
  • 2、2888: para comunicación entre máquinas del clúster
  • 3、3888: para la elección de líder

segúnserver.id = ip:port:portModifique el archivo de configuración del clúster:

Agregue la configuración al final del archivo zoo.cfg en las tres máquinas virtuales:

server.1=192.168.3.33:2888:3888
server.2=192.168.3.35:2888:3888
server.3=192.168.3.37:2888:3888

Configure myid respectivamente según el id y la dirección correspondiente.

vim /tmp/zookeeper/myid

Después de completar la configuración en este caso, la consulta muestra lo siguiente:

En la máquina IP 192.168.3.33 se configura myid. Como esta máquina se inició en modo independiente en el tutorial anterior, aparece version-2; si no aparece, no importa.

En la máquina IP 192.168.3.35 se configura myid.

En la máquina IP192.168.3.37 se configura myid.

Paso 3: Iniciar el clúster

Antes de iniciar, es necesario desactivar el firewall (en un entorno de producción se deben abrir los puertos correspondientes).

systemctl stop firewalld

Inicie 192.168.3.33 y revise el registro. Que aparezcan errores en el registro en este momento es normal, porque las otras dos máquinas aún no se han iniciado y no se puede conectar temporalmente.

Después de iniciar las otras dos máquinas respectivamente, verifique el estado de las tres máquinas:

IP 192.168.3.33

IP 192.168.3.35

IP 192.168.3.37

Finalmente se muestra que el clúster se construyó correctamente. Mode: leader representa el nodo principal, follower representa el nodo secundario, un principal y dos secundarios.
