11.0 Análisis del principio del mecanismo de eventos watcher de Zookeeper

Categoría Tutorial de Zookeeper

El mecanismo watcher de Zookeeper se puede dividir en cuatro procesos:

  • El cliente registra el watcher.
  • El servidor procesa el watcher.
  • El servidor activa el evento watcher.
  • El cliente realiza la devolución de llamada del watcher.

Entre ellas, el cliente tiene tres formas de registrar watchers. Llamando a la API del cliente se puede implementar mediante getData, exists y getChildren respectivamente. Utilizando el proyecto Maven creado en el capítulo anterior, cree una nueva clase WatcherDemo y tome el método exists como ejemplo para explicar su principio.

Ejemplo

public class WatcherDemo implements Watcher {
    static ZooKeeper zooKeeper;
    static {
        try {
            zooKeeper = new ZooKeeper("192.168.3.39:2181", 4000,new WatcherDemo());
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
    @Override
    public void process(WatchedEvent event) {
        System.out.println("eventType:"+event.getType());
        if(event.getType()==Event.EventType.NodeDataChanged){
            try {
                zooKeeper.exists(event.getPath(),true);
            } catch (KeeperException e) {
                e.printStackTrace();
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
    }
    public static void main(String[] args) throws IOException, KeeperException, InterruptedException {
        String path="/watcher";
        if(zooKeeper.exists(path,false)==null) {
            zooKeeper.create("/watcher", "0".getBytes(), ZooDefs.Ids.OPEN_ACL_UNSAFE, CreateMode.PERSISTENT);
        }
        Thread.sleep(1000);
        System.out.println("-----------");
        // true indica que se usa el watcher configurado en la instancia de Zookeeper
        Stat stat=zooKeeper.exists(path,true);
        System.in.read();
    }
}
